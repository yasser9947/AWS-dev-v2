Amazon Route 53: DNS الذكيّ من AWS Amazon Route 53: AWS's Smart DNS

DNS ليس مجرّد ترجمة اسم إلى IP — في AWS هو أداة توزيع حِمل عالميّة ومتحكّم إتاحة. Route 53 خدمة DNS الوحيدة بضمان ١٠٠٪، ويوفّر سياسات توجيه ذكيّة تحوّل DNS إلى طبقة معمار فعّالة. DNS isn't just name→IP translation — on AWS it's a global load balancer and availability controller. Route 53 is the only AWS service with a 100% SLA and offers routing policies that turn DNS into an active architectural layer.

ما هو Route 53 وكيف يعمل DNS What is Route 53 and how DNS works

Route 53 خدمة DNS مُدارة من AWS. هو Authoritative DNS (أنت تتحكّم بالسجلّات)، و Domain Registrar (يمكنك شراء النطاقات منه مباشرةً)، ويوفّر Health Checks متكاملة. يملك ضمان SLA 100٪ — الخدمة الوحيدة في AWS بهذا المستوى.

Route 53 is AWS's managed DNS service. It's an Authoritative DNS (you control the records), a Domain Registrar (buy domains directly), and provides integrated Health Checks. 100% SLA — the only AWS service at that level.

الاسم Route 53 مشتقّ من المنفذ ٥٣ — المنفذ التقليديّ لـ DNS. عند طلب example.com، يمرّ الاستعلام عبر: Root DNS Server (.) → TLD Server (.com) → Authoritative Server (Route 53 في حالتنا).

The name Route 53 comes from port 53 — DNS's classic port. A example.com query traverses: Root DNS Server (.) → TLD Server (.com) → Authoritative Server (Route 53 in our case).

Public Hosted ZonePublic Hosted Zone

لأسماء النطاقات العامّة على الإنترنت (api.acme.com).

For public domains on the Internet (api.acme.com).

Private Hosted ZonePrivate Hosted Zone

لأسماء داخليّة في VPC واحد أو أكثر (db.acme.internal).

For internal names within one or more VPCs (db.acme.internal).

مفهوم أساسي:Key concept: تكلفة ٠٫٥٠ دولار/شهر لكلّ Hosted Zone. رسوم الاستعلامات إضافيّة (منخفضة جداً). كلّ DNS record يحتاج TTL (مدّة التخزين المؤقّت)، ما عدا Alias records التي تأخذ TTL تلقائياً من الـ target. Pricing: $0.50/month per hosted zone. Query charges are extra (very low). Every DNS record needs a TTL (cache duration), except Alias records which inherit TTL from the target.

CNAME vs Alias — التمييز المهمّ CNAME vs Alias — the key distinction

موارد AWS (ELB، CloudFront، S3 Website) تعطيك اسم مضيف AWS مثل my-alb.us-east-1.elb.amazonaws.com. لكنّك تريد acme.com. أمامك خياران: CNAME أو Alias. الفرق بينهما يُسأل كثيراً في الامتحان.

AWS resources (ELB, CloudFront, S3 Website) give you AWS hostnames like my-alb.us-east-1.elb.amazonaws.com. But you want acme.com. Two options: CNAME or Alias. The exam asks about this constantly.

CNAME — قياسيّ لكن محدودCNAME — standard but limited

يوجّه اسماً إلى اسم آخر (app.acme.com → blabla.anywhere.com). يعمل مع أيّ hostname، ليس محصوراً بـ AWS. لا يعمل على الـ Zone Apex (الـ root domain) — لا يمكنك إنشاء CNAME لـ acme.com نفسها، فقط للـ subdomains.

Points a name to another name (app.acme.com → blabla.anywhere.com). Works with any hostname, not AWS-only. Cannot be used at the Zone Apex (root domain) — you can't CNAME acme.com itself, only subdomains.

Alias — الخيار الـ AWS-nativeAlias — the AWS-native choice

ميزة Route 53 الخاصّة: يوجّه اسماً إلى مورد AWS محدّد. يعمل على Zone Apex و subdomains. مجانيّ (لا رسوم استعلام). دائماً من نوع A أو AAAA (IPv4/IPv6). يكتشف تغيّر IP الـ resource تلقائياً. لا يمكن ضبط TTL يدوياً.

A Route 53 exclusive: points a name to a specific AWS resource. Works on Zone Apex and subdomains. Free (no query fee). Always type A or AAAA (IPv4/IPv6). Auto-detects target IP changes. Cannot set TTL manually.

سياسات التوجيه (Routing Policies) Routing Policies

سياسات التوجيه تحدّد كيف يردّ Route 53 على استعلامات DNS. هذه القدرة تحوّل DNS من خدمة تسمية إلى أداة توزيع حِمل عالميّة. Route 53 يدعم ٧ سياسات.

Routing policies define how Route 53 answers DNS queries. This turns DNS from a naming service into a global traffic director. Route 53 supports 7 policies.

SimpleSimple

افتراضي — قيمة واحدة أو عدّة قيم يختار منها العميل عشوائياً. لا يدعم Health Checks.

Default — single or multiple values; client picks randomly. No health checks.

WeightedWeighted

توزيع حسب أوزان. ٧٠٪ لـ v1، ٣٠٪ لـ v2 — مثاليّ لـ canary releases و A/B testing.

Split by weights. 70% to v1, 30% to v2 — perfect for canary releases and A/B testing.

Failover (Active-Passive)Failover (Active-Passive)

Primary + Secondary. Health Check إلزاميّ على Primary. عند فشله، التوجيه يحوّل إلى Secondary.

Primary + Secondary. Health check required on Primary. On failure, traffic shifts to Secondary.

Latency-basedLatency-based

توجيه إلى الـ Region ذي أقلّ زمن استجابة من المستخدم. قد يتغيّر ديناميكياً.

Routes to the lowest-latency Region from the user. Changes dynamically.

GeolocationGeolocation

حسب موقع المستخدم (قارّة، دولة، ولاية أمريكية). مختلف عن Latency — قد لا يكون الأسرع. ضع سجلّ Default.

By user location (continent, country, US state). Different from latency — not always fastest. Always set a Default record.

GeoproximityGeoproximity

مزيج من الموقع والـ bias. تتحكّم بتوسيع (+١ إلى +٩٩) أو تقليص (-١ إلى -٩٩) حجم المنطقة. يحتاج Route 53 Traffic Flow.

Combines location + bias. Expand (+1 to +99) or shrink (-1 to -99) a region's footprint. Requires Route 53 Traffic Flow.

Multi-ValueMulti-Value

حتى ٨ قيم صحّية تُعاد في نفس الاستعلام. بديل client-side بسيط لـ ELB — لكن ليس بديلاً حقيقياً.

Up to 8 healthy values returned per query. Simple client-side alternative to ELB — but not a real replacement.

نصيحة للامتحان:Exam tip: الأسئلة تميل لسيناريوهات: canary deploy → Weighted. DR passive → Failover. أقرب region للسرعة → Latency-based. امتثال قانونيّ (محتوى مخصّص للدولة) → Geolocation. شبه-ELB client-side → Multi-Value. Exam leans on scenarios: canary deploy → Weighted. Passive DR → Failover. Nearest region for speed → Latency-based. Regulatory (country-specific content) → Geolocation. Client-side pseudo-ELB → Multi-Value.

Health Checks — كشف الفشل وتحويل الحِمل Health Checks — failure detection and traffic shifts

Health Checks في Route 53 تعمل من ١٥ فاحصاً عالميّاً. كلّ فاحص يطلب المورد، وإذا اتّفق أكثر من ١٨٪ على أنّه سليم، يعتبره Route 53 healthy. الفحص كلّ ٣٠ ثانية افتراضياً (١٠ مدفوع).

Route 53 Health Checks use ~15 global checkers. If 18%+ report healthy, Route 53 considers the endpoint healthy. Check interval is 30s default (10s paid).

Endpoint Health CheckEndpoint Health Check

HTTP/HTTPS/TCP على IP أو hostname عامّ. يجب أن يعيد 2xx/3xx. يمكن فحص نصّ في أوّل ٥١٢٠ bytes.

HTTP/HTTPS/TCP against a public IP or hostname. Must return 2xx/3xx. Can match text in the first 5120 bytes.

Calculated Health CheckCalculated Health Check

يدمج نتائج عدّة فحوصات (AND / OR / NOT، حتى ٢٥٦ child). مفيد للصيانة.

Combines multiple checks (AND / OR / NOT, up to 256 children). Great for maintenance windows.

CloudWatch Alarm Health CheckCloudWatch Alarm Health Check

يراقب Alarm مخصّصاً (مثل throttles DynamoDB). الحلّ الوحيد لـ Private endpoints.

Watches a custom alarm (e.g. DynamoDB throttles). The only way to check Private endpoints.

فخّ شائع:Common pitfall: Route 53 Health Checkers موجودة خارج VPC، فلا يمكنها الوصول إلى endpoints خاصّة. الحلّ: استخدم CloudWatch Alarm (مبني على metric من الـ endpoint الخاصّ) وأربط Health Check بالـ Alarm. Route 53 Health Checkers live outside the VPC — they can't reach private endpoints. Fix: use a CloudWatch Alarm (built from a metric inside the private endpoint) and associate the Health Check with that alarm. 
// Java SDK v2 — create a Failover routing with health check
import software.amazon.awssdk.services.route53.Route53Client;
import software.amazon.awssdk.services.route53.model.*;

Route53Client r53 = Route53Client.create();

// 1. Create an HTTPS health check on the primary endpoint
CreateHealthCheckResponse hc = r53.createHealthCheck(CreateHealthCheckRequest.builder()
    .callerReference("acme-primary-" + System.currentTimeMillis())
    .healthCheckConfig(HealthCheckConfig.builder()
        .type(HealthCheckType.HTTPS)
        .fullyQualifiedDomainName("api.acme.com")
        .port(443)
        .resourcePath("/health")
        .requestInterval(30)
        .failureThreshold(3)
        .build())
    .build());

// 2. Create the Primary record (points to primary ALB, uses the health check)
r53.changeResourceRecordSets(ChangeResourceRecordSetsRequest.builder()
    .hostedZoneId("Z0123")
    .changeBatch(ChangeBatch.builder().changes(
        Change.builder().action(ChangeAction.UPSERT).resourceRecordSet(
            ResourceRecordSet.builder()
                .name("api.acme.com")
                .type(RRType.A)
                .setIdentifier("primary")
                .failover(ResourceRecordSetFailover.PRIMARY)
                .healthCheckId(hc.healthCheck().id())
                .aliasTarget(AliasTarget.builder()
                    .hostedZoneId("Z35SXDOTRQ7X7K")
                    .dnsName("acme-primary-alb.us-east-1.elb.amazonaws.com")
                    .evaluateTargetHealth(true).build())
                .build()).build()
    ).build())
    .build());

// 3. Create the Secondary record (DR, no health check needed)

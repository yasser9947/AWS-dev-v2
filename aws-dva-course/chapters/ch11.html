Concurrency و Throttling و Cold Starts Concurrency, Throttling, and Cold Starts

Concurrency = عدد الـ instances التي تُشغَّل في نفس اللحظة. الحد الافتراضيّ للحساب = ١٠٠٠ تنفيذ متزامن لكل Region (قابل للرفع). عند التجاوز: sync = ThrottleError (429)، async = retry تلقائيّ لمدّة ٦ ساعات ثم DLQ.

Concurrency = how many instances run simultaneously. Default account limit = 1000 concurrent executions per region (raisable). On overage: sync = ThrottleError (429), async = auto-retry for 6 hours then DLQ.

Reserved ConcurrencyReserved Concurrency

سقف صارم على دالة معيّنة + يحجز لها السعة من الـ pool المشترك. يمنعها من ابتلاع كلّ الحصّة، ويضمن لها حدّاً أدنى.

Hard cap on a function + reserves capacity from the shared pool. Prevents it from eating all account concurrency, guarantees a floor.

Provisioned ConcurrencyProvisioned Concurrency

تهيئة instances مُحمَّلة مسبقاً — بدون cold starts. أغلى لكنّه ضروريّ للزمن الحرج. يمكن ربطه بـ Application Auto Scaling.

Pre-initialized instances — zero cold starts. More expensive but necessary for latency-critical paths. Integrates with Application Auto Scaling.

ما هو Cold Start؟What is a cold start?

عند إنشاء instance جديدة: تحميل الكود، تشغيل init (خارج الـ handler)، ثم المعالجة. Java ‌و‌ .NET أبطأ لأنّ JVM تحتاج تحميل classes.

When a fresh instance spins up: code load, init (outside handler), then processing. Java and .NET are slower because JVM needs class loading.

حدود الـ initInit limits

الـ init time ليس ضمن duration المفوتَرة لكن يؤثّر على المستخدم. بَسّط التبعيّات واستخدم GraalVM للـ Java عند الحاجة.

Init time isn't billed as duration but affects users. Trim dependencies and consider GraalVM for Java.

ذاكرة CPU linkedMemory-CPU coupling

١٢٨MB→١٠GB. زيادة RAM = زيادة vCPU. كامل vCPU عند ١٧٩٢MB. أكثر من ذلك = multi-threading مطلوب (حتى ٦ vCPU).

128MB→10GB. More RAM = more vCPU. Full vCPU at 1792MB. Beyond that needs multi-threading (up to 6 vCPU).

TimeoutTimeout

افتراضيّ ٣ ثوانٍ، أقصى ٩٠٠ ثانية (١٥ دقيقة). للمهام الأطول استخدم Step Functions أو ECS/Fargate.

Default 3s, max 900s (15 min). For longer jobs use Step Functions or ECS/Fargate.

للمطوّر السينيور:For the senior dev: قاعدة إنتاجيّة: Reserved Concurrency لعزل دالة حساسة عن باقي الحساب، وProvisioned Concurrency عندما يكون cold start غير مقبول (مثلاً login endpoint). قيسها بـ CloudWatch metric ProvisionedConcurrencyUtilization. Prod rule: use Reserved Concurrency to isolate a critical function from the rest of the account, and Provisioned Concurrency when cold start is unacceptable (e.g., login endpoint). Tune with CloudWatch metric ProvisionedConcurrencyUtilization.

Lambda داخل VPC و الوصول للإنترنت Lambda in a VPC & Internet Access

افتراضياً Lambda تعمل في شبكة AWS المُدارة. لتصل إلى موارد خاصّة (RDS، ElastiCache، EC2 داخل VPC) عرّف VPC ID و Subnets و Security Groups. Lambda ينشئ ENI في الـ subnets لتنفيذ الاستدعاءات.

By default Lambda runs in AWS-managed networking. To reach private resources (RDS, ElastiCache, EC2 in VPC), specify VPC ID, Subnets, and Security Groups. Lambda creates ENIs in the subnets for invocations.

فخّ شائع:Common pitfall: نشر Lambda في public subnet لا يعطيه إنترنت. لا يملك Public IP. الحل الصحيح: subnet خاصّ مع NAT Gateway لإخراج الطلبات، أو VPC Endpoints للوصول لخدمات AWS بشكل خاص. CloudWatch Logs يعمل حتى بدون أيّ endpoint. Deploying Lambda in a public subnet does NOT give it internet. It has no public IP. Correct: private subnet + NAT Gateway for outbound, or VPC Endpoints for private AWS access. CloudWatch Logs works even with no endpoint.

Lambda Layers و EFS و ‎/tmp Lambda Layers, EFS, and /tmp

Lambda Layers = أرشيفات zip تحتوي على مكتبات/runtimes مشتركة تُضاف إلى عدّة دوالّ. حتى ٥ layers لكلّ دالة، الحجم الإجماليّ المفكوك ≤ ٢٥٠MB. تُقلّل حجم حزمة كل دالة وتُسرّع النشر.

Lambda Layers = zip archives of shared libraries/runtimes attached to multiple functions. Up to 5 layers per function, total unpacked ≤ 250MB. Reduces per-function package size and speeds deployments.

‎/tmp (ephemeral)/tmp (ephemeral)

٥١٢MB-١٠GB. تُمسَح عند إعادة الـ instance. مفيدة للتحميل المؤقّت (ZIP، صور) أو cache بين استدعاءات warm.

512MB-10GB. Wiped on instance rebuild. Good for transient download (ZIP, images) or cache across warm invocations.

Layers (immutable)Layers (immutable)

حد أقصى ٥ لكل دالة. ٢٥٠MB إجماليّ مفكوك. غير قابلة للتعديل بعد النشر — تُنشَأ إصدارة جديدة.

Max 5 per function. 250MB total unpacked. Immutable after publish — create a new version instead.

S3S3

تخزين دائم أو لحفظ checkpoints و نتائج نهائية. يتطلّب IAM. Object storage، ليس filesystem.

Durable storage for checkpoints and final results. Needs IAM. Object storage, not filesystem.

EFSEFS

Network filesystem مشترك. يحتاج VPC. مناسب لبيانات كبيرة مشتركة بين دوالّ (ML models). اعتنِ بـ connection limits.

Shared network filesystem. Needs VPC. Good for large shared data across functions (ML models). Mind connection limits.

للمطوّر السينيور:For the senior dev: للتطبيقات الكبيرة، ادمج Layers (للـ AWS SDK و dependencies الثقيلة) + /tmp (للتحميل الديناميكيّ) + EFS (للبيانات المشتركة عبر دوالّ). هذا النمط يقلّل الـ cold start ويحسّن الـ reuse. For large apps, combine Layers (for AWS SDK and heavy deps) + /tmp (for dynamic downloads) + EFS (for data shared across functions). This pattern trims cold starts and maximizes reuse.

Versions و Aliases و CodeDeploy Versions, Aliases & CodeDeploy

عند التطوير، أنت تعمل على $LATEST (mutable). عند النشر، تُنشِئ Version (snapshot غير قابل للتعديل، رقم متزايد، ARN خاصّ). Alias = pointer قابل للتعديل إلى إصدار، ويُستخدَم لفصل البيئات (dev/test/prod) ولتوزيع الترافيك.

Development happens on $LATEST (mutable). To release, publish a Version (immutable snapshot, incrementing number, own ARN). An Alias = mutable pointer to a version, used to separate environments (dev/test/prod) and to split traffic.

Version (immutable)Version (immutable)

Code + configuration كاملاً. ARN محدّد. لا يتغيّر. مناسب لإطلاق إنتاجيّ موثوق.

Code + full config. Specific ARN. Never changes. For reliable production releases.

Alias (mutable pointer)Alias (mutable pointer)

"prod" يشير إلى V12، يمكن تحديثه ليشير إلى V13. يدعم توزيع الترافيك (٩٥٪ V12 / ٥٪ V13 للـ canary).

"prod" points at V12; flip it to V13. Supports weighted routing (95% V12 / 5% V13 for canary).

# Publish a new version from $LATEST
aws lambda publish-version \
  --function-name OrderProcessor \
  --description "Add idempotency guard"
# → returns Version: "4"

# Point the 'prod' alias at v3 with 10% traffic on v4 (canary)
aws lambda create-alias --function-name OrderProcessor \
  --name prod --function-version 3 \
  --routing-config AdditionalVersionWeights={"4"=0.10}

# Later, flip alias 100% to v4
aws lambda update-alias --function-name OrderProcessor \
  --name prod --function-version 4
مفهوم أساسي:Key concept: Aliases لا يمكن أن تشير إلى Aliases أخرى — فقط إلى versions. هذا قيد تصميميّ لمنع الحلقات. Aliases cannot reference other aliases — only versions. A design constraint to prevent cycles.

AllAtOnceAllAtOnce

نقل ١٠٠٪ من الترافيك فوراً. الأسرع لكنّ الأكثر خطورة.

Shift 100% immediately. Fastest but riskiest.

LinearLinear

Linear10PercentEvery3Minutes، Linear10PercentEvery10Minutes.

Linear10PercentEvery3Minutes, Linear10PercentEvery10Minutes.

CanaryCanary

جرّب X٪ لفترة ثم ١٠٠٪: Canary10Percent5Minutes، Canary10Percent30Minutes.

Try X% for a window then 100%: Canary10Percent5Minutes, Canary10Percent30Minutes.

(2) API Gateway and EventBridge point to the alias ARN, never $LATEST. (3) Deployment only flips the alias — rollback is instant by pointing the alias back.

Lambda Function URL و CodeGuru Profiling و الحدود Lambda Function URL, CodeGuru Profiling & Limits

Lambda Function URL = endpoint HTTPS جاهز لدالة دون API Gateway أو ALB. الـ URL ثابت بصيغة https://<url-id>.lambda-url.<region>.on.aws. يدعم CORS و AuthType (NONE للعامّ، AWS_IAM للمحمي).

Lambda Function URL = ready-made HTTPS endpoint for a function without API Gateway or ALB. URL format: https://<url-id>.lambda-url.<region>.on.aws. Supports CORS and AuthType (NONE for public, AWS_IAM for auth).

نصيحة للامتحان:Exam tip: Function URL لا يدعم PrivateLink — يعمل عبر الإنترنت العامّ فقط. إن احتجت خصوصيّة شبكيّة استخدم API Gateway VPC Endpoint أو ALB داخليّ. Function URL doesn't support PrivateLink — it's public-internet only. For network privacy use API Gateway VPC endpoint or internal ALB.

CodeGuru Profiler gives runtime perf insights for Lambda (Java and Python). Enable from console; it adds a layer and the AmazonCodeGuruProfilerAgentAccess policy automatically. Pinpoints hot methods and long cold starts.

Public subnet doesn't grant internet. Use private subnet + NAT Gateway, or VPC Endpoints for AWS services.

للحفظ السريع: Mnemonic:

للذاكرة/CPU في Lambda: ١٧٩٢ = رقم سحريّ = vCPU كامل. اقرأها "ألف سبعمائة اثنان وتسعون" وتذكّر: قبل = جزء CPU، بعد = multi-threading مطلوب. للنشر: Version محفور، Alias قابل للتحويل، CodeDeploy يوتمت التحوّل.

For Lambda memory/CPU: 1792 MB = magic full-vCPU threshold. Below = fractional CPU, above = multi-threading needed (up to 6 vCPU). For deployment: Version frozen, Alias mutable, CodeDeploy automates the swap.

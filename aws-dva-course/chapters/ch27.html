المقاييس (Metrics) في CloudWatch CloudWatch Metrics

CloudWatch يوفّر مقاييس لكلّ خدمة AWS تقريباً. Metric هو متغيّر قابل للرصد عبر الزمن (مثل CPUUtilization أو NetworkIn). كل مقياس ينتمي إلى namespace ويحمل timestamp و حتى ٣٠ dimension لتقسيمه (مثل InstanceId أو Environment).

CloudWatch provides metrics for every AWS service. A metric is a variable tracked over time (e.g., CPUUtilization, NetworkIn). Each belongs to a namespace, has a timestamp, and up to 30 dimensions (e.g., InstanceId, Environment).

EC2 Basic vs DetailedEC2 Basic vs Detailed

الافتراضي: نقطة كلّ ٥ دقائق مجّاناً. Detailed Monitoring: كلّ ١ دقيقة (بمقابل). ضروري لـ Auto Scaling السريع. ملاحظة: الذاكرة (RAM) لا تُرسَل افتراضياً — تحتاج Custom Metric عبر Unified Agent.

Default: 1 data point every 5 minutes, free. Detailed Monitoring: every 1 minute (paid). Needed for fast Auto Scaling. Note: memory (RAM) is NOT pushed by default — needs a custom metric via Unified Agent.

Custom MetricsCustom Metrics

أنشئ مقاييسك عبر PutMetricData. استخدم dimensions لتقسيمها. Standard: دقّة ١ دقيقة. High Resolution: ١/٥/١٠/٣٠ ثانية (أغلى). يقبل نقاطاً من أسبوعين للماضي وساعتين للمستقبل.

Create your own via PutMetricData. Use dimensions to segment. Standard: 1-minute resolution. High Resolution: 1/5/10/30 sec (higher cost). Accepts points 2 weeks in the past to 2 hours in the future.

// Publish a custom metric from a Spring Boot app
import software.amazon.awssdk.services.cloudwatch.CloudWatchClient;
import software.amazon.awssdk.services.cloudwatch.model.*;

CloudWatchClient cw = CloudWatchClient.create();

MetricDatum datum = MetricDatum.builder()
    .metricName("OrdersProcessed")
    .unit(StandardUnit.COUNT)
    .value(42.0)
    .storageResolution(60)   // 60 = standard, 1 = high-resolution
    .dimensions(
        Dimension.builder().name("Environment").value("prod").build(),
        Dimension.builder().name("Service").value("checkout").build()
    )
    .timestamp(java.time.Instant.now())
    .build();

cw.putMetricData(PutMetricDataRequest.builder()
    .namespace("Acme/Checkout")
    .metricData(datum)
    .build());
مفهوم أساسي:Key concept: للامتحان: كلّ مقياس يحمل namespace + name + dimensions + timestamp. نفس الاسم مع dimensions مختلفة يُعتبر مقياساً منفصلاً. CloudWatch Dashboards تجمع المقاييس من عدّة حسابات ومناطق. Exam: each metric has namespace + name + dimensions + timestamp. Same name with different dimensions = separate metric. Dashboards can aggregate metrics from multiple accounts and regions.

السجلّات (Logs): Groups و Streams و Agent CloudWatch Logs: Groups, Streams & Agent

CloudWatch Logs هو مخزن السجلّات المركزيّ في AWS. Log Group اسم اعتباري يمثّل التطبيق. Log Stream هو مجرى سجلّ من مصدر واحد (خادم معيّن أو حاوية). يمكن تحديد سياسة انتهاء الصلاحية من يوم واحد إلى ١٠ سنوات أو أبداً.

CloudWatch Logs is AWS's central log store. A Log Group is an arbitrary name representing an app. A Log Stream is a log from a single source (instance or container). You define retention policies from 1 day to 10 years, or never expire.

يجمع السجلّات و مقاييس على مستوى النظام: CPU, Disk I/O, RAM, Netstat, Processes, Swap. الإعداد المركزي عبر SSM Parameter Store. هذا هو المطلوب في الامتحان لجمع مقاييس RAM.

Collects logs plus system metrics: CPU, Disk I/O, RAM, Netstat, Processes, Swap. Centralized config via SSM Parameter Store. This is the answer for RAM metrics in exam.

// Unified Agent config snippet — /opt/aws/amazon-cloudwatch-agent/etc/config.json
{
  "metrics": {
    "namespace": "Acme/EC2",
    "append_dimensions": { "InstanceId": "${aws:InstanceId}" },
    "metrics_collected": {
      "mem":  { "measurement": ["mem_used_percent"] },
      "disk": { "measurement": ["used_percent"], "resources": ["*"] }
    }
  },
  "logs": {
    "logs_collected": {
      "files": { "collect_list": [
        { "file_path": "/var/log/myapp/*.log",
          "log_group_name": "acme-api",
          "log_stream_name": "{instance_id}" }
      ]}
    }
  }
}
نصيحة للامتحان:Exam tip: السجلّات مشفّرة افتراضياً. يمكن استخدام KMS key خاصّ. لا تسجّل معلومات حسّاسة بنصّ صريح — استخدم Filter Pattern لاكتشافها وإنذار الفريق. Logs are encrypted by default. You can supply your own KMS key. Never log sensitive data in plaintext — use Metric Filters to detect and alert.

Metric Filters و Subscriptions Metric Filters & Subscriptions

Metric Filter يحوّل أنماطاً في السجلّات إلى مقياس (مثل عدّ ظهور كلمة ERROR)، ثمّ يُمكن بناء Alarm عليه. مهمّ: الفلتر لا يعمل بأثر رجعيّ؛ يبدأ النشر فقط للأحداث اللاحقة لإنشائه. يدعم حتى ٣ أبعاد.

A Metric Filter turns log patterns into a metric (e.g., count of ERROR occurrences), which can then trigger an alarm. Critical: filters do NOT retroactively filter — they only publish for events after the filter is created. Supports up to 3 dimensions.

Subscription Filter يختلف: يبثّ السجلّات في الوقت الفعليّ إلى وجهة: Kinesis Data Streams، Kinesis Data Firehose (near real-time لـ S3)، أو Lambda (real-time). يدعم Cross-Account Subscription لتجميع السجلّات في حساب مركزيّ.

A Subscription Filter is different: it streams logs in real time to a destination: Kinesis Data Streams, Kinesis Data Firehose (near real-time to S3), or Lambda (real-time). Supports Cross-Account Subscription for central log aggregation.

S3 ExportS3 Export

CreateExportTask. يستغرق حتى ١٢ ساعة. ليس في الوقت الفعليّ.

CreateExportTask. Up to 12 hours. Not real-time.

Subscription Destination in recipient account + IAM Role allowing PutRecord.

فخّ شائع:Common pitfall: خلط شائع: Metric Filter ≠ Subscription Filter. الأوّل يعدّ/يستخرج ليصنع metric للإنذار. الثاني يبثّ السجلّ الخام كاملاً لخدمة أخرى. Common confusion: Metric Filter ≠ Subscription Filter. First counts/extracts to build a metric for alarms. Second streams the raw log to another service.

Logs Insights — لغة استعلام السجلّات Logs Insights — log query language

CloudWatch Logs Insights محرّك استعلام مخصّص للسجلّات المخزّنة في CloudWatch. يكتشف الحقول تلقائياً من JSON ومن خدمات AWS. ليس محرّك real-time — بل محرّك استعلام. يمكن استعلام عدّة Log Groups عبر حسابات مختلفة وحفظ الاستعلامات في Dashboards.

CloudWatch Logs Insights is a purpose-built query engine for logs stored in CloudWatch. Auto-discovers fields from JSON and AWS services. It's a query engine, not real-time. Can query multiple Log Groups across AWS accounts and save queries to Dashboards.

# 25 most recent events
fields @timestamp, @message
| sort @timestamp desc
| limit 25

# Count exceptions per 5-minute bucket
filter @message like /Exception/
| stats count(*) as exceptionCount by bin(5m)
| sort exceptionCount desc

# Spring Boot: find slow requests
fields @timestamp, @message
| parse @message /duration=(?<duration>\d+)ms/
| filter duration > 1000
| stats avg(duration), max(duration), count(*) by bin(1m)
للمطوّر السينيور:For the senior dev: للمطوّر السينيور: Logs Insights شبيه بـ KQL في Azure أو LogQL في Grafana Loki. اعتد على fields | filter | parse | stats | sort | limit. Dashboards تربطها ببانل Alarm لتنبيه فوريّ على أنماط في السجلّ. Senior dev: Insights is like Azure KQL or Grafana Loki's LogQL. Memorize fields | filter | parse | stats | sort | limit. Dashboards bind it to Alarm panels for instant log-pattern alerting.

الإنذارات (Alarms) و EMF Alarms & Embedded Metric Format (EMF)

الـ Alarm يراقب مقياساً واحداً ويطلق إجراءً عند تجاوز عتبة. الحالات الثلاث: OK، ALARM، INSUFFICIENT_DATA. الأخيرة مهمّة في الامتحان: تعني أنّ البيانات غير كافية للحكم.

An alarm watches one metric and triggers an action when a threshold is breached. Three states: OK, ALARM, INSUFFICIENT_DATA. The last one matters on exam: it means not enough data to judge.

PeriodPeriodHigh-resolution: ١٠ أو ٣٠ ثانية أو مضاعفات ٦٠. Standard: ١ دقيقة وأكثر.High-resolution: 10s, 30s, or multiples of 60. Standard: 1 minute and up.

EC2 Instance Recovery: ألارم على StatusCheckFailed_System يعيد تشغيل الخادم على عتاد جديد مع الاحتفاظ بـ Private/Public/Elastic IP والـ metadata والـ placement group. حلّ سريع لأعطال الخادم الفيزيائي.

EC2 Instance Recovery: alarm on StatusCheckFailed_System recovers the instance on new hardware, keeping same Private/Public/Elastic IP, metadata, and placement group. Fast fix for physical host failures.

# Test an alarm without waiting for the threshold
aws cloudwatch set-alarm-state \
  --alarm-name 'high-cpu-prod' \
  --state-value ALARM \
  --state-reason 'testing'

Embedded Metric Format (EMF): JSON منظّم تُرسله من Lambda أو ECS إلى CloudWatch Logs، فتستخرج CloudWatch منه مقاييس مخصّصة بدون استدعاء PutMetricData. موفّر للكلفة ويدمج السجلّ والمقياس في رحلة واحدة — مفيد جداً لتطبيقات Spring Boot بدون خادم.

Embedded Metric Format (EMF): structured JSON you write from Lambda/ECS to CloudWatch Logs; CloudWatch extracts custom metrics from it without calling PutMetricData. Saves cost and unifies log+metric in one trip — excellent for serverless Spring Boot apps.

// Example EMF log line (Lambda prints this to stdout)
{
  "_aws": {
    "Timestamp": 1700000000000,
    "CloudWatchMetrics": [{
      "Namespace": "Acme/Checkout",
      "Dimensions": [["Service","Environment"]],
      "Metrics": [{ "Name":"OrderLatency", "Unit":"Milliseconds" }]
    }]
  },
  "Service": "checkout",
  "Environment": "prod",
  "OrderLatency": 143.7,
  "OrderId": "o-9821"
}

ServiceLens unifies CloudWatch Metrics + Logs + X-Ray Traces in one view for bottleneck discovery. Appears on exam as the end-to-end observability answer.

معمل عملي Hands-on Lab

الهدف: إعداد Metric Filter على سجلّات تطبيق Spring Boot لعدّ أخطاء Exception، وربطها بـ Alarm يرسل إشعار SNS.

Goal: Set up a Metric Filter on a Spring Boot app's logs to count Exceptions, then wire an Alarm to an SNS notification.

  1. ١

    أنشئ Log Group Create the Log Group 

    aws logs create-log-group --log-group-name /acme/api
aws logs put-retention-policy --log-group-name /acme/api --retention-in-days 30
  2. ٢

    أنشئ Metric Filter لاستخراج أخطاء Exception Create a Metric Filter for Exceptions

    نستخدم نمطاً بسيطاً يبحث عن كلمة Exception في السجلّ.

    Use a simple pattern matching Exception in the log line.

    aws logs put-metric-filter \
  --log-group-name /acme/api \
  --filter-name exception-count \
  --filter-pattern 'Exception' \
  --metric-transformations \
    metricName=ExceptionCount,metricNamespace=Acme/API,metricValue=1,defaultValue=0
  3. ٣

    أنشئ SNS Topic للتنبيه Create an SNS Topic for the alert 

    aws sns create-topic --name ops-alerts
aws sns subscribe --topic-arn arn:aws:sns:us-east-1:111122223333:ops-alerts \
  --protocol email --notification-endpoint oncall@acme.com
  4. ٤

    اربط Alarm يطلق SNS Wire an Alarm to SNS

    عتبة: أكثر من ٥ أخطاء خلال ٥ دقائق.

    Threshold: more than 5 exceptions in 5 minutes.

    aws cloudwatch put-metric-alarm \
  --alarm-name acme-api-exceptions \
  --namespace Acme/API --metric-name ExceptionCount \
  --statistic Sum --period 300 --evaluation-periods 1 \
  --threshold 5 --comparison-operator GreaterThanThreshold \
  --alarm-actions arn:aws:sns:us-east-1:111122223333:ops-alerts \
  --treat-missing-data notBreaching
  5. ٥

    اختبر الإنذار بدون انتظار Test the alarm without waiting 

    aws cloudwatch set-alarm-state \
  --alarm-name acme-api-exceptions \
  --state-value ALARM --state-reason 'testing'
تنبيه: Warning: احذف الـ Alarm والـ Metric Filter والـ SNS subscription بعد الاختبار — الـ Metric Filter مجانيّ لكن Alarms High-Resolution لها تكلفة. Delete the alarm, metric filter, and SNS subscription after testing — Metric Filters are free but high-res alarms aren't.

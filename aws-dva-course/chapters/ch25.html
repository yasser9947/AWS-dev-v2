Docker على AWS — نظرة عامّة Docker on AWS — overview

Docker يغلّف التطبيق مع كل اعتماديّاته داخل Container يعمل بنفس الطريقة على أيّ نظام. على AWS، لك ثلاث طرق لتشغيل Docker: ECS، EKS، و Fargate. ECR هو Registry لتخزين الصور.

Docker packages an app with all its dependencies in a container that runs the same on any OS. On AWS you have three ways to run Docker: ECS, EKS, and Fargate. ECR is the image registry.

الخدمةServiceماذا تقدّمWhat it provides
ECSمنصّة Docker الأصليّة من Amazon. EC2 Launch Type (تُدير EC2) أو Fargate (Serverless).Amazon's native Docker platform. EC2 Launch Type (you manage EC2) or Fargate (serverless).
FargateServerless — يعمل مع ECS أو EKS. بدون إدارة خوادم. ادفع بالـ vCPU/memory.Serverless — works with ECS or EKS. No server management. Pay per vCPU/memory.
EKSKubernetes مُدار. مفتوح المصدر، cloud-agnostic. استخدمه لو فريقك يعرف k8s.Managed Kubernetes. Open source, cloud-agnostic. Use if your team knows k8s.
ECRRegistry لتخزين الصور. Private أو Public (gallery.ecr.aws).Registry for images. Private or Public (gallery.ecr.aws).
مفهوم أساسي:Key concept: Task = instance of Docker container. Service = عدد من Tasks لها load balancing و auto-scaling. Cluster = مجموعة Tasks/Services. Task = instance of a Docker container. Service = N tasks with load balancing and auto-scaling. Cluster = a group of tasks/services.

ECS EC2 Launch Type vs Fargate ECS EC2 Launch Type vs Fargate

EC2 Launch TypeEC2 Launch Type

أنت تُدير EC2 Instances وعليك تثبيت ECS Agent. أرخص للأحمال الثابتة، تحكّم كامل بالـ OS والـ instance types.

You manage EC2 instances and install the ECS Agent. Cheaper for steady workloads, full control over OS and instance types.

FargateFargate

Serverless. تُعرّف CPU/memory — AWS تشغّل. لا خوادم للصيانة. فوترة بالثانية. أغلى للوحدة، لكن بصفر عمليّات.

Serverless. You define CPU/memory — AWS runs it. No servers to patch. Per-second billing. Pricier per unit but zero ops.

مفهوم أساسي:Key concept: الاختيار في الامتحان: Fargate للأحمال المتقطّعة، الإقلاع السريع، أو تجنّب إدارة الخوادم. EC2 Launch Type للتحكّم الكامل (مثل GPU instances)، أو لأحمال ٢٤/٧ كبيرة بتكلفة أقلّ مع Reserved Instances. Exam pick: Fargate for spiky workloads, fast start, or avoiding server management. EC2 Launch Type for full control (GPU instances) or 24/7 heavy workloads at lower cost with Reserved Instances.

EC2 Launch TypeEC2 Launch Type

تحتاج: EC2 + ECS Agent + Capacity Provider لإدارة التوسّع.

Needs: EC2 + ECS Agent + Capacity Provider for scaling.

FargateFargate

تحتاج: Task Definition فقط. AWS تُدير كل شيء.

Needs: just a Task Definition. AWS manages everything.

Task Definition و IAM Roles (نقطة حرجة في الامتحان) Task Definition & IAM Roles (exam hotspot)

Task Definition هو JSON يصف كيف تُشغَّل الـ Containers: الصورة، CPU، Memory، Networking، Ports، Volumes، Environment Variables، و نوعان من IAM Roles.

Task Definition is a JSON describing how to run containers: image, CPU, memory, networking, ports, volumes, env vars, and two types of IAM roles.

الدورRoleمن يستخدمهWho uses itالغرضPurpose
executionRoleArnECS Agent / Fargate infrastructureECS Agent / Fargate infraسحب صورة من ECR، إرسال Logs لـ CloudWatch، قراءة Secrets Manager/SSM عند بدء التشغيلPull image from ECR, send logs to CloudWatch, read Secrets/SSM at startup
taskRoleArnكود التطبيق داخل ContainerApp code inside the containerصلاحيات التطبيق (S3، DynamoDB، SQS، ...)App permissions (S3, DynamoDB, SQS, ...)
فخّ شائع:Common pitfall: فخّ الامتحان: خلط بين executionRoleArn و taskRoleArn. التطبيق Java داخل Container يستخدم taskRoleArn للوصول إلى S3 مثلاً. لكنّ Fargate نفسه يستخدم executionRoleArn لسحب الصورة من ECR. Exam trap: confusing executionRoleArn and taskRoleArn. A Java app inside a container uses taskRoleArn to access S3 or similar. But Fargate itself uses executionRoleArn to pull the image from ECR.

Task Placement (EC2 Launch Type فقط) Task Placement (EC2 Launch Type only)

عند تشغيل Tasks على EC2 Launch Type، ECS يحتاج اختيار EC2 Instance لوضع الـ Task فيها. Fargate لا يحتاج هذا لأنّه Serverless.

With EC2 Launch Type, ECS must choose an EC2 instance to place each task. Fargate doesn't need this because it's serverless.

الاستراتيجيّةStrategyالسلوكBehaviorالاستخدامUse case
binpackيضع Tasks على أقل Instances متاحة (ضغط). يُقلّل عدد EC2.Packs tasks on the fewest instances. Minimizes EC2 count.توفير التكلفةCost savings
spreadتوزيع متساوٍ على قيمة (AZ، instanceId).Even spread by a value (AZ, instanceId).عالي التوفّر، AZ diversificationHigh availability, AZ diversification
randomاختيار عشوائيّ.Random placement.بسيط، بلا إعداداتSimple, no tuning
 
// Mix strategies for HA + cost-efficient cluster
"placementStrategy": [
  { "type": "spread", "field": "attribute:ecs.availability-zone" },
  { "type": "binpack", "field": "memory" }
]

// Constraints — hard rules
"placementConstraints": [
  { "type": "distinctInstance" },                                // no two tasks on same EC2
  { "type": "memberOf", "expression": "attribute:ecs.instance-type =~ t3.*" }
]
للمطوّر السينيور:For the senior dev: الأمر الذي يحدث فعلياً: ECS يختار Instances بالترتيب التالي: ١) تُرضي CPU/memory/port، ٢) Constraints، ٣) Strategies. الـ Strategies best effort، Constraints صارمة. What actually happens: ECS picks instances in this order: 1) CPU/memory/port requirements, 2) constraints, 3) strategies. Strategies are best effort; constraints are strict.

ECR، Service Discovery، و EKS ECR, Service Discovery & EKS

ECR (Elastic Container Registry) لتخزين صور Docker على AWS. مدعوم بـ S3، مشفّر، مع vulnerability scanning و lifecycle policies.

ECR (Elastic Container Registry) stores Docker images on AWS. Backed by S3, encrypted, with vulnerability scanning and lifecycle policies.

# Login (AWS CLI v2)
aws ecr get-login-password --region us-east-1 | \
  docker login --username AWS \
  --password-stdin 123456789012.dkr.ecr.us-east-1.amazonaws.com

# Build and push
docker build -t acme-api:v1 .
docker tag  acme-api:v1 \
  123456789012.dkr.ecr.us-east-1.amazonaws.com/acme-api:v1
docker push 123456789012.dkr.ecr.us-east-1.amazonaws.com/acme-api:v1

# Pull on another machine
docker pull 123456789012.dkr.ecr.us-east-1.amazonaws.com/acme-api:v1
فخّ شائع:Common pitfall: خطأ شائع: "No such image" أو "pull access denied" عند تشغيل Task. السبب ٩٠٪: الـ executionRoleArn لا يملك AmazonECSTaskExecutionRolePolicy (التي تتضمّن أذونات ECR + CloudWatch Logs). Common error: "No such image" or "pull access denied" on task start. 90% cause: executionRoleArn is missing AmazonECSTaskExecutionRolePolicy (which includes ECR + CloudWatch Logs permissions).

ECR Lifecycle PoliciesECR Lifecycle Policies

قواعد لحذف الصور القديمة (بالوقت أو العدد) لتوفير التكلفة.

Rules to delete old images (by age or count) to save cost.

Image ScanningImage scanning

ECR يفحص الصور لاكتشاف الثغرات الأمنيّة عند Push أو عند طلب يدويّ.

ECR scans images for vulnerabilities on push or on demand.

Service DiscoveryService Discovery

ECS + Cloud Map = إعطاء Tasks DNS names قابلة للكشف بدون Load Balancer للـ microservices.

ECS + Cloud Map = give tasks discoverable DNS names — no ALB needed for internal microservices.

EKS (Kubernetes)EKS (Kubernetes)

للشركات التي تستخدم k8s. EKS يُدير Control Plane، أنت تُدير Worker Nodes (EC2 أو Fargate).

For companies using k8s. EKS manages the control plane; you manage worker nodes (EC2 or Fargate).

مفهوم أساسي:Key concept: الأمور المهمّة للامتحان في EKS: يدعم EC2 worker nodes أو Fargate، cloud-agnostic (تطبيق k8s يعمل في Azure/GCP)، مناسب للشركات التي تملك خبرة k8s محلياً وتريد الترحيل. EKS exam essentials: supports EC2 worker nodes or Fargate, is cloud-agnostic (k8s app runs on Azure/GCP), ideal for companies with existing k8s skills migrating to AWS.

الملخّص وأهمّ النقاط Summary & Key Takeaways

ECS أو EKS أو Fargate ECS or EKS or Fargate

ECS منصّة AWS الأصليّة، EKS Kubernetes، Fargate Serverless.

ECS is AWS-native, EKS is Kubernetes, Fargate is serverless.

TaskRole للتطبيق، ExecutionRole للـ Infra TaskRole for app, ExecutionRole for infra

خلط بينهما خطأ امتحان شائع جداً.

Mixing them up is a very common exam trap.

binpack للتكلفة، spread للتوفّر binpack for cost, spread for availability

Task Placement فقط لـ EC2 Launch Type، Fargate لا يحتاجه.

Task placement is EC2-only; Fargate doesn't need it.

ECR = Registry مع IAM ECR = registry with IAM

Pull Errors ⇒ executionRoleArn ناقصة ECR policy.

Pull errors ⇒ missing ECR policy on executionRoleArn.

للحفظ السريع: Mnemonic:

"ExecPulls، TaskAccesses": ExecutionRole يسحب الصورة من ECR؛ TaskRole هو ما يستخدمه التطبيق للوصول إلى S3/DynamoDB. للـ Placement: "Bpack = Cheap، Spread = Safe".

"ExecPulls, TaskAccesses": ExecutionRole pulls the image from ECR; TaskRole is what the app uses to access S3/DynamoDB. For placement: "Bpack = Cheap, Spread = Safe".

ما هو Elastic Beanstalk What is Elastic Beanstalk

Elastic Beanstalk خدمة PaaS (Platform as a Service). ارفع ZIP أو JAR (مثل Spring Boot fat jar)، و Beanstalk يُجهّز EC2 + Auto Scaling + ALB + RDS (اختياريّ) تلقائياً. أنت تركّز على الكود فقط، AWS تدير البنية التحتية.

Elastic Beanstalk is AWS's PaaS. Upload a ZIP or JAR (like a Spring Boot fat jar) and Beanstalk provisions EC2 + Auto Scaling + ALB + RDS (optional) automatically. You focus on code; AWS manages infra.

منصات مدعومةSupported platforms

Go، Java SE، Java+Tomcat، .NET Core، Node.js، PHP، Python، Ruby، Docker (Single/Multi).

Go, Java SE, Java+Tomcat, .NET Core, Node.js, PHP, Python, Ruby, Docker (single/multi).

Beanstalk مجانيBeanstalk is free

تدفع فقط مقابل الموارد الأساسيّة (EC2، ELB، RDS، S3). الخدمة نفسها لا تكلّف شيئاً.

You pay only for underlying resources (EC2, ELB, RDS, S3). The service itself is free.

Environment TiersEnvironment tiers

Web Server (ALB + EC2 لـ HTTP) أو Worker (SQS + EC2 للمعالجة الخلفيّة).

Web Server (ALB + EC2 for HTTP) or Worker (SQS + EC2 for background work).

خلف الكواليس: CloudFormationUnder the hood: CloudFormation

كل Beanstalk environment هو Stack CloudFormation. يمكنك إضافة موارد بـ .ebextensions.

Every Beanstalk environment is a CloudFormation stack. Add extra resources via .ebextensions.

مفهوم أساسي:Key concept: المفاهيم الثلاثة: Application (مجموع مكوّنات Beanstalk)، Application Version (إصدار من كودك)، Environment (موارد AWS تشغّل Version واحدة). Three concepts: Application (collection of Beanstalk components), Application Version (one version of your code), Environment (AWS resources running one Version).

سياسات النشر الأربع (الأكثر في الامتحان) The 4 deployment policies (heavily tested)

هذا الموضوع الأوّل للامتحان في Beanstalk. عليك معرفة كل سياسة: الوقت، التكلفة، Downtime، Rollback.

This is the #1 Beanstalk exam topic. You must know each policy: duration, cost, downtime, rollback.

All at once — Downtime!All at once — has downtime!

كل الخوادم تُنزَل، تُحدَّث، تعود. الأسرع، لكن التطبيق غير متاح لثوانٍ/دقائق. مناسب فقط لـ Dev.

All instances drop, update, come back. Fastest but app offline for seconds/minutes. Dev only.

Rolling — سعة مخفّضةRolling — reduced capacity

يُحدَّث bucket (دفعة) تلو الأخرى. التطبيق يعمل لكن بعدد خوادم أقل مؤقّتاً.

Update bucket by bucket. App runs but fewer instances temporarily.

Rolling + additional — سعة كاملةRolling + additional — full capacity

يُشغّل Instances جديدة قبل إنهاء القديمة. سعة كاملة طوال الوقت. جيّد للإنتاج.

Spins up new instances before killing old. Full capacity throughout. Good for prod.

Immutable — الأكثر أماناًImmutable — safest

ينشئ ASG جديد كامل بـ V2، يتحقّق من الصحّة، ثمّ يستبدل. Rollback فوري بحذف الـ ASG الجديد.

Creates a new ASG with V2, health-checks it, then swaps. Rollback = just kill the new ASG.

مفهوم أساسي:Key concept: Blue/Green ليس سياسة Beanstalk مباشرة. الطريقة: إنشاء Environment ثانٍ، النشر عليه، ثم Swap URLs. Rollback = إعادة Swap. Blue/Green isn't a direct Beanstalk policy. Method: create a second environment, deploy there, then Swap URLs. Rollback = swap back.
للمطوّر السينيور:For the senior dev: Traffic Splitting (Canary): Beanstalk ينشر V2 على ASG مؤقّت ويُرسِل ٪ صغير من الترافيك إليه. إذا فشل، Rollback تلقائيّ سريع. Traffic Splitting (Canary): Beanstalk deploys V2 to a temporary ASG and sends a small % of traffic. On failure, automatic fast rollback.

Web Server Tier vs Worker Tier Web Server Tier vs Worker Tier

Beanstalk يدعم نوعين من البيئات. الاختيار الصحيح مهمّ لأسئلة السيناريو.

Beanstalk supports two environment types. Picking the right one matters for scenario questions.

Web Server EnvironmentWeb Server Environment

HTTP/HTTPS مع ELB. للـ REST APIs و web apps. الـ URL من شكل myapp.us-east-1.elasticbeanstalk.com.

HTTP/HTTPS with ELB. For REST APIs and web apps. URL like myapp.us-east-1.elasticbeanstalk.com.

Worker EnvironmentWorker Environment

EC2 + SQS Queue. للمعالجة الخلفيّة (معالجة الصور، إرسال الإيميلات). يتسع تلقائياً حسب عدد الرسائل في Queue.

EC2 + SQS Queue. For background jobs (image processing, emails). Scales on queue depth.

نمط شائع: Web Server Tier يستقبل الطلبات السريعة، ثمّ يُرسِل رسالة SQS، و Worker Tier يلتقطها لاحقاً لإتمام المعالجة الثقيلة (معالجة ملفات، تصدير تقارير).

Common pattern: Web tier handles fast requests, pushes an SQS message, and the Worker tier picks it up for heavy work (file processing, report export).

.ebextensions و RDS Decoupling .ebextensions & RDS decoupling

لتخصيص البيئة (إعدادات الخادم، موارد إضافيّة، تثبيت حزم)، استخدم ملفّات .ebextensions/ في جذر ZIP. الملفات YAML/JSON بامتداد .config.

To customize the environment (server settings, extra resources, package install), use .ebextensions/ files in the ZIP root. YAML/JSON files with .config extension.

# .ebextensions/01-options.config
option_settings:
  aws:elasticbeanstalk:application:environment:
    SPRING_PROFILES_ACTIVE: prod
    JAVA_OPTS: '-Xmx1g -XX:+UseG1GC'
  aws:autoscaling:asg:
    MinSize: 2
    MaxSize: 6

# .ebextensions/02-elasticache.config
Resources:
  CacheCluster:
    Type: AWS::ElastiCache::CacheCluster
    Properties:
      Engine: redis
      CacheNodeType: cache.t3.micro
      NumCacheNodes: 1
فخّ شائع:Common pitfall: الموارد المُدارة بـ .ebextensions تُحذَف مع حذف الـ Environment (لأنّ Beanstalk هو CloudFormation Stack). لذلك لا تُنشئ RDS بـ .ebextensions لبيئة إنتاج. Resources managed by .ebextensions are deleted when the environment is deleted (because Beanstalk = CloudFormation stack). So don't create RDS via .ebextensions for production.

RDS داخل Beanstalk (خطأ للـ Prod)RDS inside Beanstalk (bad for prod)

حياة قاعدة البيانات مرتبطة بالـ Environment. حذف Environment = حذف RDS والبيانات.

DB lifecycle tied to environment. Delete env = delete RDS and data.

RDS منفصل (الصحيح للـ Prod)Separate RDS (correct for prod)

أنشِئ RDS بـ Stack منفصل. مرِّر Connection String للتطبيق عبر Environment Variables.

Create RDS in a separate stack. Pass connection string to the app via env vars.

للمطوّر السينيور:For the senior dev: للترحيل من Beanstalk + RDS مدمج إلى منفصل: ١) خذ Snapshot، ٢) فعّل Deletion Protection على RDS، ٣) أنشئ Environment جديد بدون RDS يشير إلى RDS القديم، ٤) Swap URLs، ٥) احذف Environment القديم (RDS سيبقى). To migrate from Beanstalk + embedded RDS to separate: 1) take a snapshot, 2) enable RDS deletion protection, 3) create a new env without RDS pointing to the old RDS, 4) swap URLs, 5) delete old env (RDS remains).

EB CLI، Lifecycle Policy، و Cloning EB CLI, lifecycle policy & cloning

EB CLI أداة سطر أوامر مخصّصة لـ Beanstalk (مختلفة عن AWS CLI). مفيدة للـ CI/CD pipelines.

EB CLI is a Beanstalk-specific command-line tool (different from the AWS CLI). Useful for CI/CD pipelines.

# Install EB CLI
pip install awsebcli

# Initialize in project directory
eb init            # sets up app + region
eb create prod     # creates an environment called 'prod'
eb deploy          # deploys current code
eb status
eb logs            # fetch logs
eb open            # open in browser
eb config          # edit environment config
eb terminate       # destroy environment

Lifecycle PolicyLifecycle Policy

Beanstalk يحتفظ بأقصى ١٠٠٠ إصدار. تستخدم Lifecycle Policy لحذف القديم بالوقت أو العدد (لكن ليس المستخدمة حالياً).

Beanstalk stores up to 1000 versions. Use a lifecycle policy to drop old ones by age or count (but not ones currently in use).

CloningCloning

نسخ Environment بنفس الإعدادات. مفيد لإنشاء test env مطابق لـ prod. البيانات في RDS لا تُنسَخ.

Clone an environment with identical config. Useful for creating a test env mirroring prod. RDS data is not cloned.

Load Balancer TypeLoad Balancer Type

لا يمكن تغيير نوع ELB بعد إنشاء Environment (ALB، NLB، CLB). الحل: Environment جديد + CNAME Swap.

ELB type (ALB, NLB, CLB) cannot change after env creation. Solution: new env + CNAME swap.

Deployment BundleDeployment Bundle

ZIP يحتوي على كودك + pom/package.json + أي .ebextensions. الحجم الأقصى ٥١٢ MB.

ZIP with your code + pom/package.json + any .ebextensions. 512 MB max.

معمل عملي Hands-on Lab

الهدف: نشر تطبيق Spring Boot على Beanstalk مع Rolling with additional batches، ثم ترقيته لنسخة جديدة.

Goal: Deploy a Spring Boot app on Beanstalk with 'Rolling with additional batches', then upgrade to a new version.

  1. ١

    جهّز Spring Boot JAR Prepare the Spring Boot JAR 

    mvn clean package
# produces target/acme-app-1.0.jar (fat jar)
  2. ٢

    ثبّت EB CLI وأنشئ البيئة Install EB CLI and create env 

    pip install awsebcli
eb init acme-app --region=us-east-1 --platform='Corretto 17'
eb create prod --instance-type=t3.small --min-instances=2 --max-instances=4
  3. ٣

    أضف .ebextensions للإعدادات Add .ebextensions for config

    احفظ الملف في جذر مشروع Spring Boot تحت .ebextensions/01-env.config

    Save file in Spring Boot project root under .ebextensions/01-env.config

    option_settings:
  aws:elasticbeanstalk:application:environment:
    SPRING_PROFILES_ACTIVE: prod
    JAVA_OPTS: '-Xmx1g'
  aws:elasticbeanstalk:command:
    DeploymentPolicy: RollingWithAdditionalBatch
    BatchSizeType: Percentage
    BatchSize: 25
  4. ٤

    انشر الإصدار الأوّل Deploy first version 

    eb deploy
eb open  # open browser on the URL
  5. ٥

    حدّث الكود وأعِد النشر Update code and redeploy

    Beanstalk سيُطبّق Rolling with additional batches: ٢٥٪ في كل batch مع Instances جديدة مؤقّتة.

    Beanstalk applies Rolling with additional batches: 25% per batch with temporary new instances.

    # Change version in pom.xml, rebuild, redeploy
mvn clean package
eb deploy
  6. ٦

    تنظيف Cleanup 

    eb terminate prod
تنبيه: Warning: لا تُنشئ RDS من داخل Beanstalk في بيئات الإنتاج. استخدم Stack منفصل أو AWS Console، ومرّر Connection String للتطبيق عبر Environment Variables. Don't create RDS from inside Beanstalk for production. Use a separate stack or AWS Console, and pass the connection string to the app via env vars.

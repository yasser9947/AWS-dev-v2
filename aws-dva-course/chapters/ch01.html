ما هي AWS ولماذا نستخدمها؟ What is AWS and why use it?

AWS هي اختصار لـ Amazon Web Services، وهي مزوّد خدمات سحابية يقدّم أكثر من مئتَي خدمة للحوسبة والتخزين والبرمجيات. انطلقت علنياً عام ٢٠٠٦ مع ثلاث خدمات فقط: SQS و S3 و EC2. اليوم هي اللاعب الأول في سوق السحابة بحصة ٣١٪ (الربع الأول من ٢٠٢٤)، وإيراد سنوي بلغ تسعين مليار دولار عام ٢٠٢٣.

AWS (Amazon Web Services) is a cloud provider offering 200+ compute, storage, and software services. Since its public relaunch in 2006 with SQS, S3, and EC2, it became the market leader with 31% market share (Q1 2024) and $90B annual revenue (2023).

لماذا AWS؟ Why AWS?

  • لا شراء مسبق للأجهزة، بل دفع حسب الاستخدام. No upfront hardware cost — pay-as-you-go.
  • مرونة وتوسعة خلال ثوانٍ. Elasticity — scale in seconds.
  • بنية تحتية عالمية تقلّل زمن الاستجابة للعملاء. Global infrastructure — lower latency for users.
  • أمان على مستوى المؤسسات والبنوك. Enterprise-grade security.

حالات الاستخدام Use Cases

  • أنظمة المؤسسات والنسخ الاحتياطي والتخزين. Enterprise IT, backup & storage.
  • استضافة المواقع والتطبيقات. Website & app hosting.
  • تحليل البيانات الضخمة. Big Data analytics.
  • تطبيقات الجوال والتواصل الاجتماعي والألعاب. Mobile, social apps, gaming.
مفهوم أساسي للامتحان: Key exam concept: البنية التحتية لـ AWS تتوزّع على أربع طبقات متتالية: نطاق الخدمة، ثم مناطق التوفّر، ثم مراكز البيانات، ثم مواقع الحافة. لكلّ طبقة دور مختلف. والامتحان يحبّ أن يسأل: أيّ خدمة عالمية وأيّ خدمة إقليمية؟ AWS infrastructure is split into four layers: Regions → AZs → Data Centers → Edge Locations. Each has a distinct role — and the exam loves asking which service is Global vs Regional.

نطاقات الخدمة — AWS Regions AWS Regions

النطاق (Region) هو تجمّع من مراكز البيانات في منطقة جغرافية محدّدة. كل نطاق معزول تماماً عن غيره على مستوى البيانات والشبكات، إلّا إذا فعّلت أنت صراحةً نسخاً عبر النطاقات. أسماء النطاقات تتبع صيغة موحّدة مثل us-east-1 (ولاية فرجينيا الشمالية)، و eu-west-3 (باريس)، وهكذا.

A Region is a cluster of data centers in a specific geographic area. Regions are fully isolated (data, networking) unless you explicitly enable cross-region replication. Region names follow a standard format: us-east-1 (N. Virginia), eu-west-3 (Paris), etc.

كيف تختار نطاقاً؟ أربعة معايير How to choose a Region? (4 criteria)

١. الامتثال التنظيمي 1. Compliance

بعض الدول تشترط ألّا تغادر البيانات أراضيها (مثل لائحة GDPR في أوروبا، ولائحة PDPL في السعودية). البيانات داخل النطاق لا تغادره إلّا بإذن صريح منك.

Some countries require data residency (GDPR in EU, PDPL in Saudi Arabia). Data in a Region never leaves it without your permission.

٢. قرب العملاء 2. Proximity to users

إذا كان عملاؤك في دبي، استخدم نطاق me-central-1 بدلاً من us-east-1. الفرق في زمن الاستجابة قد يتجاوز مئتي ميلي ثانية.

Users in Dubai? Use me-central-1 instead of us-east-1 — latency difference is 200ms+.

٣. توفّر الخدمات 3. Service availability

الخدمات الجديدة تُطلق أوّلاً في us-east-1. بعض النطاقات الحديثة (كالإمارات) قد ينقصها بعض الخدمات. راجع Region Services Table قبل الاختيار.

New services launch first in us-east-1. Newer Regions (e.g. UAE) may lack some services. Check the Region Services Table.

٤. التسعير 4. Pricing

الخدمة الواحدة قد يختلف سعرها من نطاق لآخر. عادةً us-east-1 هو الأرخص. الأسعار معلنة بشفافية في صفحة كل خدمة.

The same service varies in price between Regions. Usually us-east-1 is cheapest. Pricing is transparent on each service page.

مناطق التوفّر — Availability Zones Availability Zones (AZs)

كل نطاق يحتوي على ثلاث إلى ست مناطق توفّر، والحدّ الأدنى ثلاث. كل منطقة توفّر عبارة عن مركز بيانات مستقلّ (أو أكثر) له كهرباء وشبكة منفصلة، ومعزول فيزيائياً عن باقي المناطق ليحميك من الكوارث. لكنّ هذه المناطق متّصلة ببعضها بشبكة عالية الإنتاجية وزمن استجابة قصير جداً — وهذا هو السرّ خلف التوافرية العالية في AWS.

Each Region has 3–6 AZs (minimum 3). An AZ is one or more discrete data centers with independent power, networking, and connectivity — physically separated from other AZs for disaster isolation. AZs are connected via high-bandwidth, ultra-low latency networking — that's how you get High Availability.

مثال: نطاق سيدني Example: Region = ap-southeast-2 (Sydney)
ap-southeast-2

ap-southeast-2a

منطقة التوفّر الأولى AZ 1

ap-southeast-2b

منطقة التوفّر الثانية AZ 2

ap-southeast-2c

منطقة التوفّر الثالثة AZ 3

متّصلة ببعضها بشبكة عالية السرعة وزمن استجابة قصير. Connected via high-bandwidth, low-latency networking.
نصيحة للامتحان: Exam tip: معرّف منطقة التوفّر الثابت (AZ ID) مثل use1-az1 يختلف عن اسمها (AZ name) مثل us-east-1a. الأسماء تختلف بين الحسابات (منطقة us-east-1a في حسابك قد تكون منطقة us-east-1b في حساب آخر) لتوزيع الحِمل بين العملاء، بينما المعرّفات الثابتة هي نفسها عبر الحسابات. هذه المعلومة تُسأل في سياق مشاركة شبكات VPC بين الحسابات. An AZ ID (e.g. use1-az1) is not the same as AZ name (us-east-1a) — names differ between accounts (your us-east-1a ≠ my us-east-1a) for load balancing, while IDs are stable. Important when sharing VPCs across accounts.

مواقع الحافة — Edge Locations Edge Locations (Points of Presence)

مواقع الحافة عبارة عن مواقع صغيرة منتشرة في أكثر من أربع مئة مدينة داخل أربعين دولة، مهمّتها تقريب المحتوى من المستخدم النهائي عبر التخزين المؤقّت. يستخدمها بشكل رئيسي: CloudFront لتوزيع المحتوى، و S3 Transfer Acceleration لتسريع الرفع، و Route 53 لخدمة أسماء النطاقات.

Edge Locations are smaller sites spread across 400+ cities in 40+ countries, bringing content closer to end users via caching. They're mainly used by: CloudFront for content delivery, S3 Transfer Acceleration for faster uploads, and Route 53 for DNS.

AZ

منطقة التوفّر Availability Zone

مركز بيانات كامل داخل النطاق. يستضيف الخوادم الفعلية لتطبيقك.

Full data center inside a Region. Hosts your actual compute.

RE

ذاكرة مؤقّتة إقليمية Regional Edge Cache

أكثر من عشرة مواقع، تعمل كطبقة تخزين مؤقّت بين المصدر الأصلي ومواقع الحافة. تُستخدم للمحتوى الأقلّ شعبيةً.

10+ sites — caching tier between origin and Edge Locations. For less-popular content.

EL

موقع حافة Edge Location

أكثر من أربع مئة موقع صغير، تخزّن المحتوى الشعبي قرب المستخدم. هي نقاط التواجد لخدمة CloudFront.

400+ small sites. Caches popular content near users. CloudFront PoPs.

الخدمات العالمية مقابل الإقليمية Global vs Regional Services

هذا من أكثر المواضيع تكراراً في الامتحان: أيّ خدمة عالمية وأيّ خدمة إقليمية؟ الفرق مهمّ لأنه يؤثّر على نقاط الوصول (endpoints) والتسعير وسلوك النسخ الاحتياطي.

This is one of the most frequent exam questions: which service is Global vs Regional? The difference matters — it affects endpoints, pricing, and replication behavior.

خدمات عالمية Global Services

لا تنتمي إلى نطاق محدّد Not tied to a Region

  • IAM — إدارة المستخدمين والصلاحيات users and permissions
  • Route 53 — خدمة أسماء النطاقات DNS
  • CloudFront — شبكة توصيل المحتوى CDN
  • WAF — جدار حماية تطبيقات الويب Web Application Firewall

خدمات إقليمية Regional Services

مرتبطة بنطاق محدّد Scoped to a specific Region

  • EC2 — بنية تحتية كخدمة IaaS
  • Lambda — دوال سحابية FaaS
  • DynamoDB, RDS, S3*
  • Elastic Beanstalk — منصّة كخدمة PaaS
فخّ شائع في الامتحان: Common pitfall: أسماء S3 buckets عالمية (يجب أن يكون الاسم فريداً على مستوى AWS كلها)، لكنّ bucket نفسه إقليمي (البيانات تُخزَّن فعلياً في نطاق واحد). لا تخلط بين الاسم والمورد. S3 bucket names are Global (unique across all of AWS) but the bucket itself is Regional (data resides in one Region). Don't confuse the name with the resource.

نموذج المسؤولية المشتركة Shared Responsibility Model

AWS وأنت تتقاسمان مسؤوليات الأمان. باختصار: AWS مسؤولة عن أمان السحابة ذاتها (الأجهزة، المباني، برامج المحاكاة الافتراضية). وأنت مسؤول عن الأمان داخل السحابة (بياناتك، الصلاحيات، التشفير، تحديثات نظام التشغيل على خوادم EC2).

AWS and you share security responsibilities. In short: AWS secures the Cloud itself (hardware, facilities, hypervisor), and you secure what's in the Cloud (your data, IAM, encryption, OS patches on EC2).

AWS

مسؤولة عن أمان السحابة Security OF the Cloud

  • • الأجهزة الفيزيائية • Physical hardware
  • • الشبكة الفيزيائية • Physical network
  • • المباني وأمانها • Facilities security
  • • برامج المحاكاة الافتراضية • Hypervisor (virtualization)
  • • الخدمات المُدارة مثل RDS و Lambda (التحديثات والنسخ الاحتياطي) • Managed services — patching & backups

أنت You

مسؤول عن الأمان داخل السحابة Security IN the Cloud

  • • بياناتك (تشفيرها، تصنيفها) • Your data (encryption, classification)
  • • الهويات والصلاحيات والأدوار • IAM: users, roles, policies
  • • نظام التشغيل على خوادم EC2 (التحديثات، الجدار الناري) • OS on EC2 (patching, firewall)
  • • مجموعات الأمان وقوائم التحكم بالشبكة • Security Groups and Network ACLs
  • • تطبيقك والكود الذي تكتبه • Your application code

ثلاث طرق رئيسية للتفاعل مع AWS Ways to Interact with AWS

أمامك ثلاث طرق للتحكّم في AWS، وجميعها تستدعي في النهاية نفس واجهة البرمجة الأساسية.

You have 3 main ways to control AWS — all ultimately call the same underlying API.

AWS Management Console

واجهة ويب للتحكّم اليدوي. ممتازة للاستكشاف والتعلّم، لكنها لا تصلح للإنتاج لأنها يدوية وصعبة التكرار.

Web UI. Great for exploration and learning, but not suited for production — manual and hard to reproduce.

console.aws.amazon.com

AWS CLI (Command Line Interface)

أوامر سطر الأوامر. مثالية لسكربتات الأتمتة وتسلسل الأوامر. مكتوبة بلغة بايثون.

Shell commands. Ideal for scripts and automation. Written in Python. 

# List all S3 buckets in the account
aws s3 ls

# List EC2 instances in a specific region
aws ec2 describe-instances --region us-east-1

# Create an S3 bucket
aws s3 mb s3://acme-app-artifacts-20260423 --region us-east-1

# Invoke a Lambda function
aws lambda invoke --function-name process-orders \
  --payload '{"orderId":"12345"}' response.json

# Check your identity (super useful for debugging IAM)
aws sts get-caller-identity

AWS SDKs

مكتبات للغات البرمجة: جافا وبايثون (boto3) وجافا سكريبت و Go و C# و Ruby وغيرها. تستدعيها من داخل كود تطبيقك.

Language-native libraries: Java, Python (boto3), JavaScript, Go, C#, Ruby, and more. Use them from inside your app. 

// Java SDK v2 — list all S3 buckets
import software.amazon.awssdk.regions.Region;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.ListBucketsResponse;

public class ListBuckets {
    public static void main(String[] args) {
        S3Client s3 = S3Client.builder()
            .region(Region.US_EAST_1)
            .build();

        ListBucketsResponse response = s3.listBuckets();
        response.buckets().forEach(bucket ->
            System.out.println(bucket.name())
        );

        s3.close();
    }
}

نفس المثال بلغة بايثون (boto3): Same example in Python (boto3): 

import boto3

s3 = boto3.client('s3', region_name='us-east-1')
response = s3.list_buckets()

for bucket in response['Buckets']:
    print(bucket['Name'])
للمطوّر السينيور: For the senior dev: كما تتعامل مكتبتا RestTemplate و WebClient في Spring مع بروتوكول HTTP، فإنّ AWS SDK هو عميل HTTP متخصّص: يدير إعادة المحاولة مع التباعد الأسّي تلقائياً، والتوقيع الأمني (SigV4)، وتجميع الاتّصالات. لا تستخدم HTTP مباشرةً إلّا إذا اضطررت. Just like Spring's RestTemplate / WebClient wrap HTTP, the AWS SDK is a specialized HTTP client handling retries/backoff, SigV4 signing, and connection pooling. Don't hit HTTP directly unless forced to.

الملخّص وأهمّ النقاط Summary & Key Takeaways

النطاق = تجمّع مراكز بيانات Region = Cluster of Data Centers

معزولة تماماً. البيانات لا تغادر النطاق إلّا بطلبك.

Fully isolated. Data never leaves a Region without your request.

منطقة التوفّر = مركز بيانات منفصل AZ = Discrete Data Center(s)

من ٣ إلى ٦ مناطق في كل نطاق. منفصلة فيزيائياً، متّصلة بشبكة عالية السرعة.

3–6 AZs/Region. Physically separate, high-speed interconnect.

الخدمات العالمية أربع Global Services = 4

IAM · Route 53 · CloudFront · WAF

المسؤولية المشتركة Shared Responsibility

AWS مسؤولة عن أمان السحابة، وأنت عن الأمان داخلها.

AWS = security OF cloud. You = security IN cloud.

وسيلة للحفظ السريع: Mnemonic:

الخدمات العالمية الأربع: I R C W — أي IAM و Route 53 و CloudFront و WAF. فكّر فيها كعبارة "I Route Content Worldwide" أي أنا أوجّه المحتوى عبر العالم.

The 4 Global services: I R C W = IAM · Route 53 · CloudFront · WAF — think "I Route Content Worldwide".

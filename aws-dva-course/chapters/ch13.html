ما هي API Gateway ومتى تستخدمها What is API Gateway and when to use it

API Gateway خدمة مُدارة بالكامل تُتيح لك إنشاء ونشر وإدارة APIs بدون بنية تحتية. تعالج المصادقة، الاختناق، التخزين المؤقّت، المراقبة، ونسخ الـ APIs — وهي الشريك الدائم لـ Lambda في المعمار serverless. للعميل هي نقطة دخول واحدة تخفي تعقيدات الـ backend.

API Gateway is a fully managed service for creating, publishing, and managing APIs with zero infrastructure. It handles authentication, throttling, caching, monitoring, and API versioning — the forever-partner of Lambda in serverless. To clients, it's a single entry point that hides backend complexity.

REST APIREST API

الأغنى بالميزات. يدعم mapping templates, request validation, usage plans, API keys, WAF, private endpoint.

Feature-rich. Supports mapping templates, request validation, usage plans, API keys, WAF, private endpoints.

HTTP APIHTTP API

٧٠٪ أرخص، زمن استجابة أقل. يدعم JWT/OIDC مباشرة و CORS مدمج. لا يدعم usage plans أو mapping templates.

70% cheaper, lower latency. Native JWT/OIDC, built-in CORS. No usage plans or mapping templates.

WebSocket APIWebSocket API

اتّصال ثنائي الاتّجاه مستمرّ. للتطبيقات الفورية: chat, multi-player games, trading.

Persistent two-way connection. For real-time: chat, multiplayer games, trading.

Endpoint Types وأنواع التكامل Endpoint Types & Integration Types

عند إنشاء API عندك ثلاثة أنواع Endpoints: Edge-Optimized (الافتراضي — يمرّ عبر CloudFront لأداء عالمي)، Regional (لعملاء داخل نفس الـ region)، Private (فقط من داخل VPC عبر Interface VPC Endpoint).

When creating an API you pick from three Endpoint Types: Edge-Optimized (default — routes via CloudFront for global performance), Regional (for in-region clients), Private (only reachable from a VPC via Interface VPC Endpoint).

أنواع التكامل (Integration Types) من أهمّ مواضيع الامتحان. كل method في الـ API لها integration type يحدّد كيف تتعامل مع الـ backend:

AWS_PROXY (Lambda Proxy)AWS_PROXY (Lambda Proxy)

بدون mapping templates. الـ headers وquery strings و path params تصل لـ Lambda في event object جاهز. Lambda ترجع {statusCode, headers, body}. الـ body يجب أن يكون string (JSON.stringify).

No mapping templates. Headers, query strings, path params arrive as a ready event. Lambda returns {statusCode, headers, body}. Body must be a string (JSON.stringify).

AWS (Custom)AWS (Custom)

VTL mapping templates transform client payload to Lambda/AWS format. More control, cleaner Lambda code, more maintenance.

            "Content-Type", "application/json",
            "Access-Control-Allow-Origin", "*"))

Deployment Stages و Canary و Stage Variables Deployment Stages, Canary & Stage Variables

تغيير في API Gateway لا يصبح فعّالاً إلّا بعد Deployment. يُنشر لـ Stage (dev, test, prod, v1, v2...). كل stage له إعداداته الخاصّة (throttling, caching, logging). وتُحفظ تاريخ النشر لاحتمال rollback.

A change in API Gateway isn't live until you create a Deployment. It's published to a Stage (dev, test, prod, v1, v2...). Each stage has its own config (throttling, caching, logging). Deployment history is retained so you can roll back.

Stage VariablesStage Variables

متغيّرات بيئة للـ stage. تُستخدم في: Lambda ARN (أو alias مثل ${stageVariables.lambdaAlias})، HTTP endpoint، mapping templates. تمكّنك من تبديل الـ backend بدون تعديل الـ API.

Stage-scoped env vars. Used in: Lambda ARN (or alias like ${stageVariables.lambdaAlias}), HTTP endpoint, mapping templates. Let you swap backends without editing the API.

Canary DeploymentCanary Deployment

يرسل ٪ محدّد من حركة المرور للإصدار الجديد (canary). مقاييس منفصلة. طريقة blue/green مع Lambda + API Gateway.

Routes a % of traffic to the new version (canary). Separate metrics. The blue/green approach with Lambda + API Gateway.

للمطوّر السينيور:For the senior dev: نمط سينيور: استخدم stage variable لاسم Lambda alias (مثلاً prod, canary)، واستفد من Lambda Weighted Aliases (٩٥٪/٥٪) لتقسيم الحركة بدون لمس API Gateway. هذا المعمار المفضّل للنشر التدريجي في serverless. Senior pattern: put a stage variable for the Lambda alias (e.g. prod, canary) and use Lambda Weighted Aliases (95%/5%) to split traffic without touching API Gateway. That's the canonical progressive-deployment pattern in serverless. 
# Deploy API changes to the prod stage
aws apigateway create-deployment \
  --rest-api-id abc123 \
  --stage-name prod \
  --description 'release 2024-11 - add /orders'

# Configure canary on prod stage: 10% to canary
aws apigateway update-stage \
  --rest-api-id abc123 --stage-name prod \
  --patch-operations \
    'op=replace,path=/canarySettings/percentTraffic,value=10' \
    'op=replace,path=/canarySettings/useStageCache,value=false'

الأمان: Authorizers و IAM و Cognito و CORS Security: Authorizers, IAM, Cognito & CORS

لـ API Gateway ثلاثة مسارات للمصادقة/التفويض، ولكلٍّ استخدامه. هذا من أكثر مواضيع الامتحان سؤالاً:

API Gateway has three auth paths, each with its niche. It's one of the most-asked exam topics:

نصيحة للامتحان:Exam tip: Lambda Authorizer: Lambda تستقبل الـ token وتُرجع IAM policy. نتيجتها تُخزَّن مؤقتاً (cache) لـ ٣٠٠ ثانية افتراضياً — لذا يُفضَّل للـ tokens ذات عمر طويل. نوعان: Token-based (JWT في Authorization header) و Request parameter-based (headers/query strings). Lambda Authorizer: Lambda receives the token and returns an IAM policy. Result is cached for 300 seconds by default — best for long-lived tokens. Two kinds: Token-based (JWT in Authorization header) and Request parameter-based (headers/query strings).

CORS (Cross-Origin Resource Sharing) — من أكثر المشاكل شيوعاً عند ربط frontend (مثل S3 static site) مع API Gateway على domain مختلف. المتصفّح يُرسل preflight OPTIONS request قبل الطلب الحقيقي ويتوقّع الـ headers التالية في الاستجابة: Access-Control-Allow-Origin, Access-Control-Allow-Methods, Access-Control-Allow-Headers.

CORS (Cross-Origin Resource Sharing) — the most common pain when connecting a frontend (e.g. S3 static site) to API Gateway on a different domain. The browser sends a preflight OPTIONS request before the real one and expects these headers back: Access-Control-Allow-Origin, Access-Control-Allow-Methods, Access-Control-Allow-Headers.

فخّ شائع:Common pitfall: فخّ CORS الامتحاني: إن رأيت في السؤال "CORS error from browser" أو "API works from Postman but not browser"، الحلّ دائماً: فعّل CORS في API Gateway (ينشئ method OPTIONS تلقائياً مع الـ headers). الـ Lambda مع Proxy Integration يجب أن ترجع Access-Control-Allow-Origin بنفسها. CORS exam trap: if the question says "CORS error from browser" or "works in Postman but not browser", the answer is always: enable CORS in API Gateway (creates OPTIONS method with proper headers). With Lambda Proxy Integration, your Lambda must also return Access-Control-Allow-Origin itself.

Throttling و Caching و Usage Plans و Monitoring Throttling, Caching, Usage Plans & Monitoring

API Gateway يحدّ الطلبات على ثلاثة مستويات. الـ Account Limit الافتراضي ١٠٬٠٠٠ طلب/ثانية عبر كل الـ APIs (قابل للرفع). يمكن ضبط Stage Limits و Method Limits للحماية من API واحد يستهلك كل الـ quota. الـ Usage Plans تُقيّد العملاء فردياً بـ API Keys.

API Gateway throttles at three levels. Default Account Limit is 10,000 RPS across all APIs (soft, raisable). Set Stage Limits and Method Limits to stop one API hogging quota. Usage Plans throttle individual customers by API Key.

Throttling — 429Throttling — 429

تجاوز الحدّ يُرجع 429 Too Many Requests (قابل للإعادة). إعدّ الاستراتيجية: exponential backoff في العميل.

Exceeding the limit returns 429 Too Many Requests (retriable). Strategy: exponential backoff on client.

Caching per stageCaching per stage

TTL افتراضي ٣٠٠ ثانية (أقصى ٣٦٠٠). الحجم ٠.٥ – ٢٣٧ GB. يقلّل الطلبات للـ backend. الـ cache per stage ويمكن تجاوزه per method.

Default TTL 300s (max 3600). Size 0.5 – 237 GB. Reduces backend calls. Cache is per stage, overridable per method.

Usage Plans & API KeysUsage Plans & API Keys

API Keys تُرسَل في header x-api-key. Usage Plan يربط الـ key بـ throttling وquota لكل عميل. متاح في REST API فقط.

API Keys go in x-api-key header. Usage Plan links keys to throttling/quota per customer. REST API only.

CloudWatch & X-RayCloudWatch & X-Ray

مقاييس: CacheHit/MissCount, Count, Latency, IntegrationLatency, 4XXError, 5XXError. X-Ray للـ tracing عبر Lambda.

Metrics: CacheHit/MissCount, Count, Latency, IntegrationLatency, 4XXError, 5XXError. X-Ray traces to Lambda.

نصيحة للامتحان:Exam tip: ترتيب إنشاء Usage Plan الصحيح: (١) أنشئ API وفعّل API Key على الـ methods. (٢) انشر API على stage. (٣) أنشئ/استورد API Keys. (٤) أنشئ Usage Plan بحدود throttle وquota. (٥) اربط الـ Stage والـ Keys بالـ Usage Plan. العملاء يرسلون الـ key في x-api-key header. Correct Usage Plan order: (1) create API, enable API Key on methods. (2) deploy to a stage. (3) generate/import API Keys. (4) create Usage Plan with throttle/quota. (5) associate Stage and Keys with the Usage Plan. Clients send the key in the x-api-key header.

فخّ شائع:Common pitfall: حدّ API Gateway ٢٩ ثانية للـ integration timeout. لو احتجت لعملية أطول: اجعل API يُرجع ٢٠٢ Accepted ويستدعي Lambda غير متزامنة أو Step Function ويعيد للعميل polling URL أو webhook. API Gateway's 29-second integration timeout is hard. For longer ops: return 202 Accepted, invoke async Lambda or Step Function, give client a polling URL or webhook.

OpenAPI (Swagger) 3.0 تستطيع استيراده مباشرة في API Gateway لإنشاء كامل الـ API من ملف واحد (YAML/JSON). تدعم امتدادات AWS الخاصّة (x-amazon-apigateway-*) لتكوين التكامل والـ validators. يمكن تصدير الـ API كـ OpenAPI spec أيضاً. Request Validation يُفعَّل عبر هذه المواصفة ويرفض الطلبات غير المطابقة قبل ضرب الـ backend.

OpenAPI (Swagger) 3.0 can be imported directly into API Gateway to create the whole API from one YAML/JSON file. AWS extensions (x-amazon-apigateway-*) cover integrations and validators. You can also export the API as OpenAPI. Request Validation is wired via the spec and rejects malformed requests before they hit backend.

WebSocket API: اتّصال مستمرّ ثنائي الاتجاه. العميل يتّصل على wss://{id}.execute-api.{region}.amazonaws.com/{stage} فيُستدعى Lambda $connect مع connectionId. تخزّن الـ connectionId (عادة في DynamoDB) ثم تدفع الرسائل للعملاء عبر الـ ManagementApi. الـ routes: $connect, $disconnect, $default، ومسارات مخصّصة.

WebSocket API: persistent bidirectional connection. Client connects to wss://{id}.execute-api.{region}.amazonaws.com/{stage}, triggering Lambda $connect with a connectionId. Store connectionIds (usually in DynamoDB) and push to clients via the ManagementApi. Routes: $connect, $disconnect, $default, plus custom routes.

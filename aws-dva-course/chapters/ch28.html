AWS X-Ray و CloudTrail — التتبّع الموزّع والتدقيق AWS X-Ray & CloudTrail — Distributed Tracing & Audit

X-Ray يجيب عن "أين يتأخّر طلبي؟" بخريطة خدمات بصريّة. CloudTrail يجيب عن "من فعل ماذا ومتى؟" في حسابك. معاً يكملان CloudWatch لإغلاق دائرة المراقبة. X-Ray answers "where is my request slow?" with a visual service map. CloudTrail answers "who did what and when?" in your account. Together they complement CloudWatch to close the observability loop.

ما هو AWS X-Ray ولماذا؟ What is AWS X-Ray & why?

في العالم الموزّع (Lambda + API Gateway + DynamoDB + SNS) يصبح تصحيح الأعطال كابوساً: ملفّات سجلّ متناثرة وصيغ مختلفة. X-Ray يجمع كلّ الطلب في trace واحد بصريّ يبيّن أين يُستهلك الوقت وأين تحدث الأخطاء. فكّر فيه كـ Zipkin/Jaeger على AWS.

In a distributed world (Lambda + API Gateway + DynamoDB + SNS), debugging becomes a nightmare of scattered logs and inconsistent formats. X-Ray unifies every request into a single visual trace showing where time is spent and where errors occur. Think Zipkin/Jaeger on AWS.

تشخيص الأداءPerformance diagnosis

يكشف الاختناقات و latency بين الخدمات.

Reveals bottlenecks and inter-service latency.

خريطة خدماتService Map

رسم تلقائيّ للاعتمادات بين الخدمات — حتى غير المطوّرين يفهمونه.

Auto-drawn dependency graph — even non-devs can follow.

أخطاء وخنقErrors & throttling

يُظهر Exceptions وحالات 429 Throttling أين بالضبط.

Pinpoints exceptions and 429 Throttling.

SLASLA

هل نلتزم بزمن الاستجابة المتعاقد عليه؟ X-Ray يرصد ذلك.

Are we meeting response-time SLA? X-Ray tracks it.

يتكامل X-Ray مع: Lambda، API Gateway، Elastic Beanstalk، ECS/EKS، ELB، EC2 (وحتى خوادم On-Prem). متوافق مع Java و Python و Go و Node.js و .NET.

Integrations: Lambda, API Gateway, Elastic Beanstalk, ECS/EKS, ELB, EC2 (even on-prem). Works with Java, Python, Go, Node.js, .NET.

المفاهيم الأساسيّة: Segments و Subsegments و Traces Core concepts: Segments, Subsegments, Traces

المفهومConceptالمعنىMeaning
Segmentالعمل الذي تقوم به خدمة واحدة (مثلاً: Lambda function). كلّ خدمة ترسل segment خاصّاً بها.The work one service does (e.g., a Lambda function). Each service emits its own segment.
Subsegmentتفصيل داخل segment لاستدعاء downstream (DynamoDB، HTTP client، SQL).Detail inside a segment for a downstream call (DynamoDB, HTTP client, SQL).
Traceمجموع segments لطلب واحد عبر كلّ الخدمات من البداية إلى النهاية.The collection of all segments for one request across all services, end to end.
Annotationskey/value مفهرسة للبحث والتصفية (مثل userId).Key/value pairs indexed for searching and filtering (e.g., userId).
Metadatakey/value غير مفهرسة، للمعلومات الإضافيّة فقط.Key/value not indexed, for extra context only.
مفهوم أساسي:Key concept: قاعدة ذهبيّة للامتحان: Annotations للبحث، Metadata للقراءة فقط. userId أو orderId ضعهما كـ annotation؛ payload الكامل ضعه metadata. Golden rule: Annotations = searchable, Metadata = context-only. Put userId/orderId as annotations; full payload as metadata. 
// Spring Boot + X-Ray SDK v2 — add annotations & subsegments
import com.amazonaws.xray.AWSXRay;

@RestController
public class OrderController {

    @GetMapping("/orders/{id}")
    public Order getOrder(@PathVariable String id) {
        // Make this trace searchable by order id
        AWSXRay.getCurrentSegment().putAnnotation("orderId", id);
        AWSXRay.getCurrentSegment().putMetadata("request-ip", requestIp());

        // Custom subsegment for business logic
        return AWSXRay.createSubsegment("loadOrder", subsegment -> {
            return orderRepo.findById(id);
        });
    }
}

التفعيل: Daemon و SDK و IAM Enabling X-Ray: Daemon, SDK, IAM

لتمكين X-Ray تحتاج خطوتين: (١) استيراد X-Ray SDK في الكود لإنشاء segments تلقائياً، و (٢) تشغيل X-Ray Daemon — وسيط UDP على المنفذ 2000 يجمع segments ويرسلها إلى خدمة X-Ray كلّ ثانية. Lambda و Beanstalk يشغّلان الـ daemon نيابةً عنك.

Enable X-Ray in 2 steps: (1) import the X-Ray SDK so segments are created automatically, and (2) run the X-Ray Daemon — a UDP listener on port 2000 that batches segments to the X-Ray service every second. Lambda & Beanstalk run the daemon for you.

ECS: Daemon ContainerECS: Daemon Container

حاوية واحدة للـ daemon على كلّ EC2 في الـ cluster (نمط DaemonSet). رخيص، لكن مشترَك بين المهامّ.

One daemon container per EC2 in the cluster (DaemonSet pattern). Cheap, but shared across tasks.

ECS / Fargate: SidecarECS / Fargate: Sidecar

حاوية daemon مرفقة مع كلّ مهمّة — العزل أفضل، وهو الخيار الوحيد في Fargate.

Daemon container attached per task — better isolation, only option on Fargate.

# Elastic Beanstalk enables X-Ray via .ebextensions/xray-daemon.config
option_settings:
  aws:elasticbeanstalk:xray:
    XRayEnabled: true

# The instance profile must allow writes to X-Ray (see IAM below).
// Minimum IAM policy for the X-Ray Daemon / application
{
  "Effect": "Allow",
  "Action": [
    "xray:PutTraceSegments",
    "xray:PutTelemetryRecords",
    "xray:GetSamplingRules",
    "xray:GetSamplingTargets",
    "xray:GetSamplingStatisticSummaries"
  ],
  "Resource": "*"
}
// Or the managed policy: arn:aws:iam::aws:policy/AWSXrayWriteOnlyAccess
فخّ شائع:Common pitfall: أكثر سببين لتعطّل X-Ray في الامتحان: (١) الـ IAM Role لا يمتلك xray:PutTraceSegments. (٢) على Lambda: Active Tracing غير مُفعّل في إعدادات الدالّة. Top 2 X-Ray failures on exam: (1) IAM Role missing xray:PutTraceSegments. (2) On Lambda: Active Tracing not enabled in function config.

قواعد أخذ العيّنات (Sampling Rules) Sampling Rules

تتبّع كلّ طلب يُكلّف كثيراً. Sampling Rules تتحكّم بكم من الطلبات تُسجَّل. الافتراضي: أوّل طلب في كلّ ثانية (Reservoir) ثمّ ٥٪ من الباقي (Rate). يمكن تعديل القواعد من الـ Console دون تعديل الكود.

Tracing every request is expensive. Sampling Rules control how many requests are recorded. Default: the first request each second (Reservoir) then 5% of additional requests (Rate). Rules are editable from the Console — no code change needed.

المفهومTermالشرحExplanation
Reservoirالحدّ الأدنى المضمون في الثانية (ضمان وجود trace واحد على الأقلّ).Guaranteed minimum per second (ensures at least one trace/sec).
Rateالنسبة المأخوذة من الطلبات الإضافيّة فوق Reservoir.Sampled percentage of additional requests above reservoir.
قاعدة PriorityPriority ruleرقم أصغر = أولويّة أعلى. تُطبَّق القاعدة الأعلى أولاً.Smaller = higher priority. First matching rule wins.
 
// Debugging rule: trace every PUT /history/* call
{
  "RuleName": "DEBUG-history-updates",
  "Priority": 1,
  "Reservoir": 1,
  "Rate": 1.0,
  "ServiceName": "scorekeep",
  "HTTPMethod": "PUT",
  "URLPath": "/history/*",
  "ResourceARN": "*"
}
للمطوّر السينيور:For the senior dev: للمطوّر السينيور: عند التحقيق في مشكلة إنتاج، أنشئ قاعدة مؤقّتة Priority=1, Rate=1.0 مقصورة على المسار المشكوك فيه، واحذفها فور انتهاء التحقيق لتقليل التكلفة. Senior dev: when investigating a prod issue, create a temporary Priority=1, Rate=1.0 rule scoped to the suspect path; delete after investigation to contain cost.

AWS CloudTrail — تدقيق كلّ API Call AWS CloudTrail — audit every API call

CloudTrail مُفعّل افتراضياً في كلّ حساب AWS، ويسجّل كل API call يُجرى عبر Console أو CLI أو SDK أو خدمات AWS نفسها. الوظيفة: الحوكمة، الامتثال، والتدقيق. إذا حُذف مورد — CloudTrail هو الوجهة الأولى للبحث.

CloudTrail is on by default in every AWS account, recording every API call made via Console, CLI, SDK, or AWS services themselves. Purpose: governance, compliance, audit. If a resource disappears — CloudTrail is where you look first.

Management Events (افتراضي)Management Events (default)

عمليّات الإدارة: IAM AttachRolePolicy، EC2 CreateSubnet، CloudTrail CreateTrail. قابل للتقسيم إلى Read vs Write.

Management ops: IAM AttachRolePolicy, EC2 CreateSubnet, CreateTrail. Splittable into Read vs Write.

Data Events (غير مسجّلة افتراضياً)Data Events (NOT default)

عمليّات على مستوى الكائنات: S3 GetObject/PutObject، Lambda Invoke. حجم ضخم ومكلفة — فعّل فقط عند الحاجة.

Object-level ops: S3 GetObject/PutObject, Lambda Invoke. High volume and expensive — enable only when needed.

CloudTrail Insights EventsCloudTrail Insights Events

ML تتعلّم النشاط الطبيعيّ وتنبّه عند انحرافات: فورة IAM، تجاوز حدود الخدمة.

ML learns normal activity and alerts on anomalies: IAM bursts, service-limit spikes.

الاحتفاظRetention

٩٠ يوماً في CloudTrail نفسها. لبقاء أطول: سلّم إلى S3 (خام) + Athena للاستعلام.

90 days in CloudTrail itself. For longer retention: deliver to S3 (raw) + Athena for querying.

Multi-Region TrailMulti-Region Trail

الافتراضي الجديد: يغطّي كلّ المناطق في حساب واحد. موصى به دائماً.

The new default: covers every region in one account. Always recommended.

Organization TrailOrganization Trail

في AWS Organizations: trail واحد مركزيّ يجمع أحداث كلّ الحسابات الفرعيّة — لا يمكن لحساب فرعي إيقافه.

In AWS Organizations: one central trail aggregates events from all member accounts — a member cannot disable it.

مفهوم أساسي:Key concept: Log file integrity validation: عند التسليم إلى S3، CloudTrail ينشئ ملفّ digest (SHA-256) كلّ ساعة. لاكتشاف تلاعب، تحقّق من سلسلة الـ digest عبر aws cloudtrail validate-logs. Log file integrity validation: on S3 delivery CloudTrail creates an hourly SHA-256 digest file. To detect tampering verify the digest chain via aws cloudtrail validate-logs.

التكامل: CloudTrail + CloudWatch + EventBridge Integration: CloudTrail + CloudWatch + EventBridge

CloudTrail وحده لا يرسل تنبيهات فوريّة. لتحقيق ذلك اربطه بـ CloudWatch Logs + Metric Filter + Alarm (مثلاً عند استدعاء DeleteTable في DynamoDB). أو اربطه بـ EventBridge مباشرة لردّ فعل أوتوماتيكيّ.

CloudTrail alone doesn't push real-time alerts. Wire it to CloudWatch Logs + Metric Filter + Alarm (e.g., trigger on DeleteTable in DynamoDB). Or plug directly into EventBridge for automated response.

// EventBridge rule: alert when anyone edits Security Group inbound rules
{
  "source": ["aws.ec2"],
  "detail-type": ["AWS API Call via CloudTrail"],
  "detail": {
    "eventSource": ["ec2.amazonaws.com"],
    "eventName": ["AuthorizeSecurityGroupIngress",
                  "RevokeSecurityGroupIngress"]
  }
}
// Target: SNS topic → security oncall channel
أيّ خدمة لماذا؟Which service when?الحالةScenario
من حذف Security Group؟Who deleted a Security Group?CloudTrail
لماذا الطلب بطيء على نظام microservices؟Why is a request slow across microservices?X-Ray
كم هي نسبة استخدام CPU؟What's the CPU utilization?CloudWatch Metrics
كم ظهور كلمة ERROR في الساعة؟How many ERRORs last hour?CloudWatch Logs Insights

معمل عملي Hands-on Lab

الهدف: تمكين X-Ray على تطبيق Spring Boot يعمل على Elastic Beanstalk، وإعداد CloudTrail trail متعدّد المناطق يبثّ إلى CloudWatch Logs لتنبيه على حذف قواعد البيانات.

Goal: Enable X-Ray on a Spring Boot app running on Elastic Beanstalk, and set up a multi-region CloudTrail trail streaming to CloudWatch Logs to alert on table deletions.

  1. ١

    فعّل X-Ray في Elastic Beanstalk Enable X-Ray in Beanstalk

    أضف ملفّ إعداد في مجلد .ebextensions/.

    Add a config file under .ebextensions/.

    # .ebextensions/xray-daemon.config
option_settings:
  aws:elasticbeanstalk:xray:
    XRayEnabled: true
  2. ٢

    امنح Instance Profile صلاحية الكتابة لـ X-Ray Give instance profile X-Ray write perms 

    aws iam attach-role-policy \
  --role-name aws-elasticbeanstalk-ec2-role \
  --policy-arn arn:aws:iam::aws:policy/AWSXrayWriteOnlyAccess
  3. ٣

    أدخل تعليمات X-Ray في الكود Instrument the code 

    // Spring Boot: register the AWS X-Ray servlet filter
@Bean
public FilterRegistrationBean<AWSXRayServletFilter> tracingFilter() {
    FilterRegistrationBean<AWSXRayServletFilter> bean = new FilterRegistrationBean<>();
    bean.setFilter(new AWSXRayServletFilter("acme-api"));
    return bean;
}
  4. ٤

    أنشئ CloudTrail متعدّد المناطق يسلّم إلى S3 و CloudWatch Logs Create a multi-region trail delivering to S3 + CloudWatch Logs 

    aws cloudtrail create-trail --name acme-audit \
  --s3-bucket-name acme-audit-bucket \
  --is-multi-region-trail \
  --enable-log-file-validation

aws cloudtrail update-trail --name acme-audit \
  --cloud-watch-logs-log-group-arn arn:aws:logs:us-east-1:111:log-group:acme-audit:* \
  --cloud-watch-logs-role-arn arn:aws:iam::111:role/CloudTrailToCloudWatch

aws cloudtrail start-logging --name acme-audit
  5. ٥

    أضف Metric Filter ينذر عند DeleteTable Add a Metric Filter alerting on DeleteTable 

    aws logs put-metric-filter --log-group-name acme-audit \
  --filter-name dynamo-delete-table \
  --filter-pattern '{ $.eventSource = "dynamodb.amazonaws.com" && $.eventName = "DeleteTable" }' \
  --metric-transformations \
    metricName=DynamoTableDeletions,metricNamespace=Acme/Audit,metricValue=1
تنبيه: Warning: Data Events في CloudTrail (مثل S3 GetObject) قد تولّد ملايين الأسطر في اليوم الواحد — لا تفعّلها عبر الـ bucket كاملاً إلا عند الضرورة. ألغِ الـ trail بعد الاختبار لتفادي تكلفة تخزين S3. CloudTrail Data Events (like S3 GetObject) can generate millions of lines a day — don't enable them bucket-wide unless needed. Disable the trail after testing to avoid S3 storage cost.

أساسيات Amazon VPC Amazon VPC Basics

VPC هي الشبكة الخاصّة التي تعيش فيها كلّ مواردك في AWS. امتحان المطوّر لا يطلب إتقاناً كاملاً — لكنّه يسأل عن المفاهيم الأساسيّة: Subnets، Internet Gateway، NAT، NACL، Security Groups، VPC Peering، Endpoints. هذه الأساسات كافية لاجتياز أيّ سؤال VPC في DVA. VPC is the private network where all your AWS resources live. The developer exam doesn't demand mastery — but it does test core concepts: Subnets, Internet Gateway, NAT, NACL, Security Groups, VPC Peering, Endpoints. These basics are enough for any VPC question on DVA.

VPC و Subnets و CIDR VPC, Subnets, and CIDR

VPC (Virtual Private Cloud) هو شبكتك الافتراضيّة الخاصّة داخل region واحدة. تقسّمها إلى Subnets (كلّ واحد يعيش في AZ واحدة بالضبط). الـ VPC يأخذ نطاق CIDR (مثلاً 10.0.0.0/16 = ٦٥٥٣٦ عنواناً)، والـ subnets تأخذ قطعاً منه.

VPC (Virtual Private Cloud) is your private virtual network within a single Region. You partition it into Subnets (each lives in exactly one AZ). A VPC takes a CIDR range (e.g., 10.0.0.0/16 = 65536 addresses), and subnets get slices of it.

Public SubnetPublic Subnet

Subnet يملك route إلى Internet Gateway في route table. الموارد فيه تحصل على IP عامّ وتُوصَل من الإنترنت (مع السماح في SG). مناسب لـ Load Balancers و bastion hosts.

A subnet with a route to an Internet Gateway in its route table. Resources get a public IP and are reachable from the Internet (if allowed by SG). Suitable for Load Balancers, bastion hosts.

Private SubnetPrivate Subnet

بدون route مباشر إلى Internet Gateway. الموارد فيه لا يمكن الوصول إليها من الإنترنت. للوصول الصادر (مثل yum update) تحتاج NAT Gateway. مناسب لـ application servers و databases.

No direct IGW route. Resources cannot be reached from the Internet. For outbound access (e.g., yum update) you need a NAT Gateway. Suitable for app servers, databases.

مفهوم أساسي:Key concept: نمط الإنتاج المعياريّ: 3 AZs، كلّ AZ فيها public subnet (لـ ALB و NAT) و private subnet (لـ EC2 و ECS) و data subnet (لـ RDS و ElastiCache). هذا "3-tier architecture" الذي يسأل عنه الامتحان كثيراً. Canonical production pattern: 3 AZs, each with a public subnet (ALB + NAT), a private subnet (EC2, ECS), and a data subnet (RDS, ElastiCache). This "3-tier architecture" shows up often on the exam.
نصيحة للامتحان:Exam tip: AWS يحجز ٥ عناوين في كلّ subnet (الأوّل: network، الثاني: VPC router، الثالث: DNS، الرابع: مستقبليّ، والأخير: broadcast). لذلك subnet /28 يعطيك ١١ عنواناً قابلاً للاستخدام لا ١٦. AWS reserves 5 addresses per subnet (first: network, second: VPC router, third: DNS, fourth: future, last: broadcast). A /28 subnet gives you 11 usable addresses, not 16.

Internet Gateway و NAT Gateway Internet Gateway and NAT Gateway

Internet Gateway (IGW) مورد VPC-scope يعطي الإنترنت لمواردك. يوجد واحد فقط لكلّ VPC. Subnet "public" يعني أنّ route table الخاصّ به يحوي 0.0.0.0/0 → igw-xxx.

Internet Gateway (IGW) is a VPC-scope resource that gives your resources Internet access. One per VPC. A "public" subnet means its route table has 0.0.0.0/0 → igw-xxx.

NAT Gateway (مُدار من AWS) أو NAT Instance (تديره بنفسك) يسمح للخوادم في private subnets بالخروج إلى الإنترنت (تحميل تحديثات، استدعاء APIs خارجيّة) بدون استقبال طلبات واردة. الـ NAT Gateway يعيش في public subnet ويحتاج Elastic IP.

NAT Gateway (AWS-managed) or NAT Instance (self-managed) lets instances in private subnets initiate outbound to the Internet (updates, external API calls) without accepting inbound. NAT Gateway lives in a public subnet and needs an Elastic IP.

For HA: place a NAT Gateway in every AZ (3 NATs for 3 AZs). Private subnet in AZ-A uses its AZ-A NAT, and so on. Prevents AZ-A outage from also killing AZ-B. Higher cost but real HA.

NACLs و Security Groups NACLs and Security Groups

هذا من أكثر أسئلة VPC في الامتحان. كلاهما يعمل كجدار ناريّ لكن على مستويات مختلفة، وبمنطق مختلف.

One of the most-asked VPC topics. Both act as firewalls, but at different levels and with different semantics.

مفهوم أساسي:Key concept: القاعدة الذهبيّة: Security Groups أوّلاً وافتراضياً. NACLs للحالات النادرة (حظر IPs مؤذية، عزل subnets). NACL stateless يعني أنّك يجب السماح بمنفذ الرد (ephemeral ports ١٠٢٤-٦٥٥٣٥) صراحةً. Rule of thumb: Security Groups first and by default. NACLs for rare cases (block malicious IPs, subnet-level isolation). NACL is stateless — you must explicitly allow the return traffic port range (ephemeral ports 1024-65535).

Security Group StatefulStateful Security Group

إذا سمحت بـ inbound على ٤٤٣، الرد outbound مسموح تلقائياً — لا داعي لقاعدة إضافيّة. بهذا SG أسهل بكثير.

Inbound allow on 443 auto-allows the outbound reply — no extra rule needed. Much easier.

VPC Peering و VPC Endpoints و VPC Flow Logs VPC Peering, VPC Endpoints, and Flow Logs

VPC Peering يربط اثنين VPC بحيث تتصل مواردهما كأنّها في نفس الشبكة. شروط: CIDR ranges لا تتداخل، و العلاقة غير انتقاليّة (not transitive) — VPC A مرتبطة بـ B، و B بـ C، لا يعني أنّ A تصل C مباشرةً.

VPC Peering connects two VPCs so their resources talk as if on one network. Requirements: non-overlapping CIDR, and non-transitive — A↔B, B↔C doesn't mean A↔C directly.

VPC Endpoints تسمح لمواردك داخل VPC بالوصول لخدمات AWS عبر شبكة AWS الخاصّة بدون المرور بالإنترنت. توفّر أمناً وأداءً أعلى وتكلفة أقلّ (لا تدفع NAT).

VPC Endpoints let resources inside your VPC reach AWS services over AWS's private network without traversing the Internet. Better security, lower latency, and no NAT bill.

Gateway EndpointGateway Endpoint

مجانيّ تقريباً. يُضاف كـ route في الـ route table. متاح فقط لـ S3 و DynamoDB. لا يدعم الوصول من VPCs أخرى أو on-premises.

Essentially free. Added as a route in the route table. Only available for S3 and DynamoDB. No access from other VPCs or on-premises.

Interface EndpointInterface Endpoint

يستخدم ENI مع IP خاصّ في subnets محدّدة. يكلّف بالساعة + بالـ GB. يدعم معظم خدمات AWS (بما فيها S3 و DynamoDB). يعمل عبر VPC Peering و VPN و Direct Connect.

Uses an ENI with a private IP in specified subnets. Billed hourly + per-GB. Supports most AWS services (including S3 and DynamoDB). Works across VPC Peering, VPN, Direct Connect.

VPC Flow Logs يلتقط معلومات عن كلّ IP traffic يمرّ عبر ENI. يمكن توجيه السجلّات إلى CloudWatch Logs أو S3 أو Kinesis Data Firehose. مستويات الالتقاط: VPC كامل، subnet، أو ENI واحد. مفيد لتشخيص المشاكل الأمنيّة وتتبّع الاختراقات.

VPC Flow Logs capture info on all IP traffic through an ENI. Logs can go to CloudWatch Logs, S3, or Kinesis Data Firehose. Capture levels: entire VPC, subnet, or single ENI. Useful for security forensics and breach investigations.

# Enable VPC Flow Logs for a whole VPC, sending to CloudWatch Logs
aws ec2 create-flow-logs \
  --resource-type VPC \
  --resource-ids vpc-0abc1234 \
  --traffic-type ALL \
  --log-destination-type cloud-watch-logs \
  --log-group-name /aws/vpc/acme-prod \
  --deliver-logs-permission-arn arn:aws:iam::123456789012:role/flowlogsRole
للمطوّر السينيور:For the senior dev: VPC Endpoints تحلّ مشكلة كبيرة في تطبيقات serverless: Lambda في private subnet تريد الوصول لـ S3. بدون Endpoint، تحتاج NAT Gateway (باهظ التكلفة مع حركة S3 كثيفة). Gateway Endpoint لـ S3 مجانيّ تقريباً ويلغي الحاجة للـ NAT لهذه الحركة. VPC Endpoints solve a big serverless cost issue: Lambda in a private subnet needing S3 access. Without an Endpoint, you need a NAT Gateway (expensive with heavy S3 traffic). S3 Gateway Endpoint is essentially free and removes NAT need for that traffic.

الاتصال بالـ on-premises: VPN و Direct Connect Connecting to on-premises: VPN and Direct Connect

للاتّصال بين Data Center خاصّتك و VPC هناك طريقتان: Site-to-Site VPN (عبر الإنترنت العامّ، مشفّر) و AWS Direct Connect (اتّصال فيزيائيّ خاصّ).

To connect your data center with a VPC: Site-to-Site VPN (over public Internet, encrypted) or AWS Direct Connect (physical dedicated connection).

Site-to-Site VPNSite-to-Site VPN

سريع الإعداد (ساعات). عبر الإنترنت — مشفّر ومعقّد. تكلفة منخفضة. Bandwidth محدود (عادة <١ Gbps). مناسب للـ DR أو الحمولات الخفيفة.

Fast to set up (hours). Over the Internet — encrypted, complexity shifts to your side. Low cost. Limited bandwidth (usually <1 Gbps). Fit for DR or light traffic.

Direct Connect (DX)Direct Connect (DX)

اتّصال فيزيائيّ بـ AWS. يستغرق ≥ شهر للإعداد. أداء ثابت (١-١٠٠ Gbps). لا يعبر الإنترنت. مناسب للحمولات الحرجة والسرّيّة والبيانات الكبيرة.

Physical connection to AWS. Takes ≥ 1 month to set up. Stable performance (1-100 Gbps). Never traverses the Internet. For critical, sensitive, or high-volume workloads.

نصيحة للامتحان:Exam tip: DX بحدّ ذاته ليس مشفّراً. إن احتجت تشفيراً، شغّل VPN فوق DX (يُعرَف بـ "VPN over DX"). الامتحان يختبر هذه النقطة في أسئلة الامتثال. DX itself is not encrypted. If you need encryption, run VPN over DX ("VPN over DX"). The exam tests this in compliance scenarios.

الملخّص وأهمّ النقاط Summary & Key Takeaways

VPC = شبكة خاصّة Region-scope VPC = Region-scope private network

Subnets ترتبط بـ AZ واحدة. public = route لـ IGW، private = بدون.

Subnets tie to one AZ. Public = IGW route, private = no route.

SG stateful، NACL stateless SG stateful, NACL stateless

SG على الـ ENI بـ Allow فقط. NACL على الـ subnet بـ Allow + Deny.

SG on ENI, Allow only. NACL on subnet, Allow + Deny.

VPC Endpoints = وصول خاصّ لـ AWS VPC Endpoints = private AWS access

Gateway مجّانيّ لـ S3 و DynamoDB. Interface لمعظم الخدمات.

Gateway (free) for S3 and DynamoDB. Interface for most services.

VPN vs DX VPN vs DX

VPN سريع + إنترنت. DX فيزيائيّ + شهر + لا تشفير افتراضيّ.

VPN fast + Internet. DX physical + 1mo + no default encryption.

SG vs NACL: "SG = Single resource (ENI), Stateful, Sole Allow". "NACL = Net-wide (subnet), Non-stateful, Allow and Deny".

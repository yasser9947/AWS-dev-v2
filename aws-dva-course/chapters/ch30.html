تعرّف على الكلمات التي تحدّد الإجابة الصحيحة. AWS يضع هذه القيود عمداً لتمييز من يعرف الفروق الدقيقة.

Learn the keywords that pin down the correct answer. AWS intentionally adds these constraints to separate those who grasp the nuances.

جداول مقارنة سريعة Quick comparison tables

Secrets Manager vs Parameter StoreSecrets Manager vs Parameter Store

Secrets Manager: تدوير تلقائيّ، أغلى (~$0.40/secret/شهر). Parameter Store: أرخص، SecureString مشفّر بـ KMS، بدون تدوير مدمج. امتحان: "تدوير تلقائيّ" = Secrets Manager.

Secrets Manager: auto-rotation, pricier (~$0.40/secret/mo). Parameter Store: cheaper, SecureString encrypted via KMS, no built-in rotation. Exam: "auto-rotation" = Secrets Manager.

Kinesis vs SQS vs SNSKinesis vs SQS vs SNS

Kinesis: بثّ مرتّب، عدّة قرّاء، احتفاظ حتى عام. SQS: طوابير نقطة لنقطة، رسالة واحدة لمعالج واحد. SNS: pub/sub، نسخ لكلّ مشترك.

Kinesis: ordered stream, multiple readers, up to 1-year retention. SQS: point-to-point queue, one message one consumer. SNS: pub/sub, copies to every subscriber.

Blue/Green vs CanaryBlue/Green vs Canary

Blue/Green: بيئتان كاملتان، تبديل مفاجئ بـ DNS أو ALB (CodeDeploy AllAtOnce). Canary: نسبة مئويّة صغيرة تزداد تدريجياً (Linear/Canary في CodeDeploy). Canary يقلّل المخاطر أكثر.

Blue/Green: two full envs, instant switch via DNS or ALB (CodeDeploy AllAtOnce). Canary: small % ramps up gradually (Linear/Canary in CodeDeploy). Canary reduces risk further.

DynamoDB vs RDS vs AuroraDynamoDB vs RDS vs Aurora

DynamoDB: NoSQL, key-value, serverless, ms-latency عالميّاً. RDS: SQL تقليديّ، ترقيم يدويّ للسعة. Aurora: SQL متوافق MySQL/Postgres، ٥× أسرع، Serverless v2، تكامل أعمق مع AWS.

DynamoDB: NoSQL, key-value, serverless, ms-latency globally. RDS: classic SQL, manual capacity. Aurora: MySQL/Postgres-compat, 5× faster, Serverless v2, deeper AWS integration.

Lambda vs Fargate vs EC2Lambda vs Fargate vs EC2

Lambda: ١٥ دقيقة حدّ، ٩ أنواع runtime، أحداث فوريّة. Fargate: حاويات بدون خوادم. EC2: تحكّم كامل وتكلفة متغيّرة. للأحمال قصيرة وغير المتوقّعة → Lambda.

Lambda: 15-min max, 9 runtimes, event-driven. Fargate: serverless containers. EC2: full control. Short unpredictable workloads → Lambda.

ElastiCache vs DAXElastiCache vs DAX

ElastiCache: Redis/Memcached عامّ للتطبيق. DAX: كاش متخصّص لـ DynamoDB فقط، mikrosecond لـ read. امتحان: "كاش لـ DynamoDB" = DAX.

ElastiCache: general Redis/Memcached for apps. DAX: DynamoDB-only cache, microsecond reads. Exam: "cache for DynamoDB" = DAX.

مفهوم أساسي:Key concept: خرائط ذهنيّة سريعة: بثّ سجلّ فوريّ = Subscription Filter + Kinesis/Lambda. بثّ سجلّ إلى S3 = Kinesis Firehose. تخزين طويل مع SQL = S3 + Athena. مقياس RAM على EC2 = Unified Agent. منع نسخ متعدّدة من حدث في Lambda = SQS FIFO أو idempotency في الكود. Mental shortcuts: real-time log stream = Subscription Filter + Kinesis/Lambda. log to S3 = Kinesis Firehose. long-term + SQL = S3 + Athena. EC2 RAM metric = Unified Agent. avoid duplicate Lambda invocations = SQS FIFO or in-code idempotency.

استراتيجيّة يوم الامتحان Exam-day strategy

الامتحان: ٦٥ سؤالاً في ١٣٠ دقيقة (≈ دقيقتان للسؤال). ١٥ سؤال غير مرجّح (تجريبيّ). تحتاج ٧٢٠/١٠٠٠ للنجاح. يمكن re-take بعد ١٤ يوماً من الفشل. الرسوم ١٥٠ دولار.

Exam: 65 questions in 130 minutes (≈ 2 min/question). 15 are unscored (pilot). Need 720/1000 to pass. Re-take after 14 days if failed. Fee $150.

Flag & SkipFlag & Skip

كلّ سؤال لا تجيب عنه بثقة خلال دقيقتين → flag وانتقل. ارجع إليها آخراً.

Any question you can't confidently answer in 2 min → flag and move on. Revisit last.

إلغاء الخياراتEliminate

استبعد خيارات خاطئة بوضوح أولاً. عادة خياران من الأربعة يبعدان عن صلب السؤال.

Rule out clearly wrong options first. Typically 2/4 options are off-topic.

لا تُفرط في التفكيرDon't overthink

لو الحلّ ممكن لكن معقّد جداً، غالباً خاطئ. AWS يفضّل الحلّ الأنيق.

If a solution is feasible but very complex, likely wrong. AWS favors elegant answers.

راقب الوقتWatch the clock

بعد ٦٥ دقيقة يجب أن تكون في السؤال ~٣٣. لو أبطأ، سرّع بالـ flag & skip.

By 65 min you should be ~question 33. If slower, accelerate via flag & skip.

نصيحة:Tip: يوم الامتحان: نم جيداً الليلة السابقة، اشرب ماءً كافياً، وصل قبل ٣٠ دقيقة. إن كان online: تحقّق من الكاميرا والمنضدة خالية. لا تسمح AWS بأيّ ورقة أو قلم — كلّ ما تحتاجه يُؤخَذ ذهنياً. Exam day: sleep well the night before, hydrate, arrive 30 min early. If online: check camera and a clear desk. AWS allows no paper or pen — everything must be mental.

للحفظ السريع: Mnemonic:

قبل الضغط على "Submit" في أيّ سؤال، اطرح على نفسك ٣ أسئلة: (١) هل فهمت القيد (cost / ops / time / security)؟ (٢) هل استبعدت الخيارات الخاطئة بوضوح؟ (٣) هل الحلّ بسيط أم معقّد بلا داعٍ؟ إذا كان معقّداً جداً، غالباً فخّ. مع السلامة في امتحانك!

Before hitting "Submit" on any question, ask yourself 3 things: (1) Did I grasp the constraint (cost / ops / time / security)? (2) Did I rule out the obviously wrong options? (3) Is this solution simple or needlessly complex? If it's overly complex, it's usually a trap. Good luck on your exam!

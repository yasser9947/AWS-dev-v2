لماذا CloudFormation Why CloudFormation

CloudFormation تعريفيّة (declarative) لبنية AWS التحتية: تكتب في قالب YAML أنّك تريد Security Group و خادمين EC2 و Load Balancer، فتقوم CloudFormation بإنشائها بالترتيب الصحيح وبالإعدادات المطلوبة تماماً.

CloudFormation is a declarative way to define AWS infrastructure: write a YAML template saying you need a Security Group, two EC2 instances, and a Load Balancer, and CloudFormation creates them in the right order with the exact config.

Infrastructure as CodeInfrastructure as code

كل الموارد بالكود — قابلة للمراجعة في Git، قابلة للنسخ، وغير معرّضة لأخطاء الإعداد اليدوي.

All resources in code — version-controlled, reproducible, free from manual drift.

إعادة الإنشاء المتكرّرةEphemeral environments

يمكنك حذف Dev كل ليلة وإعادة إنشائه صباحاً — توفير تكلفة ممتاز.

Tear down dev nightly and recreate it in the morning — excellent cost savings.

تنظيم بـ StacksStack separation

VPC stack منفصل عن Application stack. يسمح لفرق مختلفة بإدارة طبقاتها.

Separate VPC stack from app stack. Different teams own their layers.

تتبّع التكلفةCost tracking

كل مورد يُوسَم تلقائياً بمُعرّف Stack، فتعرف كم تكلفتك بالضبط.

Every resource auto-tagged with stack ID, so you know exactly what each stack costs.

مفهوم أساسي:Key concept: الـ Resources هو القسم الوحيد الإلزاميّ في القالب. كلّ الأقسام الأخرى (Parameters، Outputs، Mappings، Conditions، Metadata) اختياريّة. Resources is the only mandatory section. Everything else (Parameters, Outputs, Mappings, Conditions, Metadata) is optional.

أقسام القالب وأمثلة Template sections & examples

قالب CloudFormation يتكوّن من عدّة أقسام، لكلٍّ منها غرض محدّد. يجب أن تتقن الفرق بين Parameters (مدخلات يُحدّدها المستخدم) و Mappings (قيم ثابتة متعدّدة حسب المنطقة/البيئة) و Outputs (قيم مُصدَّرة لـ Stacks أخرى).

A CloudFormation template has multiple sections, each with a specific purpose. Master the distinction between Parameters (user-provided inputs), Mappings (static lookups by region/env), and Outputs (values exported to other stacks).

القسمSectionالاستخدامPurposeمطلوب؟Required?
AWSTemplateFormatVersionإصدار القالب، دائماً 2010-09-09Template version, always 2010-09-09لاNo
Descriptionوصف نصّيّ للقالبText descriptionلاNo
Parametersمدخلات ديناميكيّة (String، Number، AllowedValues، NoEcho للأسرار)Dynamic inputs (String, Number, AllowedValues, NoEcho for secrets)لاNo
Mappingsقيم ثابتة (مثل AMI لكل منطقة)، يُقرَأ بـ FindInMapStatic lookup (e.g. AMI per region), accessed via FindInMapلاNo
Conditionsتحكّم في إنشاء مورد (prod vs dev)، يُستخدَم مع IfControl resource creation (prod vs dev), used with IfلاNo
Resourcesالموارد الفعليّة (EC2، S3، RDS، ...)The actual resources (EC2, S3, RDS, ...)نعمYes
Outputsقيم تُصدَّر، يمكن استيرادها في Stacks أخرى بـ ImportValueExported values, importable in other stacks via ImportValueلاNo
 
AWSTemplateFormatVersion: '2010-09-09'
Description: Acme web server with SG and Elastic IP

Parameters:
  InstanceType:
    Type: String
    Default: t3.micro
    AllowedValues: [t3.micro, t3.small, t3.medium]
    Description: EC2 instance class
  DBPassword:
    Type: String
    NoEcho: true           # hidden in Console & events
    MinLength: 8

Mappings:
  RegionMap:
    us-east-1:
      HVM64: ami-0abcd1234
    eu-west-1:
      HVM64: ami-0fedc5678

Conditions:
  IsProd: !Equals [!Ref Environment, prod]

Resources:
  WebServerSG:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: HTTP + SSH
      SecurityGroupIngress:
        - IpProtocol: tcp
          FromPort: 80
          ToPort: 80
          CidrIp: 0.0.0.0/0

  WebServer:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !Ref InstanceType
      ImageId: !FindInMap [RegionMap, !Ref 'AWS::Region', HVM64]
      SecurityGroupIds: [!Ref WebServerSG]

Outputs:
  WebServerPublicIp:
    Description: Public IP of the web server
    Value: !GetAtt WebServer.PublicIp
    Export:
      Name: AcmeWebServerIP

الـ Intrinsic Functions (لا بدّ من حفظها) Intrinsic functions (must know)

هذه الدّوال هي ما يجعل القالب ديناميكياً. الامتحان يركّز كثيراً على Ref و GetAtt و Sub و FindInMap و ImportValue.

These functions make templates dynamic. Exam heavily tests Ref, GetAtt, Sub, FindInMap, and ImportValue.

الدّالةFunctionماذا تُرجِعReturnsمثالExample
!RefParameter: قيمته. Resource: المُعرّف الفيزيائيّ (EC2 ID، Bucket Name).Parameter: value. Resource: physical ID (EC2 ID, bucket name).!Ref MyVPC
!GetAttصفة من مورد (مثل PublicIp، Arn، AvailabilityZone).Attribute of a resource (PublicIp, Arn, AvailabilityZone).!GetAtt EC2.PublicIp
!Subاستبدال متغيّرات في سلسلة نصيّة (أشبه بـ template literal).Variable substitution in a string (template literal).!Sub 'arn:aws:s3:::${Bucket}/*'
!Joinدمج قائمة بقيم بواصل.Join list with separator.!Join ['-', [acme, !Ref Env]]
!FindInMapقراءة قيمة من Mappings بمفتاحين.Read from Mappings with two keys.!FindInMap [Map, K1, K2]
!ImportValueاستيراد قيمة مُصدَّرة من Stack آخر (Cross-Stack).Import a value exported from another stack (cross-stack).!ImportValue SharedVPCId
!If / !Equalsتنفيذ شرطيّ (Conditions).Conditional (Conditions).!If [IsProd, m5.large, t3.micro]
!Base64ترميز سلسلة إلى Base64 (لـ UserData).Base64-encode string (for UserData).!Base64 '#!/bin/bash\nyum ...'
 
# Cross-Stack: shared VPC exported from network stack
# In network stack:
Outputs:
  VpcId:
    Value: !Ref MyVPC
    Export:
      Name: AcmeSharedVPC

# In application stack (separate file):
Resources:
  AppInstance:
    Type: AWS::EC2::Instance
    Properties:
      SubnetId: !ImportValue AcmeSharedVPC
      # Sub for interpolation
      Tags:
        - Key: Name
          Value: !Sub '${AWS::StackName}-app-${Environment}'

DeletionPolicy، Rollback، و DependsOn DeletionPolicy, Rollback & DependsOn

هذه السمات تتحكّم بالسّلوك عند الحذف أو الفشل. DeletionPolicy قد تمنع فقدان بيانات قواعد البيانات عند حذف الـ Stack. افتراضياً كل المورد يُحذَف.

These attributes control behavior on delete or failure. DeletionPolicy can prevent database data loss on stack delete. Default is that every resource gets deleted.

DeletionPolicy: RetainDeletionPolicy: Retain

يحفظ المورد حتى بعد حذف الـ Stack. مناسب لـ RDS و S3 و DynamoDB في الإنتاج.

Keeps the resource even after stack delete. Ideal for RDS, S3, DynamoDB in production.

DeletionPolicy: SnapshotDeletionPolicy: Snapshot

أخذ Snapshot نهائية قبل الحذف. مدعوم لـ EBS، RDS، ElastiCache، Redshift.

Take a final snapshot before delete. Supported for EBS, RDS, ElastiCache, Redshift.

Resources:
  ProdDatabase:
    Type: AWS::RDS::DBInstance
    DeletionPolicy: Snapshot       # snapshot on stack delete
    UpdateReplacePolicy: Snapshot  # snapshot if resource replaced during update
    Properties:
      DBInstanceClass: db.t3.small
      Engine: mysql
      AllocatedStorage: 20
      MasterUsername: admin
      MasterUserPassword: !Ref DBPassword

  DataBucket:
    Type: AWS::S3::Bucket
    DeletionPolicy: Retain         # keep bucket on stack delete

  AppInstance:
    Type: AWS::EC2::Instance
    DependsOn: ProdDatabase        # wait for DB before creating instance
    Properties:
      InstanceType: t3.micro
نصيحة للامتحان:Exam tip: عند فشل إنشاء Stack: افتراضياً يحذف CloudFormation كل الموارد المُنشأة (Rollback). عند فشل تحديث: يُعاد تلقائياً للحالة الصالحة السابقة. إذا فشل الـ Rollback نفسه، يبقى الـ Stack في UPDATE_ROLLBACK_FAILED وتحتاج ContinueUpdateRollback. On create failure: CloudFormation deletes all created resources (rollback). On update failure: auto-reverts to the last working state. If rollback itself fails, stack is stuck in UPDATE_ROLLBACK_FAILED and you need ContinueUpdateRollback.
فخّ شائع:Common pitfall: DeletionPolicy: Delete على S3 Bucket يفشل لو الـ Bucket غير فارغ. استخدم Custom Resource + Lambda لتفريغه قبل الحذف، أو فعّل AWS::S3::Bucket مع Lambda لإفراغه. DeletionPolicy: Delete on an S3 bucket fails if it isn't empty. Use a custom resource + Lambda to empty it first, or a Lambda-backed cleanup.

ChangeSets، Drift، StackSets ChangeSets, Drift, StackSets

هذه المفاهيم متقدّمة لكنّها شائعة في الامتحان. ChangeSets معاينة للتغييرات قبل تطبيقها، Drift Detection كشف التعديلات اليدويّة خارج CloudFormation، و StackSets للنشر على حسابات ومناطق متعدّدة.

Advanced but commonly tested. ChangeSets preview updates before applying, drift detection finds manual changes outside CloudFormation, and StackSets deploy to multiple accounts and regions.

ChangeSetsChangeSets

قبل أن تطبّق تحديث، CloudFormation يعرض لك ما سيحدث: أيّ مورد سيُعدَّل، يُستبدَل، يُحذَف. تراجَع ثم اعتَمِد.

Before applying an update, CloudFormation shows you what will happen: which resources are modified, replaced, or deleted. Review, then execute.

Drift DetectionDrift Detection

يكشف ما إذا عدّل أحدٌ المورد يدوياً في الـ Console. كلّ Modified أو Deleted هو انحراف.

Detects whether someone manually edited a resource in the Console. Any Modified or Deleted = drift.

StackSetsStackSets

نشر نفس القالب عبر عدّة حسابات و عدّة مناطق بعمليّة واحدة. مثاليّ للشركات الكبيرة مع AWS Organizations.

Deploy the same template across multiple accounts and regions in one operation. Ideal for large orgs with AWS Organizations.

Nested StacksNested Stacks

Stack داخل Stack. إعادة استخدام Stack جاهز (مثل Load Balancer) في قوالب متعدّدة.

A stack inside a stack. Reuse a ready stack (like a Load Balancer) in multiple templates.

# Preview changes with a ChangeSet
aws cloudformation create-change-set \
  --stack-name acme-prod \
  --change-set-name upgrade-to-v2 \
  --template-body file://template.yaml

# Review the change set
aws cloudformation describe-change-set \
  --change-set-name upgrade-to-v2 --stack-name acme-prod

# Execute if it looks good
aws cloudformation execute-change-set \
  --change-set-name upgrade-to-v2 --stack-name acme-prod

# Detect drift on existing stack
aws cloudformation detect-stack-drift --stack-name acme-prod
للمطوّر السينيور:For the senior dev: CloudFormation Service Role يسمح لـ CloudFormation بإنشاء موارد حتى لو لم يكن للمستخدم الصلاحيات المباشرة (مبدأ أقل امتياز). على المستخدم أن يكون لديه iam:PassRole. إذا القالب يُنشِئ موارد IAM، تحتاج CAPABILITY_IAM أو CAPABILITY_NAMED_IAM؛ وللـ Nested Stacks أو Macros CAPABILITY_AUTO_EXPAND. CloudFormation Service Role lets CloudFormation create resources even if the user lacks direct permissions (least privilege). User must have iam:PassRole. If the template creates IAM resources, you need CAPABILITY_IAM or CAPABILITY_NAMED_IAM; for nested stacks or macros, CAPABILITY_AUTO_EXPAND.

معمل عملي Hands-on Lab

الهدف: نشر Stack بسيط فيه EC2 Instance + Security Group، ثم كشف Drift يدويّ.

Goal: Deploy a simple Stack with EC2 + Security Group, then detect a manually introduced drift.

  1. ١

    احفظ القالب في ملفّ YAML Save the template YAML

    يحتوي على Parameter لنوع الخادم و Resource واحد لـ EC2 Instance.

    Contains a parameter for instance type and a single EC2 Instance resource.

    AWSTemplateFormatVersion: '2010-09-09'
Parameters:
  InstanceType:
    Type: String
    Default: t3.micro
Resources:
  DemoSG:
    Type: AWS::EC2::SecurityGroup
    Properties:
      GroupDescription: demo
      SecurityGroupIngress:
        - IpProtocol: tcp
          FromPort: 22
          ToPort: 22
          CidrIp: 0.0.0.0/0
  Demo:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !Ref InstanceType
      ImageId: ami-0abcdef1234567890
      SecurityGroupIds: [!Ref DemoSG]
  2. ٢

    أطلق الـ Stack عبر CLI Deploy via CLI 

    aws cloudformation create-stack \
  --stack-name ch21-demo \
  --template-body file://demo.yaml \
  --parameters ParameterKey=InstanceType,ParameterValue=t3.micro
  3. ٣

    أحدِث انحرافاً يدوياً Introduce manual drift

    من الـ Console، عدّل Security Group وأضف قاعدة port 80 جديدة.

    In Console, edit the Security Group and add a port 80 rule.

  4. ٤

    اكشف الانحراف Detect drift 

    aws cloudformation detect-stack-drift --stack-name ch21-demo
aws cloudformation describe-stack-resource-drifts \
  --stack-name ch21-demo
  5. ٥

    احذف الـ Stack Delete the Stack

    كلّ الموارد تُحذَف (ما عدا ذات DeletionPolicy: Retain).

    All resources deleted (except any with DeletionPolicy: Retain).

    aws cloudformation delete-stack --stack-name ch21-demo
تنبيه: Warning: إذا تركت EC2 بدون حذف، يستمرّ الفوترة. دائماً امسح الـ Stack بعد التجربة. If you leave EC2 running, billing continues. Always delete the stack after testing.

الملخّص وأهمّ النقاط Summary & Key Takeaways

Resources فقط إلزامي Only Resources is mandatory

باقي الأقسام (Parameters، Mappings، Outputs، Conditions) اختياريّة.

All other sections (Parameters, Mappings, Outputs, Conditions) are optional.

احفظ ٥ دوالّ أساسيّة Memorize 5 core functions

Ref، GetAtt، Sub، FindInMap، ImportValue — هذه هي الأكثر في الامتحان.

Ref, GetAtt, Sub, FindInMap, ImportValue — most tested.

DeletionPolicy يُنقذ البيانات DeletionPolicy saves data

Retain للإبقاء، Snapshot للّقطة النهائيّة. خاصّةً لـ RDS و EBS.

Retain keeps; Snapshot takes a final snapshot. Especially for RDS, EBS.

StackSets للنشر متعدّد الحسابات StackSets = multi-account deploy

قالب واحد، عدّة حسابات، عدّة مناطق. مثاليّ مع AWS Organizations.

One template, many accounts, many regions. Ideal with AWS Organizations.

PMROCD: Parameters → Mappings → Resources → Outputs → Conditions → DeletionPolicy. للأقسام فكّر: مدخلات، جداول، موارد، مخرجات، شروط، حماية.

PMROCD: Parameters → Mappings → Resources → Outputs → Conditions → DeletionPolicy. Inputs, lookups, resources, exports, conditions, protection.

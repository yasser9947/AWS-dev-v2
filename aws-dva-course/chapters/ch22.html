ما هو SAM ولماذا نستخدمه What is SAM and why

AWS SAM (Serverless Application Model) إطار عمل مفتوح المصدر لبناء ونشر تطبيقات Serverless. الفكرة: كتابة قالب YAML مختصر جداً، يتحوّل تلقائياً إلى CloudFormation كامل. يُقلّل من ١٠٠ سطر إلى ١٥ سطراً لتعريف Lambda + API Gateway + DynamoDB.

AWS SAM (Serverless Application Model) is an open-source framework for building serverless apps. The idea: write a very short YAML template that auto-transforms into full CloudFormation. It compresses 100 lines to 15 for a Lambda + API Gateway + DynamoDB definition.

مفهوم أساسي:Key concept: Transform Header يجب أن يظهر أوّل سطر لتحديد أنّ القالب SAM وليس CloudFormation عاديّ: Transform: 'AWS::Serverless-2016-10-31'. The Transform header must appear to mark the template as SAM (not plain CloudFormation): Transform: 'AWS::Serverless-2016-10-31'.

قالب SAM نموذجيّ A typical SAM template

هذا مثال كامل لتطبيق Serverless مع Lambda و API Gateway و DynamoDB. لاحظ الاختصارات: Events يُنشئ API Gateway تلقائياً، Policies يُولّد IAM Role مناسباً.

A complete serverless app with Lambda, API Gateway, and DynamoDB. Note the shortcuts: Events auto-creates API Gateway; Policies generates an appropriate IAM role.

AWSTemplateFormatVersion: '2010-09-09'
Transform: 'AWS::Serverless-2016-10-31'
Description: Acme serverless orders service

Globals:
  Function:
    Runtime: java17
    MemorySize: 512
    Timeout: 10
    Environment:
      Variables:
        TABLE_NAME: !Ref OrdersTable

Resources:
  OrdersTable:
    Type: AWS::Serverless::SimpleTable
    Properties:
      PrimaryKey:
        Name: orderId
        Type: String

  GetOrderFn:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: target/orders-1.0.jar
      Handler: com.acme.orders.GetOrder::handleRequest
      Policies:
        - DynamoDBReadPolicy:
            TableName: !Ref OrdersTable
      Events:
        ApiEvent:
          Type: Api
          Properties:
            Path: /orders/{id}
            Method: GET

Outputs:
  ApiUrl:
    Value: !Sub 'https://${ServerlessRestApi}.execute-api.${AWS::Region}.amazonaws.com/Prod'
مفهوم أساسي:Key concept: Policy Templates مثل DynamoDBReadPolicy، S3ReadPolicy، SQSPollerPolicy، DynamoDBCrudPolicy تُولّد IAM Policies جاهزة بأقل امتياز. Policy Templates like DynamoDBReadPolicy, S3ReadPolicy, SQSPollerPolicy, DynamoDBCrudPolicy generate least-privilege IAM policies.

دورة النشر: build، deploy، sync Deployment lifecycle: build, deploy, sync

دورة النشر النموذجيّة تتكوّن من sam build (يُجهّز الاعتماديّات في .aws-sam/)، ثم sam deploy (يرفع إلى S3 وينشئ ChangeSet). الـ sam sync يسرّع التطوير بتحديث كود Lambda فقط (تجاوز CloudFormation).

Typical cycle: sam build (prepares dependencies in .aws-sam/), then sam deploy (uploads to S3 and creates a ChangeSet). sam sync speeds dev by updating only Lambda code (bypasses CloudFormation).

# First-time setup
sam init                         # scaffold new project
sam validate                     # lint template.yaml

# Build & Deploy
sam build                        # compile + package deps
sam deploy --guided              # interactive first deploy (saves to samconfig.toml)
sam deploy                       # subsequent deploys

# SAM Accelerate — iterate fast (bypasses CFN for code-only changes)
sam sync --watch                 # auto-redeploy on file change
sam sync --code                  # code only, no infra update
sam sync --code --resource-id GetOrderFn  # single function

# Local testing
sam local invoke GetOrderFn -e event.json
sam local start-api              # local API Gateway on :3000
sam local start-lambda           # local Lambda endpoint
sam local generate-event s3 put  # generate sample events

sam deploysam deploy

يمرّ عبر CloudFormation الكامل. بطيء (دقائق) لكنّه آمن وعاكس للبنية التحتية.

Full CloudFormation path. Slower (minutes) but safe and infra-aware.

sam sync --codesam sync --code

يتجاوز CloudFormation، يحدّث كود Lambda مباشرةً عبر APIs. ثوانٍ — مثاليّ للتطوير السريع، ليس للإنتاج.

Bypasses CloudFormation, updates Lambda code directly via service APIs. Seconds — ideal for rapid dev, not for prod.

النشر التدريجيّ مع CodeDeploy Gradual deployment with CodeDeploy

SAM يدمج CodeDeploy لنشر Lambda بالتدريج: AutoPublishAlias يُنشِئ Alias جديد عند كل نشر، و DeploymentPreference يحدّد نمط تحويل الترافيك.

SAM integrates CodeDeploy for gradual Lambda deployment: AutoPublishAlias creates a new alias on each deploy, and DeploymentPreference sets the traffic-shift pattern.

النمطPatternالوصفDescriptionالاستخدامUse case
Canary10Percent5Minutes١٠٪ ترافيك فوراً، الباقي بعد ٥ دقائق10% traffic immediately, rest after 5 minإنتاج حسّاس، تحقّق سريع من الأخطاءCritical prod, quick error detection
Canary10Percent30Minutes١٠٪ ترافيك فوراً، الباقي بعد ٣٠ دقيقة10% traffic immediately, rest after 30 minتحقّق أعمق من مقاييس CloudWatchDeeper CloudWatch metric validation
Linear10PercentEvery1Minuteزيادة ١٠٪ كل دقيقة حتى ١٠٠٪Grow 10% every minute until 100%نشر تدريجيّ منتظمSmooth progressive rollout
Linear10PercentEvery10Minutesزيادة ١٠٪ كل ١٠ دقائقGrow 10% every 10 minللإنتاج الأبطأ المراقَبFor slower, watched production
AllAtOnce١٠٠٪ ترافيك فوراً100% immediatelyDev أو عند الثقة العاليةDev or high-confidence updates
 
Resources:
  MyLambda:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: s3://bucket/code.zip
      Handler: index.handler
      Runtime: nodejs20.x
      AutoPublishAlias: live      # publishes new version + shifts alias
      DeploymentPreference:
        Type: Canary10Percent10Minutes
        Alarms:
          # auto-rollback if any alarm fires
          - !Ref LambdaErrorsAlarm
          - !Ref AliasLatencyAlarm
        Hooks:
          PreTraffic:  !Ref PreTrafficValidationFn
          PostTraffic: !Ref PostTrafficSmokeTestFn
نصيحة للامتحان:Exam tip: الـ Alarms تُطلِق Rollback تلقائياً. الـ Hooks هي Lambda validation functions تعمل قبل/بعد تحويل الترافيك — مفيدة لـ smoke tests. Rollback هنا يعود إلى الإصدار السابق بتغيير Alias، لا بإعادة نشر. Alarms trigger automatic rollback. Hooks are Lambda validation functions running pre/post traffic shift — ideal for smoke tests. Rollback here just points the alias back to the old version, not a redeploy.

معمل عملي Hands-on Lab

الهدف: إنشاء ونشر دالّة Lambda + API Gateway عبر SAM، ثم اختبارها محلياً قبل الرفع.

Goal: Create and deploy a Lambda + API Gateway via SAM, test locally before pushing.

  1. ١

    ثبّت SAM CLI Install SAM CLI 

    # macOS
brew tap aws/tap
brew install aws-sam-cli
sam --version
  2. ٢

    أنشئ مشروعاً جديداً Scaffold a new project

    يسألك عن النموذج (Hello World Java 17 Maven مثلاً).

    Asks you for a template (e.g. Hello World Java 17 Maven).

    sam init \
  --runtime java17 \
  --package-type Zip \
  --app-template hello-world-maven \
  --name acme-orders
  3. ٣

    بني واختبر محلياً Build and test locally 

    cd acme-orders
sam build
sam local invoke HelloWorldFunction -e events/event.json
sam local start-api   # http://localhost:3000/hello
  4. ٤

    انشر إلى AWS Deploy to AWS 

    sam deploy --guided
# Stack name: acme-orders-dev
# Region: us-east-1
# Confirm changes: Y
# Allow SAM CLI IAM creation: Y
# Save arguments to samconfig.toml: Y
  5. ٥

    تطوير سريع بـ sam sync Rapid dev with sam sync 

    sam sync --watch
# Modify Java code → auto-redeployed in seconds
  6. ٦

    تنظيف Cleanup 

    sam delete --stack-name acme-orders-dev
تنبيه: Warning: Lambda + API Gateway بعد Free Tier تكلفتهما منخفضة جداً لكن تذكّر الحذف بعد التجربة، خاصّةً إذا وضعت CloudWatch Alarms (تكلفة إضافيّة). Lambda + API Gateway cost very little after Free Tier, but delete after testing — especially if you added CloudWatch Alarms (extra cost).

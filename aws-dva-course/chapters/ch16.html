Cognito: نظرتان متكاملتان Cognito: two complementary services

Amazon Cognito تجمع خدمتين منفصلتين لإدارة هوية المستخدمين في السحابة. الفرق بينهما أهمّ سؤال في هذا الفصل، ويرتبك فيه كثيرون:

Amazon Cognito bundles two distinct services for cloud identity. Their difference is this chapter's most important exam question, and the one most learners confuse:

Cognito User PoolCognito User Pool

إدارة مستخدمين (sign-up, sign-in, reset password، MFA). يُصدر JWT tokens (ID, Access, Refresh). يُستخدم في API Gateway authorizer و ALB authentication. يربط بـ Facebook/Google/SAML لتسجيل الدخول.

User directory (sign-up, sign-in, reset, MFA). Issues JWT tokens (ID, Access, Refresh). Used in API Gateway authorizer & ALB auth. Federates with Facebook/Google/SAML for sign-in.

Cognito Identity PoolCognito Identity Pool

يمنح وصولاً لـ AWS: يأخذ token (من User Pool أو Google/Facebook أو Anonymous) ويُبادله بـ temporary AWS credentials عبر STS. يسمح للتطبيق المتحرّك بالوصول مباشرة لـ S3/DynamoDB.

Grants AWS access: takes a token (from User Pool / Google / Facebook / Anonymous) and exchanges for temporary AWS credentials via STS. Lets mobile apps hit S3/DynamoDB directly.

مفهوم أساسي:Key concept: طريقة مبسّطة للتذكّر: User Pool = WHO (من أنت؟)، Identity Pool = WHAT (ماذا تستطيع أن تفعل في AWS؟). قد تستخدم أحدهما فقط أو الاثنين معاً. الخلط بينهما الفخّ الأكبر في الامتحان. Easy mnemonic: User Pool = WHO (who are you?), Identity Pool = WHAT (what can you do in AWS?). Use one, the other, or both. Confusing them is the biggest exam trap.

Cognito User Pool — إدارة المستخدمين Cognito User Pool — user management

User Pool هو user directory serverless (قاعدة بيانات مستخدمين مُدارة). يوفّر كل ما يحتاجه التطبيق لإدارة حسابات المستخدمين.

User Pool is a serverless user directory (managed user database). Delivers everything an app needs for account management.

التسجيل وتسجيل الدخولSign up & Sign in

بريد/هاتف/username. تحقّق من البريد/هاتف عبر OTP. سياسات كلمة مرور (طول، رموز، أرقام). Forgot password flow.

Email/phone/username. Email/SMS verification (OTP). Password policies (length, symbols, numbers). Forgot password flow.

MFAMFA

TOTP (Google Authenticator) أو SMS. Adaptive authentication (تحليل محاولات مشبوهة).

TOTP (Google Authenticator) or SMS. Adaptive authentication (risk-based).

Federated IdentityFederated Identity

اربط User Pool بـ Google, Facebook, Apple, SAML, OpenID Connect (Okta). المستخدم يسجّل بحسابه الخارجي فتنشئ Cognito حساب داخلي.

Link User Pool to Google, Facebook, Apple, SAML, OIDC (Okta). User signs in with external account; Cognito mirrors a local account.

Lambda TriggersLambda Triggers

Lambda هوكات على أحداث المستخدم: PreSignUp, PostConfirmation, PreAuthentication, PostAuthentication، DefineAuthChallenge (للـ custom auth).

Lambda hooks on user events: PreSignUp, PostConfirmation, PreAuthentication, PostAuthentication, DefineAuthChallenge (custom auth).

Cognito + API Gateway — نمط حماية APIs Cognito + API Gateway — API protection pattern

التكامل الأكثر شيوعاً: API Gateway Cognito User Pool Authorizer. العميل يسجّل الدخول في User Pool ويأخذ ID token (أو Access token). يرسله في Authorization header مع كل طلب. API Gateway يتحقّق من التوقيع والانتهاء تلقائياً — بدون كود إضافي.

Most common integration: API Gateway Cognito User Pool Authorizer. Client signs in at User Pool, receives an ID (or Access) token, and sends it in the Authorization header on each request. API Gateway auto-validates signature & expiry — no custom code.

// Java SDK v2 — sign in to Cognito User Pool, get tokens
import software.amazon.awssdk.services.cognitoidentityprovider.*;
import software.amazon.awssdk.services.cognitoidentityprovider.model.*;

CognitoIdentityProviderClient cognito = CognitoIdentityProviderClient.create();

AdminInitiateAuthResponse auth = cognito.adminInitiateAuth(b -> b
    .userPoolId("us-east-1_ABC")
    .clientId("abc123")
    .authFlow(AuthFlowType.ADMIN_USER_PASSWORD_AUTH)
    .authParameters(Map.of(
        "USERNAME", "yasser@acme.com",
        "PASSWORD", "************")));

AuthenticationResultType tokens = auth.authenticationResult();
String idToken      = tokens.idToken();       // for identity
String accessToken  = tokens.accessToken();   // for API calls
String refreshToken = tokens.refreshToken();  // for renewal

// Call protected API with the token
HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://abc.execute-api.us-east-1.amazonaws.com/prod/orders"))
    .header("Authorization", idToken)
    .GET().build();
نصيحة للامتحان:Exam tip: في API Gateway، بعد تفعيل Cognito Authorizer، اختر Token Source (عادة Authorization header) و OAuth Scopes (اختياري — لتقييد الـ scopes التي يسمح لها بالوصول). يمكن استخراج claims من الـ token وتمريرها لـ Lambda عبر $context.authorizer.claims. In API Gateway, after enabling the Cognito Authorizer, pick Token Source (usually Authorization header) and OAuth Scopes (optional — to restrict allowed scopes). You can extract claims and pass them to Lambda via $context.authorizer.claims.

OAuth 2.0 Flows المدعومة: Authorization Code (الأكثر أماناً — SPA/server apps)، Client Credentials (machine-to-machine، بدون مستخدم)، Implicit (مُستنكَر لمصلحة Authorization Code with PKCE). المسار الافتراضي للـ mobile و SPA اليوم: Authorization Code + PKCE.

Supported OAuth 2.0 flows: Authorization Code (safest — SPA/server apps), Client Credentials (machine-to-machine, no user), Implicit (deprecated in favor of Authorization Code with PKCE). Default for mobile/SPA today: Authorization Code + PKCE.

Cognito Identity Pool — تمرير وصول AWS Cognito Identity Pool — granting AWS access

Identity Pool (يُسمّى أيضاً Federated Identities) يحلّ مشكلة: "كيف أعطي تطبيق iOS وصولاً مباشراً لـ S3 bucket دون تضمين access keys؟". الإجابة: التطبيق يسجّل الدخول (في أيّ مكان — Cognito User Pool أو Google أو Facebook) ويستبدل الـ token بـ temporary AWS credentials عبر STS.

Identity Pool (also called Federated Identities) solves: "How do I give an iOS app direct S3 access without embedding access keys?". Answer: the app signs in (anywhere — Cognito User Pool, Google, Facebook) and swaps the token for temporary AWS credentials via STS.

Identity Pool يحدّد IAM Roles (authenticated / unauthenticated). بناءً على provider الدخول، تنال الـ session credentials ومعها صلاحيات IAM Role المرفق. يدعم Fine-Grained Access عبر policy variables مثل ${cognito-identity.amazonaws.com:sub} — كل مستخدم يصل لمجلده فقط في S3.

Identity Pool defines IAM Roles (authenticated / unauthenticated). Based on sign-in provider, you get session credentials with the attached Role's permissions. Supports fine-grained access via policy variables like ${cognito-identity.amazonaws.com:sub} — each user accesses only their folder in S3.

// Identity Pool Role Policy — user accesses ONLY their own S3 folder
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject","s3:PutObject"],
    "Resource": "arn:aws:s3:::acme-uploads/${cognito-identity.amazonaws.com:sub}/*"
  }]
}
للمطوّر السينيور:For the senior dev: نمط السينيور: في تطبيقات mobile/SPA تحتاج رفع ملفات إلى S3 مباشرةً (لتقليل تكلفة Lambda/API Gateway)، استخدم User Pool + Identity Pool: المستخدم يسجّل الدخول في User Pool، يستلم tokens، يُمرّرها لـ Identity Pool ليحصل على AWS credentials تسمح بـ s3:PutObject على مجلّده الخاص فقط. هذا النمط المعتمد للأمان. Senior pattern: for mobile/SPA uploading files directly to S3 (skip Lambda/API Gateway cost), use User Pool + Identity Pool: user signs in at User Pool, gets tokens, swaps them at Identity Pool for AWS credentials allowing s3:PutObject only on their own prefix. Canonical secure pattern.

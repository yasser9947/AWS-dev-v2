AWS KMS وأنواع المفاتيح AWS KMS & key types

KMS (Key Management Service) خدمة إدارة مفاتيح التشفير مُدمجة مع أغلب خدمات AWS (S3, EBS, RDS, Secrets Manager...). المفاتيح فيها كانت تُسمّى Customer Master Keys (CMK)، وأُعيدت تسميتها إلى KMS Keys. لا تُصدِّر المفتاح الأساسيّ أبداً — تستدعي KMS API لكلّ عمليّة تشفير/فكّ.

KMS (Key Management Service) manages encryption keys and is integrated with most AWS services (S3, EBS, RDS, Secrets Manager...). Keys were called Customer Master Keys (CMK), renamed to KMS Keys. The master key never leaves KMS — you call the KMS API for every encrypt/decrypt.

مفتاح واحد يشفّر ويفكّ. معظم خدمات AWS تستخدمه. لا ينكشف لك أبداً — تستدعي KMS API.

Public/private pair. Public is downloadable for encryption outside AWS. Private stays inside KMS. Also for digital signing.

مفهوم أساسي:Key concept: للامتحان: KMS خدمة إقليميّة (Region-bound) — مفتاح في us-east-1 لا يعمل في eu-west-1. لنقل بيانات مشفّرة بين المناطق، استخدم ReEncrypt بمفتاح الوجهة. Exam: KMS is region-bound — a key in us-east-1 doesn't work in eu-west-1. To move encrypted data across regions use ReEncrypt with the destination key.

Envelope Encryption ولماذا نحتاجها Envelope Encryption & why we need it

KMS Encrypt API محدود بـ ٤ كيلوبايت. لتشفير ملفات أكبر نستخدم Envelope Encryption: KMS يُنشئ Data Encryption Key (DEK) ويُعيد نسختين: Plaintext لاستخدامها محلّياً، ومشفّرة لحفظها بجانب الملف.

The KMS Encrypt API is limited to 4 KB. To encrypt larger files use Envelope Encryption: KMS generates a Data Encryption Key (DEK) and returns two copies: plaintext (for local use) and encrypted (stored alongside the file).

١. GenerateDataKey1. GenerateDataKey

KMS يولّد DEK يعطيك plaintext + encrypted-under-CMK.

KMS produces a DEK: plaintext + encrypted-under-CMK.

٢. شفّر محلّياً2. Encrypt locally

تستخدم الـ DEK plaintext لتشفير الملف (AES-256).

Use the plaintext DEK to encrypt the file locally (AES-256).

٣. امحِ الـ plaintext واحفظ الباقي3. Wipe plaintext & store

احذف الـ DEK plaintext من الذاكرة، احفظ: الملف المشفّر + DEK مشفّرة.

Delete the plaintext DEK from memory; store: encrypted file + encrypted DEK.

// Java SDK v2 — Envelope Encryption for a large file
import software.amazon.awssdk.services.kms.KmsClient;
import software.amazon.awssdk.services.kms.model.*;
import javax.crypto.Cipher;
import javax.crypto.spec.SecretKeySpec;

KmsClient kms = KmsClient.create();

// 1. Ask KMS for a DEK
GenerateDataKeyResponse dk = kms.generateDataKey(GenerateDataKeyRequest.builder()
    .keyId("alias/acme-data")
    .keySpec(DataKeySpec.AES_256)
    .build());

byte[] plaintextDek = dk.plaintext().asByteArray();
byte[] encryptedDek = dk.ciphertextBlob().asByteArray(); // store alongside

// 2. Encrypt the file locally with the plaintext DEK
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(plaintextDek, "AES"));
byte[] ciphertext = cipher.doFinal(largeFileBytes);

// 3. Wipe the plaintext DEK from memory
java.util.Arrays.fill(plaintextDek, (byte) 0);

// To decrypt later: call kms.decrypt(encryptedDek) → plaintext DEK → decrypt file.
للمطوّر السينيور:For the senior dev: الـ AWS Encryption SDK (متوفرة لـ Java/Python/C/JS) تُنفّذ Envelope Encryption تلقائياً وتدعم Data Key Caching لتقليل طلبات KMS. استخدمها بدلاً من كتابة الكود يدويّاً. The AWS Encryption SDK (Java/Python/C/JS) implements Envelope Encryption automatically and supports Data Key Caching to reduce KMS calls. Use it instead of DIY code.

Key Policies والوصول عبر الحسابات Key Policies & cross-account access

بخلاف S3 و IAM، KMS Key Policies إلزاميّة. بدون Key Policy صحيحة لا يستطيع حتى الحساب الجذر استخدام المفتاح. الـ Default Policy تمنح Root الحساب كلّ الصلاحيّات، ومن هناك IAM يمنح المستخدمين.

Unlike S3 or IAM, KMS Key Policies are mandatory. Without a valid Key Policy even Root can't use the key. The default policy grants Root full access, then IAM delegates to users.

// Cross-account Key Policy — allow Account B to use the key
{
  "Version": "2012-10-17",
  "Id": "key-policy-cross-account",
  "Statement": [
    {
      "Sid": "EnableRootAccess",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::111122223333:root" },
      "Action": "kms:*",
      "Resource": "*"
    },
    {
      "Sid": "AllowCrossAccountUse",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::222233334444:role/CrossAcctReader" },
      "Action": [
        "kms:Decrypt",
        "kms:DescribeKey"
      ],
      "Resource": "*"
    }
  ]
}

Grants آلية أخفّ من Key Policy: تفويض مؤقّت وصلاحيّات محدّدة (مثلاً خدمة AWS تريد تشفير EBS Snapshot نيابة عنك). الـ Grants لا تحتاج تعديل Key Policy — أكثر مرونة.

Grants are a lighter mechanism than Key Policy: short-term delegation with limited permissions (e.g., an AWS service needs to encrypt an EBS snapshot on your behalf). Grants don't require Key Policy edits — more flexible.

تدوير المفاتيح (Key Rotation) Key rotation

التدوير يستبدل مادّة المفتاح داخل KMS دون تغيير الـ Key ID أو ARN. البيانات القديمة تبقى قابلة لفكّ التشفير بالمفتاح القديم (KMS يحتفظ بجميع الإصدارات).

Rotation replaces the key material inside KMS without changing the Key ID or ARN. Old data stays decryptable with the old version (KMS keeps all versions).

AWS ManagedAWS Managed

تلقائي كلّ سنة. لا خيار لك.

Automatic every 1 year. No opt-out.

Customer ManagedCustomer Managed

اختياريّ. تلقائي كلّ ٣٦٥ يوم، أو on-demand (زر في Console).

Optional. Automatic every 365 days, or on-demand (Console button).

ImportedImported

لا تدوير تلقائيّ. يدويّ فقط عبر alias يشير لـ Key جديد.

No automatic rotation. Manual only via alias pointing to a new key.

نصيحة للامتحان:Exam tip: التدوير التلقائي لا يُعيد تشفير البيانات الحاليّة. لتطبيق المفتاح الجديد على بيانات قديمة، يجب فكّها ثمّ إعادة تشفيرها (ReEncrypt). هذا ممارسة أمان دوريّة في الأنظمة ذات الحساسيّة العالية. Automatic rotation does not re-encrypt existing data. To apply the new key to old data, decrypt and ReEncrypt. High-security systems schedule this periodically.

AWS Secrets Manager AWS Secrets Manager

Secrets Manager لتخزين الأسرار (كلمات مرور قواعد البيانات، مفاتيح API، شهادات). مُشفّر تلقائياً بـ KMS، يدعم التدوير التلقائي عبر Lambda، ومدمج مع RDS, Redshift, DocumentDB لتغيير كلمة مرور الـ DB بدون توقّف.

Secrets Manager stores secrets (DB passwords, API keys, certificates). Auto-encrypted with KMS, supports auto-rotation via Lambda, and integrates with RDS/Redshift/DocumentDB for zero-downtime DB password changes.

// Java SDK v2 — read a secret from Secrets Manager
import software.amazon.awssdk.services.secretsmanager.SecretsManagerClient;
import software.amazon.awssdk.services.secretsmanager.model.*;

SecretsManagerClient sm = SecretsManagerClient.create();

GetSecretValueResponse secret = sm.getSecretValue(GetSecretValueRequest.builder()
    .secretId("prod/acme/db-credentials")
    .build());

String secretString = secret.secretString();
// Parse JSON: {"username":"admin","password":"..."}

// IMPORTANT: Cache this in-process; don't call SecretsManager on every DB connection.
// Use the AWS Secrets Manager client-side caching library for Lambda.
مفهوم أساسي:Key concept: للمطوّر: لا تستدعي GetSecretValue في كلّ طلب. كل استدعاء يُكلّف $0.05 / 10K calls، ومع Lambda تتضاعف التكلفة. استخدم مكتبة secretsmanager-caching الرسميّة. Dev tip: don't call GetSecretValue on every request. Each call costs $0.05 / 10K, and Lambda explodes costs. Use the official secretsmanager-caching library.

التدوير التلقائي: تُعدّ دالة Lambda تُنفّذ دورة: createSecret → setSecret → testSecret → finishSecret. AWS يوفّر قوالب جاهزة لـ RDS MySQL/PostgreSQL/Aurora.

Auto-rotation: you configure a Lambda running: createSecret → setSecret → testSecret → finishSecret. AWS provides pre-built templates for RDS MySQL/PostgreSQL/Aurora.

SSM Parameter Store و مقارنة بـ Secrets Manager SSM Parameter Store vs Secrets Manager

SSM Parameter Store بديل أرخص بكثير لتخزين الإعدادات والأسرار. يدعم ٣ أنواع: String، StringList، وSecureString (مشفّر بـ KMS). منظّم هرمياً بالـ /.

SSM Parameter Store is a far cheaper alternative for configs and secrets. Three types: String, StringList, SecureString (KMS-encrypted). Organized hierarchically by /.

# Store a SecureString parameter
aws ssm put-parameter \
  --name /acme/prod/db-password \
  --value 'SuperSecret!' \
  --type SecureString \
  --key-id alias/acme-ssm

# Retrieve it (auto-decrypt with IAM kms:Decrypt on the key)
aws ssm get-parameter \
  --name /acme/prod/db-password \
  --with-decryption

# Retrieve a whole hierarchy
aws ssm get-parameters-by-path \
  --path /acme/prod/ \
  --recursive \
  --with-decryption
للمطوّر السينيور:For the senior dev: قاعدة الاختيار: Secrets Manager للأسرار التي تحتاج تدويراً تلقائياً (DB passwords). Parameter Store للإعدادات وللأسرار التي تُدوَّر يدوياً أو التي التكلفة مهمّة فيها. يمكنك قراءة Secrets Manager secret عبر Parameter Store API باستخدام المسار /aws/reference/secretsmanager/<name>. Pick rule: Secrets Manager for secrets needing auto-rotation (DB passwords). Parameter Store for configs and manually-rotated/cost-sensitive secrets. You can read a Secrets Manager secret through the Parameter Store API via /aws/reference/secretsmanager/<name>.

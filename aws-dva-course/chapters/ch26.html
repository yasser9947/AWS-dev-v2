نظرة عامّة على AWS CI/CD AWS CI/CD overview

أتمتة الدورة من الـ Commit إلى الإنتاج تسمح بـ Deployment متكرّر وآمن. AWS تقدّم خدمات مدمجة لكل مرحلة: CodeCommit للتخزين، CodeBuild للبناء، CodeDeploy للنشر، CodePipeline لتنسيق الكل.

Automating commit-to-prod enables frequent, safe deployments. AWS provides integrated services for each stage: CodeCommit for storage, CodeBuild for building, CodeDeploy for deploying, CodePipeline to orchestrate.

CodeCommitCodeCommit

Git مستضاف، خاص، مدعوم بـ KMS. IAM للصلاحيات، SSH/HTTPS للوصول. بديل GitHub/GitLab.

Managed Git, private, KMS-encrypted. IAM permissions, SSH/HTTPS access. Alternative to GitHub/GitLab.

CodeBuildCodeBuild

خدمة CI مُدارة. تُشغّل buildspec.yml في Docker. فوترة بالدقيقة. بديل Jenkins.

Managed CI service. Runs buildspec.yml in Docker. Per-minute billing. Jenkins alternative.

CodeDeployCodeDeploy

نشر إلى EC2 / On-prem / Lambda / ECS. Hooks لتخصيص كل مرحلة. Rollback تلقائيّ.

Deploy to EC2 / on-prem / Lambda / ECS. Hooks customize each phase. Auto-rollback.

CodePipelineCodePipeline

ينسّق كل المراحل (Source → Build → Test → Deploy). يمكن دمجه مع GitHub، Jenkins، أدوات خارجيّة.

Orchestrates all stages (Source → Build → Test → Deploy). Integrates with GitHub, Jenkins, 3rd-party tools.

مفهوم أساسي:Key concept: CodeArtifact لتخزين حزم البرمجة (Maven، npm، pip، NuGet). CodeGuru (ML) لمراجعة الكود آلياً. CodeStar عرض مُوحَّد لكل ما سبق. CodeArtifact stores software packages (Maven, npm, pip, NuGet). CodeGuru (ML) automates code review. CodeStar is a unified view of all the above.

buildspec.yml — قلب CodeBuild buildspec.yml — the heart of CodeBuild

الملف buildspec.yml يقع في جذر مستودع الكود. يُخبر CodeBuild بكيفيّة البناء. الأقسام الأساسيّة: env (متغيّرات)، phases (الخطوات)، artifacts (المخرجات)، cache (للتسريع).

buildspec.yml lives at the code root. Tells CodeBuild how to build. Key sections: env (variables), phases (steps), artifacts (outputs), cache (for speed).

المرحلةPhaseالغرضPurpose
installتثبيت الـ runtime أو الحزم (apt/yum install...)Install runtime or packages (apt/yum install...)
pre_buildخطوات قبل البناء (Docker login إلى ECR، تحميل deps)Before build (Docker login to ECR, deps download)
buildأمر البناء الفعليّ (mvn clean package، npm run build)The actual build command (mvn clean package, npm run build)
post_buildاللمسات الأخيرة (Docker push، تغليف ZIP، نشر تقارير)Finishing touches (Docker push, zip packaging, publish reports)
 
version: 0.2

env:
  variables:
    JAVA_HOME: /usr/lib/jvm/java-17-amazon-corretto
  parameter-store:                  # from SSM Parameter Store
    DOCKERHUB_TOKEN: /acme/dockerhub/token
  secrets-manager:                  # from Secrets Manager
    DB_PASSWORD: prod/db-creds:password

phases:
  install:
    runtime-versions:
      java: corretto17
    commands:
      - echo "Installing extras..."
      - apt-get install -y jq
  pre_build:
    commands:
      - echo "Logging into ECR..."
      - aws ecr get-login-password | docker login --username AWS --password-stdin 123456789012.dkr.ecr.us-east-1.amazonaws.com
  build:
    commands:
      - mvn clean package -DskipTests=false
      - docker build -t acme-api:${CODEBUILD_RESOLVED_SOURCE_VERSION} .
  post_build:
    commands:
      - docker tag  acme-api:${CODEBUILD_RESOLVED_SOURCE_VERSION} \
                    123456789012.dkr.ecr.us-east-1.amazonaws.com/acme-api:latest
      - docker push 123456789012.dkr.ecr.us-east-1.amazonaws.com/acme-api:latest

reports:
  junit-reports:
    files: ['target/surefire-reports/*.xml']
    file-format: JUNITXML

artifacts:
  files:
    - target/acme-*.jar
    - appspec.yml
    - scripts/**/*

cache:
  paths:
    - '/root/.m2/**/*'              # cache Maven dependencies
نصيحة للامتحان:Exam tip: الـ cache قسم مهمّ: تخزين .m2/ (Maven) أو node_modules/ (npm) في S3 يُقلّل وقت البناء من ٥ دقائق إلى ٣٠ ثانية. The cache section matters: storing .m2/ (Maven) or node_modules/ (npm) in S3 cuts build time from 5 minutes to 30 seconds.
فخّ شائع:Common pitfall: الخطأ الشائع: CodeBuild يبني ولكن الـ Artifacts لا تصل إلى S3. السبب: قسم artifacts: مفقود أو يُحدّد ملفّات غير موجودة. تحقّق من مسارات الإخراج في files:. Common error: CodeBuild succeeds but artifacts don't reach S3. Cause: missing artifacts: section or wrong paths. Check files: entries.

CodeDeploy — Configurations و Strategies CodeDeploy — configurations and strategies

CodeDeploy ينشر إلى ٤ منصّات: EC2/On-prem، Lambda، ECS. لكل منصّة استراتيجيّات مختلفة.

CodeDeploy deploys to 4 platforms: EC2/on-prem, Lambda, ECS. Each platform has its own strategies.

المنصّةPlatformConfigurations المتاحةAvailable configurationsالأسلوبStyle
EC2 / On-premEC2 / On-premAllAtOnce, HalfAtATime, OneAtATime, CustomIn-place أو Blue/GreenIn-place or Blue/Green
LambdaLambdaCanary (10%5/10%30), Linear (10%/1min, 10%/10min), AllAtOnceTraffic shift بـ AliasTraffic shift via alias
ECSECSCanary, Linear, AllAtOnceBlue/Green فقط (عبر ALB + Target Groups)Blue/Green only (via ALB + Target Groups)

EC2: In-placeEC2: In-place

يُحدَّث الكود على Instances القائمة. يتطلّب CodeDeploy Agent على EC2.

Code updates on existing instances. Requires CodeDeploy Agent on EC2.

EC2: Blue/GreenEC2: Blue/Green

ينشئ ASG جديد بـ V2، يحوّل ترافيك ALB، ثمّ يهدم القديم.

Spawns a new ASG with V2, shifts ALB traffic, then tears down the old.

Lambda: Traffic shiftLambda: Traffic shift

يغيّر Alias لتحويل Traffic إلى Version جديدة. Canary سريع، Linear تدريجيّ.

Changes alias to shift traffic to a new version. Canary = fast, Linear = gradual.

ECS: Blue/Green (ALB)ECS: Blue/Green (ALB)

ALB مع Target Group لكل لون. CodeDeploy يُحوّل الترافيك تدريجياً.

ALB with one Target Group per color. CodeDeploy shifts traffic gradually.

appspec.yml — لماذا يختلف حسب المنصّة appspec.yml — why it differs by platform

الملف appspec.yml يُوجِّه CodeDeploy. صيغته تختلف بين EC2 و Lambda. الـ Hooks هي نقاط تحكّم بين مراحل النشر.

appspec.yml drives CodeDeploy. Its schema differs between EC2 and Lambda. Hooks are control points between deploy phases.

appspec.yml لـ EC2appspec.yml for EC2

أقسام: files (ما يُنسَخ)، hooks (scripts)، Hooks: ApplicationStop → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService.

Sections: files (what to copy), hooks (scripts). Hooks: ApplicationStop → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService.

appspec.yml لـ Lambdaappspec.yml for Lambda

Resources يحدّد Function و Alias و Versions. Hooks: BeforeAllowTraffic → AfterAllowTraffic (اثنان فقط).

Resources specifies Function, alias, versions. Hooks: BeforeAllowTraffic → AfterAllowTraffic (just two).

# EC2 appspec.yml
version: 0.0
os: linux
files:
  - source: /
    destination: /var/www/html
hooks:
  ApplicationStop:
    - location: scripts/stop_server.sh
      timeout: 60
      runas: root
  BeforeInstall:
    - location: scripts/install_deps.sh
  AfterInstall:
    - location: scripts/change_permissions.sh
  ApplicationStart:
    - location: scripts/start_server.sh
  ValidateService:
    - location: scripts/smoke_test.sh
      timeout: 30
# Lambda appspec.yml
version: 0.0
Resources:
  - myFunction:
      Type: AWS::Lambda::Function
      Properties:
        Name: acme-api
        Alias: live
        CurrentVersion: "3"
        TargetVersion:  "4"
Hooks:
  - BeforeAllowTraffic: PreTrafficValidationFn    # run before shift
  - AfterAllowTraffic:  SmokeTestFn               # run after shift
مفهوم أساسي:Key concept: ترتيب hooks الـ EC2 مهمّ في الامتحان: ApplicationStop → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService. الـ ValidateService يمكنه إلغاء النشر لو فشل. EC2 hooks order matters on the exam: ApplicationStop → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService. ValidateService can abort a deploy on failure.

CodePipeline، CodeArtifact، و Troubleshooting CodePipeline, CodeArtifact & troubleshooting

CodePipeline ينسّق كل ما سبق. يتكوّن من Stages (Source، Build، Test، Deploy، Invoke)، كل Stage به Actions متوازية أو متسلسلة. الـ Artifacts تُخزَّن في S3 وتنتقل بين Stages.

CodePipeline orchestrates everything. Made of Stages (Source, Build, Test, Deploy, Invoke), each with parallel or sequential Actions. Artifacts are stored in S3 and flow between stages.

// Simplified CodePipeline stages
{
  "stages": [
    { "name": "Source",
      "actions": [{ "actionTypeId": "Source", "provider": "CodeCommit", ... }] },
    { "name": "Build",
      "actions": [{ "actionTypeId": "Build", "provider": "CodeBuild", ... }] },
    { "name": "Approval",
      "actions": [{ "actionTypeId": "Approval", "provider": "Manual", ... }] },
    { "name": "Deploy",
      "actions": [
        { "actionTypeId": "Deploy", "provider": "CodeDeploy", ... },
        { "actionTypeId": "Deploy", "provider": "CloudFormation", ... }
      ]
    }
  ]
}

CodeArtifactCodeArtifact

مستودع حزم (Maven، npm، pip، NuGet). يتكامل مع CodeBuild و IDE. يمكن أن يعمل كـ Proxy لـ Maven Central.

Package repository (Maven, npm, pip, NuGet). Integrates with CodeBuild and IDEs. Can proxy Maven Central.

CodeGuruCodeGuru

Reviewer (مراجعة كود آلية) و Profiler (تحليل أداء Runtime). يدعم Java و Python.

Reviewer (automated code review) + Profiler (runtime performance). Supports Java and Python.

CodeStarCodeStar

منصّة مُوحّدة لإدارة Projects (Source + Build + Deploy + Issues + Monitoring) من dashboard واحد.

Unified project console (Source + Build + Deploy + Issues + Monitoring) in one dashboard.

TroubleshootingTroubleshooting

EventBridge للإشعارات عند فشل Stage. CloudTrail للـ Audit. IAM Service Role صحيح ضروريّ.

EventBridge for stage-failure notifications. CloudTrail for audit. Correct IAM service role is essential.

فخّ شائع:Common pitfall: فشل شائع: CodePipeline can't perform action. السبب الأوّل دائماً: الـ IAM Service Role المُرتَبط بالـ Pipeline ناقصه أذونات (مثل codebuild:StartBuild أو s3:PutObject). Common failure: CodePipeline can't perform action. #1 cause: the IAM service role attached to the pipeline is missing permissions (like codebuild:StartBuild or s3:PutObject).
للمطوّر السينيور:For the senior dev: معمارية CI/CD نموذجيّة لـ Spring Boot: CodeCommit (Git) → CodeBuild (mvn + Docker build + Push ECR) → CodeDeploy ECS (Blue/Green عبر ALB). مع Manual Approval قبل Prod و Rollback تلقائيّ بـ CloudWatch Alarms. A canonical Spring Boot CI/CD: CodeCommit (Git) → CodeBuild (mvn + Docker build + ECR push) → CodeDeploy ECS (Blue/Green via ALB). With manual approval before prod and CloudWatch-alarm-triggered rollback.

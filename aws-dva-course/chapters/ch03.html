تخزين خوادم EC2: EBS و EFS و Instance Store EC2 Instance Storage: EBS, EFS, Instance Store

ثلاث طبقات تخزين لكلّ منها شخصيّة مختلفة: أقراص شبكيّة مُستمرّة (EBS)، ونظام ملفّات مشترك (EFS)، وأقراص فيزيائيّة سريعة لكنّها مؤقّتة (Instance Store). فهم الفروق بينها شرط للامتحان ولأيّ قرار معماريّ جدّيّ. Three storage tiers, each with a distinct personality: persistent network-attached block (EBS), shared multi-instance file (EFS), and ultra-fast ephemeral local (Instance Store). Knowing their trade-offs is essential for the exam and for any serious architectural call.

ما هو EBS؟ القرص الشبكيّ المُستمرّ What is EBS? The persistent network drive

EBS (Elastic Block Store) هو قرص تخزين كتليّ (block) يُرفَق بخادم EC2 عبر الشبكة. تعامل معه كأنّه USB شبكيّ: يمكن فصله من خادم وإعادة ربطه بخادم آخر بسرعة، ويبقى محتواه سليماً حتى لو حُذف الخادم.

EBS (Elastic Block Store) is a block storage volume attached to an EC2 instance over the network. Think of it as a network USB stick: detachable from one instance, quickly attachable to another, and the data persists even after the instance is terminated.

شبكيّ لا فيزيائيّNetwork, not physical

يُتَّصل به عبر شبكة AWS الداخليّة، ولذا هناك زمن استجابة بسيط مقارنةً بالأقراص المحلّية.

Attached over AWS's internal network, so slightly higher latency than local disks.

مقيّد بـ AZ واحدةLocked to one AZ

قرص في us-east-1a لا يمكن ربطه بخادم في us-east-1b. للنقل تحتاج Snapshot.

A volume in us-east-1a cannot attach to an instance in us-east-1b. Migrate via snapshot.

خادم واحد افتراضياًOne instance by default

على مستوى CCP: قرص واحد لخادم واحد. الاستثناء هو Multi-Attach لفئة io1/io2.

At CCP level: one volume to one instance. Exception: Multi-Attach for io1/io2.

مُستمرّ بعد حذف الخادمPersists after termination

البيانات تبقى إلّا إذا فُعِّلت Delete on Termination (مُفعَّلة افتراضياً للـ root).

Data survives unless Delete on Termination is enabled (default for root).

نصيحة للامتحان:Exam tip: سلوك Delete on Termination: مُفعَّل افتراضياً على الـ root volume، ومُعطَّل للأقراص الإضافيّة. يسأل الامتحان عن هذا في سياق حفظ البيانات عند حذف الخادم بالخطأ. Delete on Termination behavior: enabled by default for the root volume, disabled for additional EBS volumes. Exam tests this in data-preservation scenarios.

أنواع أقراص EBS واختيار المناسب EBS volume types and choosing the right one

EBS يأتي بـ٦ أنواع مقسَّمة إلى عائلتين: SSD لأحمال الأداء، و HDD لأحمال النقل الضخم. أسئلة الامتحان تدور دائماً حول اختيار النوع الأمثل بناءً على الحِمل.

EBS comes in 6 types split across two families: SSD for performance workloads, HDD for high-throughput bulk workloads. Exam questions revolve around picking the right type for the workload.

gp3 vs gp2 — متى تختار أيّاً؟gp3 vs gp2 — which one?

gp3: الأداء منفصل عن الحجم. ابدأ بـ ٣٠٠٠ IOPS دون الحاجة لقرص كبير، وارفع IOPS و throughput باستقلالية. أرخص من gp2 بحوالي ٢٠٪ لنفس الأداء. gp2: الأداء مربوط بالحجم (٣ IOPS/GiB). للوصول لـ ١٦٠٠٠ IOPS تحتاج ٥٣٣٤ GiB.

gp3: perf decoupled from size. Start at 3000 IOPS without oversizing the disk; scale IOPS and throughput independently. ~20% cheaper than gp2 for same performance. gp2: perf tied to size (3 IOPS/GiB). To hit 16000 IOPS you need a 5334 GiB disk.

io1/io2 — أحمال الإنتاج الحرجةio1/io2 — critical production

خصّص الـ IOPS بشكل ثابت (Provisioned). io2 Block Express هو الأحدث والأسرع — يصل لـ ٢٥٦٠٠٠ IOPS بزمن استجابة أقلّ من ميلّي ثانية. استخدم io1/io2 لقواعد بيانات الإنتاج الحسّاسة. فقط هذه العائلة تدعم Multi-Attach.

Statically provisioned IOPS. io2 Block Express is newest/fastest — up to 256000 IOPS with sub-ms latency. Use io1/io2 for sensitive prod databases. Only this family supports Multi-Attach.

Snapshots و AMIs Snapshots and AMIs

EBS Snapshot هو نسخة احتياطيّة نقطة-زمنيّة (point-in-time) للقرص تُخزَّن في S3 (بشكل مخفيّ). وحدها الطريقة لنقل قرص EBS بين AZs أو Regions. AMI يتضمّن Snapshot للقرص بالإضافة إلى إعدادات الخادم (نوع، صلاحيات، ...).

An EBS Snapshot is a point-in-time backup stored in S3 (under the hood). It's the only way to move an EBS volume across AZs or Regions. An AMI wraps a snapshot plus instance config (type, permissions, etc.).

EBS Snapshot ArchiveEBS Snapshot Archive

تنقل Snapshot إلى طبقة أرخص بنسبة ٧٥٪، لكنّ الاستعادة تأخذ ٢٤-٧٢ ساعة.

Moves a snapshot to an archive tier 75% cheaper, but restore takes 24-72 hours.

Recycle BinRecycle Bin

يحفظ Snapshots المحذوفة لفترة تحدّدها (من يوم إلى سنة) لاستعادتها عند الحذف الخاطئ.

Retains deleted snapshots for a configurable window (1 day - 1 year) for accidental-deletion recovery.

Fast Snapshot RestoreFast Snapshot Restore (FSR)

تهيئة مسبقة كاملة للـ Snapshot لتفادي زمن استجابة أوّل قراءة — مكلّف.

Pre-initializes a snapshot to avoid first-read latency — expensive.

// Java SDK v2 — create a snapshot, then launch an AMI from it
import software.amazon.awssdk.services.ec2.Ec2Client;
import software.amazon.awssdk.services.ec2.model.*;

Ec2Client ec2 = Ec2Client.create();

// 1. Snapshot an EBS volume
CreateSnapshotResponse snap = ec2.createSnapshot(CreateSnapshotRequest.builder()
    .volumeId("vol-0abc1234")
    .description("Acme prod DB nightly backup")
    .tagSpecifications(TagSpecification.builder()
        .resourceType(ResourceType.SNAPSHOT)
        .tags(Tag.builder().key("env").value("prod").build())
        .build())
    .build());

String snapshotId = snap.snapshotId();
System.out.println("Snapshot: " + snapshotId);

// 2. Copy the snapshot to another region (DR)
ec2.copySnapshot(CopySnapshotRequest.builder()
    .sourceRegion("us-east-1")
    .sourceSnapshotId(snapshotId)
    .destinationRegion("eu-west-1")
    .description("DR copy for Acme")
    .build());
فخّ شائع:Common pitfall: AMI مرتبط بـ Region واحدة. لإطلاق خادم من نفس الـ AMI في region أخرى، انسخه عبر CopyImage. كذلك الأمر لـ Snapshots — لا يمكن استخدامها عبر regions إلّا بعد النسخ. An AMI is tied to one Region. To launch it in another region, copy it via CopyImage. Same for snapshots — cross-region requires an explicit copy.

Instance Store و EBS Multi-Attach Instance Store and EBS Multi-Attach

Instance Store قرص فيزيائيّ متّصل مباشرةً بالخادم. أداءه مذهل (ملايين IOPS للـ i3.metal) لأنّه لا يعبر الشبكة. لكنّه مؤقّت (ephemeral): البيانات تُمسَح عند إيقاف الخادم أو عند فشل الجهاز الفيزيائيّ. استخدامه مقصور على تخزين مؤقّت و scratch و cache.

Instance Store is a physical disk directly attached to the host. Performance is phenomenal (millions of IOPS on i3.metal) because it bypasses the network. But it's ephemeral: data is wiped on stop or host failure. Use only for scratch, cache, buffers.

Instance Store — الأداء المطلقInstance Store — peak performance

ملايين الـ IOPS، زمن استجابة سخيف الصغر. استخدمه لقواعد بيانات الذاكرة المؤقّتة (Redis scratch)، تحليلات Spark العابرة، caching لفك ترميز الفيديو. يجب أن يكون تطبيقك مستعدّاً لفقدان البيانات في أيّ لحظة — استنسخ أو اربطه بـ EBS/S3 للحفظ الدائم.

Millions of IOPS, absurdly low latency. Use for ephemeral DBs (Redis scratch), transient Spark analytics, video-encoding caches. App must tolerate data loss at any moment — replicate or pair with EBS/S3 for durability.

EBS Multi-Attach (io1/io2)EBS Multi-Attach (io1/io2)

يسمح بربط نفس القرص بحتى ١٦ خادم EC2 في نفس الـ AZ. القراءة والكتابة كاملة لكلّ خادم. يتطلّب نظام ملفّات cluster-aware (مثل GFS2) — لا يعمل مع XFS أو EXT4. مخصّص لتطبيقات التجميع العنقوديّ (Teradata clustered Linux).

Same volume attachable to up to 16 EC2 instances in one AZ. Full R/W per instance. Requires a cluster-aware file system (GFS2) — does NOT work with XFS or EXT4. For clustered Linux apps (Teradata).

للمطوّر السينيور:For the senior dev: لمطوّر Spring Boot: اعتبر Instance Store مثل /tmp في JVM — مساحة عمل سريعة تُمسَح مع عمر العمليّة. أيّ بيانات جلسة (session) أو نتيجة تحتاج الحفاظ عليها ضعها على EBS أو في ElastiCache/Redis خارجيّ. لا تعتمد على Instance Store لتخزين logs الإنتاج. Spring Boot analogy: treat Instance Store like the JVM's /tmp — workspace that dies with the process. Put session state or persistent results on EBS or in external ElastiCache/Redis. Never rely on Instance Store for prod logs.

Amazon EFS — نظام الملفّات المشترك Amazon EFS — the shared file system

EFS (Elastic File System) هو NFS مُدار يمكن ربطه بآلاف خوادم EC2 بشكل متزامن عبر عدّة AZs. يصلح لمحتوى مشترك (WordPress، إدارة المحتوى، مشاركة ملفّات). مُتوافق مع Linux فقط (POSIX)، ويستخدم NFSv4.1.

EFS (Elastic File System) is a managed NFS mountable to thousands of EC2 instances simultaneously across AZs. Great for shared content (WordPress, CMS, file sharing). Linux-only (POSIX), NFSv4.1.

أوضاع أداء EFS: General Purpose (افتراضي، لمواقع الويب)، و Max I/O (لأحمال متوازية ضخمة مع زمن استجابة أعلى). أوضاع الـ throughput: Bursting (افتراضي)، Provisioned (ثابت)، و Elastic (يتوسّع تلقائياً للأحمال غير المتوقّعة).

EFS performance modes: General Purpose (default, for websites), Max I/O (massively parallel with higher latency). Throughput modes: Bursting (default), Provisioned (fixed), Elastic (auto-scales for unpredictable workloads).

EFS StandardEFS Standard

للملفّات النشطة. Multi-AZ بشكل افتراضيّ.

For active files. Multi-AZ by default.

EFS IAEFS IA (Infrequent Access)

أرخص في التخزين، تكلفة عند كلّ قراءة. استخدم lifecycle policies للنقل التلقائي.

Cheaper storage, charge on retrieval. Use lifecycle policies to auto-tier.

EFS ArchiveEFS Archive

لبيانات تُقرَأ بضع مرّات في السنة — أرخص بـ٥٠٪.

For data read a few times a year — 50% cheaper.

نصيحة:Tip: لتوفير ٩٠٪+ من تكلفة EFS: فعِّل Lifecycle Policies التي تنقل الملفّات إلى IA أو Archive بعد N يوم من عدم الوصول إليها. وضع One Zone متوفّر للتطوير — Multi-AZ هو الخيار الصحيح للإنتاج. To save 90%+ on EFS cost: enable Lifecycle Policies that move files to IA or Archive after N days of no access. One Zone mode exists for dev — Multi-AZ is the right pick for production.

معمل عملي Hands-on Lab

الهدف: ربط قرص EBS إضافيّ بخادم Acme، أخذ Snapshot، ثم محاكاة فشل الخادم واستعادة البيانات من الـ Snapshot في AZ مختلفة.

Goal: Attach an extra EBS volume to an Acme instance, snapshot it, simulate instance failure, then restore from the snapshot in a different AZ.

  1. ١

    أنشئ قرص EBS وأرفقه Create and attach an EBS volume

    من الـ Console: EC2 → Volumes → Create. اختر gp3، ١٠ GiB، في نفس AZ للخادم.

    In the Console: EC2 → Volumes → Create. Choose gp3, 10 GiB, in the same AZ as the instance.

  2. ٢

    هيّئ القرص داخل الخادم Format the volume inside the instance 

    # After attaching as /dev/sdf
lsblk                          # confirm device (e.g., /dev/nvme1n1)
sudo mkfs -t xfs /dev/nvme1n1  # format
sudo mkdir /data
sudo mount /dev/nvme1n1 /data
echo 'Hello Acme' | sudo tee /data/test.txt
  3. ٣

    خذ Snapshot Take a snapshot

    Volumes → اختر القرص → Actions → Create Snapshot. أضف tag env=lab.

    Volumes → select volume → Actions → Create Snapshot. Add tag env=lab.

  4. ٤

    استعد القرص في AZ مختلفة Restore into a different AZ

    Snapshots → اختر الـ Snapshot → Actions → Create Volume from Snapshot. اختر AZ مختلفة.

    Snapshots → select → Actions → Create Volume from Snapshot. Pick a different AZ.

  5. ٥

    أرفقه بخادم جديد وتحقّق Attach to a new instance and verify 

    sudo mount /dev/nvme1n1 /data
cat /data/test.txt              # Should print 'Hello Acme'
تنبيه: Warning: احذف الأقراص و Snapshots عند انتهاء التجربة — التخزين يُحسَب بالـ GiB-شهر حتى لو لم يرتبط القرص بخادم. Delete volumes and snapshots when done — storage is billed per GiB-month even when unattached.

الملخّص وأهمّ النقاط Summary & Key Takeaways

EBS: قرص شبكيّ مُستمرّ EBS: persistent network block

مربوط بـ AZ واحدة. gp3 الخيار الافتراضيّ. io2 Block Express للأحمال الحرجة.

AZ-locked. gp3 default. io2 Block Express for critical workloads.

EFS: ملفّات مشتركة Multi-AZ EFS: Multi-AZ shared files

NFS مُدار، آلاف الخوادم Linux. غالٍ لكن Storage Tiers توفّر ٩٠٪.

Managed NFS, thousands of Linux instances. Expensive but tiers save 90%.

Instance Store: أسرع لكنّه مؤقّت Instance Store: fastest but ephemeral

للـ cache والـ scratch فقط. البيانات تُفقَد عند stop أو host failure.

For cache/scratch only. Data lost on stop or host failure.

Snapshots = نقل وDR Snapshots = migration and DR

الطريقة الوحيدة لنقل EBS بين AZs/Regions. Archive للتخزين الطويل.

Only path for cross-AZ/Region EBS migration. Archive for long-term retention.

للحفظ السريع: Mnemonic:

للتمييز بين الثلاثة: EBS = Elastic (شبكيّ ومُستمرّ، AZ واحدة). EFS = Expensive but shared (Multi-AZ، Linux). Instance Store = Impermanent (أسرع، لكن يختفي عند stop).

To tell them apart: EBS = Elastic (network, persistent, one AZ). EFS = Expensive but shared (Multi-AZ, Linux). Instance Store = Impermanent (fastest but vanishes on stop).

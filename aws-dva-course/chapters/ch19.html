طبقات التحكّم في الوصول: IAM vs Bucket Policy vs ACL Access control layers: IAM vs Bucket Policy vs ACL

S3 تقدّم عدّة آليّات للتحكّم في الوصول. الأساسيّ: IAM Policy (على الهويّة) و Bucket Policy (على المورد). الـ ACLs موروثة من ما قبل IAM وتُنصَح بتعطيلها (Object Ownership = Bucket owner enforced).

S3 offers multiple access-control mechanisms. Primary: IAM Policy (identity-based) and Bucket Policy (resource-based). ACLs predate IAM and should be disabled (Object Ownership = Bucket owner enforced).

الآليّةMechanismتُرفَق بـAttached toالاستخدامUse case
IAM Policyالمستخدم/المجموعة/الدورUser/Group/Roleوصول من نفس الحساب — الأكثر شيوعاً.Same-account access — most common.
Bucket Policyالـ Bucket نفسهThe bucket itselfCross-Account، فرض HTTPS أو التشفير، الوصول العامّ.Cross-account, forcing HTTPS or encryption, public access.
Object ACLكائن واحد (قديم)Single object (legacy)نادر — يُنصَح بتعطيل ACLs بالكامل.Rare — best to disable ACLs entirely.
Access Pointمسار داخل BucketPrefix within a bucketتقسيم صلاحيّات على أقسام (finance, sales).Slicing permissions per prefix (finance, sales).
مفهوم أساسي:Key concept: قاعدة التقييم في S3: يستطيع المستخدم الوصول إذا سمحت IAM أو Bucket Policy، وليس هناك Deny صريح. الـ Deny في أيّ طبقة يفوز دائماً. S3 evaluation rule: access granted if IAM OR Bucket Policy allows, and no explicit Deny exists. A Deny at any layer always wins.

Bucket Policies عمليّة Practical Bucket Policies

أمثلة حقيقيّة من سؤال امتحان كلاسيكيّ: فرض HTTPS، حصر IP، تشفير إلزاميّ.

Real-world examples from classic exam questions: force HTTPS, restrict IP, mandatory encryption.

// 1) Force HTTPS on every request
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyHTTP",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": [
      "arn:aws:s3:::acme-prod",
      "arn:aws:s3:::acme-prod/*"
    ],
    "Condition": {
      "Bool": { "aws:SecureTransport": "false" }
    }
  }]
}
// 2) Restrict by source IP (corporate VPN only)
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "AllowCorpOnly",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": "arn:aws:s3:::acme-prod/*",
    "Condition": {
      "NotIpAddress": {
        "aws:SourceIp": ["203.0.113.0/24", "198.51.100.0/24"]
      }
    }
  }]
}
// 3) Reject PUTs that aren't SSE-KMS encrypted
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyUnEncryptedObjectUploads",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:PutObject",
    "Resource": "arn:aws:s3:::acme-prod/*",
    "Condition": {
      "StringNotEquals": {
        "s3:x-amz-server-side-encryption": "aws:kms"
      }
    }
  }]
}
فخّ شائع:Common pitfall: عند استخدام aws:SourceIp لحصر الوصول، استثنِ حركة VPC الداخليّة عبر aws:ViaAWSService أو aws:SourceVpce، وإلّا ستكسر خدمات مثل CloudFormation و Lambda. When using aws:SourceIp to restrict, exempt internal AWS traffic via aws:ViaAWSService or aws:SourceVpce, otherwise you break CloudFormation, Lambda, etc.

أنواع تشفير S3 S3 encryption types

S3 يدعم ٤ طرق للتشفير. الفرق الجوهريّ: من يدير المفاتيح، ومن يقوم بالتشفير.

S3 supports 4 encryption methods. Key difference: who manages keys, and who encrypts.

النوعTypeمن يدير المفتاحKey ownerالتشفير يتمّ عندEncryption pointHeader إلزاميّRequired header
SSE-S3AWS (S3)AWS (S3)الخادم (افتراضيّ على كلّ الـ Buckets الجديدة)Server-side (default on new buckets)x-amz-server-side-encryption: AES256
SSE-KMSAWS KMS (CMK)AWS KMS (CMK)الخادم — مع تدقيق في CloudTrailServer-side — with CloudTrail auditx-amz-server-side-encryption: aws:kms
SSE-Cالعميل (خارج AWS)Customer (outside AWS)الخادم — يستلم المفتاح في الـ HeaderServer-side — key in headerx-amz-server-side-encryption-customer-key
Client-SideالعميلCustomerقبل الإرسال إلى S3 (Encryption SDK)Before upload (Encryption SDK)N/A
نصيحة للامتحان:Exam tip: SSE-C تتطلّب HTTPS إلزامياً لأنّ المفتاح يُرسَل في Header. S3 لا يخزّن المفتاح أبداً — إن ضاع، ضاعت البيانات. لا تستخدمه إلّا إذا كان لديك نظام KMS خارجيّ ناضج. SSE-C mandates HTTPS because the key travels in a header. S3 never stores the key — lose it, lose the data. Use only with a mature external KMS.

SSE-S3 vs SSE-KMS: متى أختار ماذا؟SSE-S3 vs SSE-KMS: which?

SSE-S3: تشفير افتراضيّ بدون تدخّل، رخيص، لا حدود طلبات. SSE-KMS: تحكّم دقيق عبر Key Policy، تدقيق في CloudTrail، لكن يستهلك حصّة KMS (٥٥٠٠-٣٠٠٠٠ طلب/ث).

SSE-S3: default encryption, cheap, no request quota. SSE-KMS: fine-grained control via Key Policy, CloudTrail audit — but consumes KMS quota (5500–30000 req/s).

S3 Bucket KeyS3 Bucket Key

ميزة تقلّل طلبات KMS بنسبة ٩٩٪ عند SSE-KMS. يُنشَأ "S3 Bucket Key" وسيط يشفّر الكائنات بمفاتيح بيانات، بدلاً من استدعاء KMS لكلّ كائن.

Feature cutting KMS calls by 99% with SSE-KMS. An intermediate "S3 Bucket Key" encrypts objects with data keys instead of calling KMS per object.

Presigned URLs و CORS Presigned URLs & CORS

Presigned URL رابط موقَّع بمفاتيحك يعطي وصولاً مؤقّتاً إلى Object في Bucket خاصّ. المستلم يستخدم الرابط دون الحاجة لحساب AWS. الصلاحيّة: من ١ دقيقة إلى ١٢ ساعة (Console) أو إلى ١٦٨ ساعة (CLI/SDK).

A Presigned URL is a URL signed with your keys giving temporary access to an object in a private bucket. The recipient uses it without an AWS account. Duration: 1 min–12h (Console) or up to 168h (CLI/SDK).

// Java SDK v2 — generate a presigned GET URL valid for 15 minutes
import software.amazon.awssdk.services.s3.presigner.S3Presigner;
import software.amazon.awssdk.services.s3.presigner.model.GetObjectPresignRequest;
import software.amazon.awssdk.services.s3.model.GetObjectRequest;
import java.time.Duration;

S3Presigner presigner = S3Presigner.create();

GetObjectPresignRequest req = GetObjectPresignRequest.builder()
    .signatureDuration(Duration.ofMinutes(15))
    .getObjectRequest(GetObjectRequest.builder()
        .bucket("acme-reports")
        .key("2026/Q1/report.pdf")
        .build())
    .build();

String url = presigner.presignGetObject(req).url().toString();
// Share `url` with the user — works for 15 minutes, no AWS login needed.
مفهوم أساسي:Key concept: المستلم يرث صلاحيّات من وقّع الرابط. إذا وقّعه دور بصلاحيّة PUT، يستطيع المستلم رفع ملف جديد عبر الرابط. استخدم أدوار بأقلّ الصلاحيّات الممكنة للتوقيع. The recipient inherits permissions of whoever signed the URL. If signed by a role with PUT, the recipient can upload via that URL. Sign with least-privileged roles.

CORS (Cross-Origin Resource Sharing) ضروريّ عندما يطلب JavaScript في متصفّح موارد من S3 على دومين مختلف. تُعرَّف في إعدادات الـ Bucket بصيغة JSON.

CORS (Cross-Origin Resource Sharing) is needed when browser JS fetches S3 resources on a different origin. Configure in bucket settings as JSON.

[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedOrigins": ["https://app.acme.com"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]

Block Public Access بطبقاته Block Public Access layers

Block Public Access (BPA) شبكة أمان تمنع التسرّب العرضيّ. تعمل بأربعة إعدادات يمكن تفعيلها على مستويَين: Bucket و Account.

Block Public Access (BPA) is a safety net against accidental leaks. Four settings, applicable at two levels: Bucket and Account.

BlockPublicAclsBlockPublicAcls

يرفض محاولات تعيين ACL عامّ على أيّ كائن.

Rejects attempts to set public ACL on any object.

IgnorePublicAclsIgnorePublicAcls

يتجاهل أيّ ACL عامّ موجود حالياً.

Ignores any existing public ACLs.

BlockPublicPolicyBlockPublicPolicy

يرفض وضع Bucket Policy تفتح الوصول للعموم.

Rejects bucket policies that grant public access.

RestrictPublicBucketsRestrictPublicBuckets

يحدّد الوصول لأيّ Bucket "عامّ" إلى الخدمات المصرّحة داخل AWS فقط.

Limits access to any "public" bucket to authorized AWS services only.

مفهوم أساسي:Key concept: على مستوى الحساب يعلو على مستوى الـ Bucket. فعّل كلّ الأربعة على الحساب كسلوك افتراضيّ، ثمّ استثنِ Buckets الـ CDN/الثابتة المطلوب أن تكون عامّة. Account-level overrides bucket-level. Enable all four at account level as default, then explicitly exempt CDN/static buckets that need public access. 
# Enable all BPA at account level
aws s3control put-public-access-block \
  --account-id 111122223333 \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

VPC Endpoints لـ S3 VPC Endpoints for S3

افتراضياً، حركة EC2 ↔ S3 تمرّ عبر الإنترنت العامّ (مع TLS). VPC Gateway Endpoint ينشئ مساراً داخل شبكة AWS لا يغادر VPC — أسرع، أرخص (لا رسوم NAT)، وأكثر أمناً (لا تعريض لـ Internet Gateway).

By default, EC2 ↔ S3 traffic traverses the public internet (with TLS). A VPC Gateway Endpoint creates a path inside the AWS network never leaving the VPC — faster, cheaper (no NAT fees), more secure (no Internet Gateway exposure).

Gateway Endpoint (S3 و DynamoDB فقط)Gateway Endpoint (S3 & DynamoDB only)

مجاني. يُضاف كمدخل في Route Table الـ VPC. عليه Endpoint Policy تعمل كسياسة موارد موازية.

Free. Added as an entry in the VPC route table. Supports an endpoint policy acting as a parallel resource policy.

Interface Endpoint (PrivateLink)Interface Endpoint (PrivateLink)

ENI داخل subnet خاصّ. مدفوع (بالساعة + GB). يدعم معظم خدمات AWS (S3 أيضاً منذ 2021).

An ENI in a private subnet. Paid (hourly + per GB). Supports most AWS services (including S3 since 2021).

// VPC Endpoint policy — restrict to one bucket + read-only
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "RestrictedAccess",
    "Effect": "Allow",
    "Principal": "*",
    "Action": ["s3:GetObject", "s3:ListBucket"],
    "Resource": [
      "arn:aws:s3:::acme-prod-reports",
      "arn:aws:s3:::acme-prod-reports/*"
    ]
  }]
}
للمطوّر السينيور:For the senior dev: لمؤسّسة ناضجة: اربط aws:SourceVpce في Bucket Policy لرفض أيّ طلب لا يمرّ عبر VPC Endpoint محدّد. هذا يمنع تسرّب البيانات من خادم EC2 مُختَرَق عبر الإنترنت. Mature orgs: bind aws:SourceVpce in Bucket Policy to reject any request not coming through a specific VPC Endpoint. Blocks data exfil from a compromised EC2 via internet.

معمل عملي Hands-on Lab

الهدف: إنشاء Bucket آمن بـ SSE-KMS، Block Public Access كامل، وفرض HTTPS، ثمّ توليد Presigned URL من Java.

Goal: Create a secure bucket with SSE-KMS, full Block Public Access, HTTPS enforcement, then generate a Java Presigned URL.

  1. ١

    أنشئ Bucket ومفتاح KMS Create bucket and KMS key 

    # Create KMS CMK
aws kms create-key --description 'S3-acme-prod'
aws kms create-alias --alias-name alias/s3-acme-prod --target-key-id <KEY_ID>

# Create bucket
aws s3api create-bucket --bucket acme-prod-reports --region us-east-1

# Enable default SSE-KMS
aws s3api put-bucket-encryption --bucket acme-prod-reports \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "aws:kms",
        "KMSMasterKeyID": "alias/s3-acme-prod"
      },
      "BucketKeyEnabled": true
    }]
  }'
  2. ٢

    فعّل Block Public Access على الـ Bucket Enable Block Public Access on the bucket 

    aws s3api put-public-access-block --bucket acme-prod-reports \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
  3. ٣

    أضف Bucket Policy تفرض HTTPS Add a Bucket Policy enforcing HTTPS 

    {
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyHTTP",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": [
      "arn:aws:s3:::acme-prod-reports",
      "arn:aws:s3:::acme-prod-reports/*"
    ],
    "Condition": { "Bool": { "aws:SecureTransport": "false" } }
  }]
}

    ارفع ملفاً تجريبياً واختبر Presigned URL من Java Upload a test file and generate Presigned URL from Java

    استخدم كود Java أعلاه. شارك الرابط وافتحه في متصفّح — يجب أن يُنزَّل الملف لمدّة ١٥ دقيقة ثمّ ينتهي.

    Use the Java snippet above. Share the URL and open in a browser — should download for 15 minutes, then expire.

  5. ٥

    (اختياريّ) أنشئ Gateway Endpoint لـ S3 (Optional) Create a Gateway Endpoint for S3

    نظّف Clean up

    احذف الكائنات ثمّ الـ Bucket. ضع الـ KMS key في جدولة حذف (٧-٣٠ يوم) — لا يمكن حذفه فوراً.

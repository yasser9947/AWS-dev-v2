ما هو Lambda ومتى يُختار What Lambda is and when to choose it

Lambda خدمة حوسبة بلا خوادم (FaaS). ترفع كود ودالة فقط، وتدفع حسب عدد الاستدعاءات ومدّة التنفيذ بالمللي ثانية. يتمدّد تلقائياً. مصمَّم للأحمال قصيرة المدى (حد أقصى ١٥ دقيقة للتنفيذ).

Lambda is serverless compute (FaaS). You upload code + a handler, pay per request and per-millisecond execution. Auto-scales. Designed for short-running work (max 15-minute execution).

EC2EC2

خادم افتراضيّ دائم. تدير OS والمكتبات. التمدّد يدويّ أو عبر Auto Scaling. تدفع طوال وقت التشغيل.

Persistent VM. You manage OS and libs. Manual or Auto Scaling. Paid while running.

LambdaLambda

دوالّ افتراضيّة. AWS تدير كل شيء. تمدّد تلقائيّ. تدفع بالاستدعاء فقط.

Virtual functions. AWS manages everything. Auto-scales. Pay per invocation.

الاستدعاء المتزامن (Synchronous Invocation) Synchronous Invocation

الاستدعاء المتزامن هو عندما ينتظر الـ client النتيجة — يحصل على الإجابة مباشرةً أو يتحمّل مسؤولية إعادة المحاولة. أشهر المصادر: API Gateway، Application Load Balancer، CLI/SDK، Cognito، Step Functions، Lex، Alexa.

Synchronous: the client waits for the result — either gets it directly or must retry. Top sources: API Gateway, ALB, CLI/SDK, Cognito, Step Functions, Lex, Alexa.

مفهوم أساسي:Key concept: في sync invocation: معالجة الأخطاء مسؤوليّة الـ client — retry و exponential backoff و circuit breaker كلّها في كود الـ caller. Lambda لا يعيد المحاولة تلقائياً. With sync invocation: error handling is the caller's responsibility — retry, backoff, circuit breaker all belong to the client. Lambda won't retry automatically. 
// Java SDK v2 — sync invoke a Lambda from another service
import software.amazon.awssdk.services.lambda.LambdaClient;
import software.amazon.awssdk.services.lambda.model.*;
import software.amazon.awssdk.core.SdkBytes;

LambdaClient lambda = LambdaClient.create();

InvokeResponse resp = lambda.invoke(InvokeRequest.builder()
    .functionName("calculate-order-total")
    .invocationType(InvocationType.REQUEST_RESPONSE)          // = sync
    .payload(SdkBytes.fromUtf8String("{\"orderId\":\"O-991\"}"))
    .build());

if (resp.statusCode() != 200 || resp.functionError() != null) {
    // retry with exponential backoff (client responsibility)
    throw new RuntimeException("Lambda error: " + resp.functionError());
}
String response = resp.payload().asUtf8String();

ALB + Lambda: لفتح Lambda عبر HTTP دون API Gateway، سجّل الدالة في Target Group. ALB يحوّل الـ HTTP إلى JSON (requestContext، httpMethod، headers...) وتعود الدالة بـ {statusCode, headers, body, isBase64Encoded}. لا تنسى resource policy على الـ Lambda تسمح لـ elasticloadbalancing.amazonaws.com.

ALB + Lambda: expose Lambda over HTTP without API Gateway by registering it in a Target Group. ALB converts HTTP→JSON (requestContext, httpMethod, headers...) and you return {statusCode, headers, body, isBase64Encoded}. Remember the Lambda resource policy allowing elasticloadbalancing.amazonaws.com.

الاستدعاء غير المتزامن (Asynchronous) Asynchronous Invocation

عندما يستدعي مصدر (مثلاً S3، SNS، EventBridge) الـ Lambda بشكل async، يُوضَع الحدث في Event Queue داخليّ. Lambda يحاول معالجته، وإذا فشل يُعيد المحاولة ٣ مرّات (الأصلي + ٢) مع انتظار ١ دقيقة ثم ٢ دقائق.

When a source (e.g., S3, SNS, EventBridge) invokes Lambda async, the event is placed in an internal Event Queue. Lambda tries to process it; on failure it retries 3 times total (original + 2) with 1-min then 2-min waits.

الإعادة تلقائيّةAuto retries

٣ محاولات افتراضياً. يمكن ضبط عدد المحاولات و max event age.

3 attempts default. Retries count and max event age both configurable.

Idempotency إلزاميّIdempotency required

نفس الحدث قد يصل مرّتين. اجعل معالجتك idempotent (مثال: استخدام event ID كـ primary key).

The same event may be delivered twice. Make processing idempotent (e.g., use event ID as primary key).

DLQ عند الفشلDLQ on failure

بعد استنفاد المحاولات، أرسِل إلى DLQ (SNS أو SQS). يحتاج resource permissions.

After retries exhaust, send to DLQ (SNS or SQS). Needs proper perms.

Destinations (الموصى به الجديد)Destinations (new, preferred)

تعريف destinations لـ success و failure على حدّ سواء: SQS، SNS، Lambda، EventBridge.

Define destinations for success AND failure: SQS, SNS, Lambda, EventBridge.

// Java handler — async-safe processing with idempotency via DynamoDB
import com.amazonaws.services.lambda.runtime.Context;
import com.amazonaws.services.lambda.runtime.RequestHandler;
import software.amazon.awssdk.services.dynamodb.DynamoDbClient;
import software.amazon.awssdk.services.dynamodb.model.*;

public class OrderHandler implements RequestHandler<S3Event, String> {

    private static final DynamoDbClient ddb = DynamoDbClient.create();   // init OUTSIDE handler

    @Override
    public String handleRequest(S3Event event, Context ctx) {
        String eventId = event.getRecords().get(0).getResponseElements().get("x-amz-request-id");

        try {
            // conditional put = idempotency guard
            ddb.putItem(PutItemRequest.builder()
                .tableName("processed-events")
                .item(java.util.Map.of(
                    "eventId", AttributeValue.fromS(eventId),
                    "at", AttributeValue.fromN(String.valueOf(System.currentTimeMillis()))))
                .conditionExpression("attribute_not_exists(eventId)")
                .build());
        } catch (ConditionalCheckFailedException e) {
            ctx.getLogger().log("Duplicate event " + eventId + " — skipping");
            return "skipped";
        }

        // ... actual processing here ...
        return "ok";
    }
}
فخّ شائع:Common pitfall: خطأ شائع في الامتحان: تخلط بين DLQ (للاستدعاء غير المتزامن فقط) وبين DLQ لـ SQS مباشرةً (عند استخدام event source mapping مع SQS). DLQ على Lambda للـ async invocations، DLQ على SQS للرسائل التي فشلت معالجتها بعد visibilityTimeout × maxReceiveCount. Common exam trap: don't confuse the Lambda DLQ (async-invocations only) with an SQS DLQ (used when SQS→Lambda via ESM). Lambda DLQ = async; SQS DLQ = messages exceeding visibilityTimeout × maxReceiveCount.

Event Source Mapping (Kinesis، SQS، DynamoDB Streams) Event Source Mapping (Kinesis, SQS, DynamoDB Streams)

Event Source Mapping (ESM) نمط خاصّ: Lambda يَسحَب (poll) السجلّات من المصدر ثم يستدعي الدالة بشكل متزامن مع batches. المصادر المدعومة: Kinesis Data Streams، DynamoDB Streams، SQS (Standard و FIFO)، Amazon MQ، Kafka.

Event Source Mapping (ESM) is special: Lambda polls records from the source and invokes your function synchronously with batches. Supported: Kinesis Data Streams, DynamoDB Streams, SQS (Standard & FIFO), Amazon MQ, Kafka.

نصيحة للامتحان:Exam tip: لـ SQS → Lambda: اجعل visibilityTimeout = 6× timeout الـ Lambda. هذا يمنع رسالة تُعالَج بالفعل من الظهور مجدّداً قبل أن تكتمل. For SQS → Lambda: set visibilityTimeout = 6× your Lambda timeout. Prevents an in-flight message from reappearing before processing finishes.
فخّ شائع:Common pitfall: Streams & Lambda — Error Handling: افتراضياً إذا فشلت دالتك، تتمّ إعادة معالجة الـ batch كلّه من البداية حتى ينجح أو تنتهي صلاحيّة السجلّات. يمكنك ضبط: retries عدد محدود، batch splitting عند الفشل (لتجنّب مشكلة timeout)، أو إرسال الـ discarded events إلى destination. Streams & Lambda — Error Handling: by default if your function fails, the entire batch is reprocessed until it succeeds or records expire. You can configure: bounded retries, batch splitting on error (to sidestep timeout issues), or send discarded events to a destination. 
// Java SDK v2 — create an SQS event source mapping programmatically
import software.amazon.awssdk.services.lambda.LambdaClient;
import software.amazon.awssdk.services.lambda.model.*;

LambdaClient lambda = LambdaClient.create();

CreateEventSourceMappingResponse esm = lambda.createEventSourceMapping(
    CreateEventSourceMappingRequest.builder()
        .functionName("process-orders")
        .eventSourceArn("arn:aws:sqs:eu-west-1:123456789012:orders-queue")
        .batchSize(10)                                       // up to 10 per batch
        .maximumBatchingWindowInSeconds(5)                   // or flush every 5s
        .functionResponseTypes(FunctionResponseType.REPORT_BATCH_ITEM_FAILURES) // partial failures
        .build());

System.out.println("ESM UUID: " + esm.uuid());

Event Object و Context Object Event Object & Context Object

كلّ دالة Lambda تستقبل وسيطَين: event (بيانات الطلب — JSON) و context (معلومات حول التنفيذ نفسه). فهم هذَين ضروريّ لأنّ الامتحان يختبر تمييز المحتوى (request ID، function name، memory limit، log stream، حد التنفيذ المتبقّي).

Every Lambda receives two args: event (request data — JSON) and context (runtime info). Understanding them is exam-critical because you'll need to identify fields like request ID, function name, memory limit, log stream, and remaining runtime.

// Java handler with explicit event and context types
import com.amazonaws.services.lambda.runtime.Context;
import com.amazonaws.services.lambda.runtime.RequestHandler;
import com.amazonaws.services.lambda.runtime.events.APIGatewayProxyRequestEvent;
import com.amazonaws.services.lambda.runtime.events.APIGatewayProxyResponseEvent;

public class ApiHandler implements RequestHandler<APIGatewayProxyRequestEvent, APIGatewayProxyResponseEvent> {

    @Override
    public APIGatewayProxyResponseEvent handleRequest(APIGatewayProxyRequestEvent event, Context ctx) {
        // Event: request payload
        String method = event.getHttpMethod();
        String path = event.getPath();
        java.util.Map<String, String> query = event.getQueryStringParameters();

        // Context: runtime metadata
        ctx.getLogger().log("Request ID: " + ctx.getAwsRequestId());
        ctx.getLogger().log("Function ARN: " + ctx.getInvokedFunctionArn());
        ctx.getLogger().log("Memory limit (MB): " + ctx.getMemoryLimitInMB());
        ctx.getLogger().log("Log stream: " + ctx.getLogStreamName());
        ctx.getLogger().log("Remaining time (ms): " + ctx.getRemainingTimeInMillis());

        // ALWAYS reuse SDK clients initialized outside the handler (execution context reuse)
        return new APIGatewayProxyResponseEvent()
            .withStatusCode(200)
            .withBody("{\"message\":\"hello from " + method + " " + path + "\"}");
    }
}
مفهوم أساسي:Key concept: getRemainingTimeInMillis() أداة حيوية: استخدمها داخل loops طويلة لتقطع أعمالاً تدريجياً قبل timeout ولترك وقت لكتابة نقطة استئناف (checkpoint) في DynamoDB/S3. getRemainingTimeInMillis() is your friend: use it inside long loops to gracefully break work and leave time to checkpoint progress to DynamoDB/S3 before timeout.

Execution Role و Resource Policy و التسجيل والمراقبة Execution Role, Resource Policies, Logging & Monitoring

لـ Lambda طبقتا صلاحيات: Execution Role (ما تفعله الدالة) و Resource Policy (مَن يمكنه استدعاء الدالة). الـ Execution Role يشبه IAM Role لـ EC2، والـ Resource Policy يشبه Bucket Policy لـ S3.

Lambda has two permission layers: Execution Role (what the function does) and Resource Policy (who can invoke the function). Execution Role is like an EC2 IAM Role; Resource Policy is like an S3 Bucket Policy.

للمطوّر السينيور:For the senior dev: Step Functions vs Lambda chain: للتكوين الطويل، استخدم Step Functions بدلاً من ربط Lambdas عبر SDK. أسباب: الـ retry و error handling مصمَّمان في الـ state machine، visibility أوضح، تكلفة أقلّ (لا تدفع أثناء wait states). الـ direct invocation chain أسرع لكن أهشّ. Reasons: retries and error handling built into the state machine, better visibility, lower cost (wait states free). Direct invoke is faster but fragile.

للحفظ السريع: Mnemonic:

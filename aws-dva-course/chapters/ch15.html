ما هي Step Functions ولماذا نحتاجها What is Step Functions and why

Step Functions خدمة تنسيق serverless تبني state machines مرئية من Lambda functions وخدمات AWS الأخرى. بدل أن تكتب orchestration داخل Lambda (تعقيد ومعالجة أخطاء يدوياً)، تعرّف الـ workflow بـ JSON (ASL - Amazon States Language) وتدعها AWS تديرها.

Step Functions is a serverless orchestration service that builds visual state machines from Lambda functions and other AWS services. Instead of coding orchestration inside Lambda (complex, manual error handling), define the workflow as JSON (ASL — Amazon States Language) and let AWS run it.

الفوائدBenefits

رؤية بصرية، إعادة محاولة مدمجة، معالجة أخطاء، تتبّع كامل في CloudWatch، checkpointing تلقائي.

Visual, built-in retries, error handling, full CloudWatch tracing, automatic checkpointing.

التكاملIntegrations

Lambda, ECS, Batch, DynamoDB, SNS, SQS, Glue, EMR, API Gateway، أكثر من ٢٠٠ خدمة.

Lambda, ECS, Batch, DynamoDB, SNS, SQS, Glue, EMR, API Gateway — 200+ services.

Standard WorkflowStandard Workflow

مدّة أقصى سنة. Exactly-once execution. تاريخ مفصّل للتنفيذ. مكلف أكثر. مناسب للعمليات التجارية الطويلة (معالجة طلب، approval flow).

Max duration 1 year. Exactly-once execution. Detailed execution history. Pricier. Use for long business processes (order processing, approval flows).

Express WorkflowExpress Workflow

مدّة أقصى ٥ دقائق. at-least-once، ١٠٠٬٠٠٠ execution/sec، أرخص بكثير. للأحمال عالية التردّد (IoT, streaming).

Max duration 5 min. At-least-once, 100,000 exec/sec, way cheaper. For high-volume (IoT, streaming).

أنواع الحالات (States) في Step Functions State Types in Step Functions

الـ state machine يتكوّن من States متّصلة. كل State له نوع يحدّد سلوكه. هذه أنواع مهمّة للامتحان:

A state machine is made of connected States. Each has a type defining its behavior. Exam-important types:

النوعTypeالوصفDescription
Taskيعمل shغل: يستدعي Lambda أو أيّ خدمة AWSDoes work: invokes Lambda or any AWS service
Choiceتفرّع (if/else) بناءً على مُدخلBranch (if/else) based on input
Parallelفروع تعمل بالتوازي، كلّها تنتظرParallel branches, all must finish
Mapيكرّر حالة على كل عنصر في مصفوفة (parallel أو inline)Iterate a state over array items (parallel or inline)
Waitتأخير زمن محدّد أو حتى timestampDelay for duration or until timestamp
Passمرّر المُدخل للحالة التالية (للتحويل بدون عمل)Pass input through (for transforms, no work)
Succeedأنهِ الـ workflow بنجاحEnd workflow successfully
Failأنهِ الـ workflow بخطأEnd workflow with failure
 
{
  "Comment": "Order processing",
  "StartAt": "ValidateOrder",
  "States": {
    "ValidateOrder": {
      "Type": "Task",
      "Resource": "arn:aws:lambda:us-east-1:111:function:validateOrder",
      "Retry": [{ "ErrorEquals": ["Lambda.TooManyRequestsException"],
                  "IntervalSeconds": 2, "MaxAttempts": 3, "BackoffRate": 2 }],
      "Catch": [{ "ErrorEquals": ["States.ALL"], "Next": "OrderFailed" }],
      "Next": "CheckAmount"
    },
    "CheckAmount": {
      "Type": "Choice",
      "Choices": [
        { "Variable": "$.amount", "NumericGreaterThan": 1000, "Next": "ManualApproval" }
      ],
      "Default": "ChargeCard"
    },
    "ManualApproval": { "Type": "Task",
      "Resource": "arn:aws:states:::sns:publish.waitForTaskToken",
      "Parameters": { "TopicArn": "arn:...", "Message.$": "$", "TaskToken.$": "$$.Task.Token" },
      "Next": "ChargeCard" },
    "ChargeCard":  { "Type": "Task", "Resource": "arn:aws:lambda:...:charge", "End": true },
    "OrderFailed": { "Type": "Fail", "Cause": "Validation failed" }
  }
}
للمطوّر السينيور:For the senior dev: نمط waitForTaskToken قوي للسينيور: Step Function يوقف التنفيذ حتى يصله token من عملية خارجية (Human approval عبر email، callback من webhook). مدّة الانتظار قد تصل إلى سنة في Standard — مثالي لـ approval flows في الأنظمة المصرفية. waitForTaskToken pattern is powerful: Step Function pauses until a token callback arrives (human email approval, webhook). Wait can be up to 1 year in Standard — ideal for approval flows in banking.
مفهوم أساسي:Key concept: Retry vs Catch: Retry يكرّر نفس الـ state عند أخطاء محدّدة (مع backoff). Catch ينقل التحكّم لـ state أخرى عند فشل. عادةً تُستخدم معاً: retry أولاً ثم catch إن فشل كل المحاولات. Retry vs Catch: Retry re-runs the same state on specific errors (with backoff). Catch transfers to another state on failure. Typically combined: retry first, catch if retries exhaust.

Error Handling والـ Map State Error Handling and the Map State

في الأنظمة الحقيقية، الفشل أمر متوقع. Step Functions يعطيك أدوات قوية. الأخطاء المعيارية تبدأ بـ States.* (مثل States.Timeout, States.TaskFailed), أو استثناءات الخدمة (Lambda.ServiceException). States.ALL يلتقط كل شيء.

In real systems, failures happen. Step Functions gives you strong tools. Standard errors start with States.* (e.g. States.Timeout, States.TaskFailed), or service exceptions (Lambda.ServiceException). States.ALL catches everything.

الـ Map State يكرّر حالة على كل عنصر في مصفوفة، مثل forEach في الكود. وضعان: Inline (للحجم الصغير، حتى ٤٠ تكرار متوازٍ) و Distributed (للحجم الكبير، حتى ١٠٠٬٠٠٠ تكرار متوازٍ — قرأ من S3 مثلاً).

Map State iterates a state over array items, like forEach in code. Two modes: Inline (small scale, up to 40 parallel) and Distributed (large scale, up to 100,000 parallel — e.g. read from S3).

// Map state: process each order item in parallel
{
  "ProcessItems": {
    "Type": "Map",
    "ItemsPath": "$.items",
    "MaxConcurrency": 10,
    "Iterator": {
      "StartAt": "ProcessOne",
      "States": {
        "ProcessOne": {
          "Type": "Task",
          "Resource": "arn:aws:lambda:...:processItem",
          "End": true
        }
      }
    },
    "ResultPath": "$.results",
    "Next": "Summarize"
  }
}

AWS AppSync — GraphQL مُدار AWS AppSync — Managed GraphQL

AppSync خدمة مُدارة لبناء APIs GraphQL و Pub/Sub real-time. بديل REST API Gateway للتطبيقات التي تحتاج: استعلامات مرنة (يطلب العميل الحقول التي يريدها فقط)، تحديثات فورية (subscriptions)، دمج بيانات من عدّة مصادر في طلب واحد.

AppSync is a managed GraphQL + real-time Pub/Sub service. A REST API Gateway alternative for apps needing: flexible queries (clients pick fields), real-time updates (subscriptions), data from multiple sources in one call.

Data SourcesData Sources

DynamoDB, Lambda, Aurora Serverless, OpenSearch, HTTP endpoints. خدمة واحدة تتقدّم لكل منها.

DynamoDB, Lambda, Aurora Serverless, OpenSearch, HTTP endpoints. One service fronts them all.

ResolversResolvers

تحوّل GraphQL query إلى عملية على الـ data source. VTL templates أو JavaScript. Unit أو Pipeline resolvers.

Translate GraphQL queries to data source ops. VTL or JavaScript. Unit or Pipeline resolvers.

SubscriptionsSubscriptions

تحديثات فورية عبر WebSocket. العميل يشترك في حقل GraphQL ويستقبل دفعات عند تغيّره.

Real-time updates via WebSocket. Client subscribes to a GraphQL field and gets pushes on change.

AuthenticationAuthentication

API Key, IAM, Cognito User Pool, OpenID Connect. يمكن دمج عدّة modes في نفس API.

API Key, IAM, Cognito User Pool, OpenID Connect. Multiple modes per API.

# GraphQL schema example
type Query {
  order(id: ID!): Order
  ordersByUser(userId: ID!): [Order]
}
type Mutation {
  createOrder(input: CreateOrderInput!): Order
}
type Subscription {
  onOrderCreated(userId: ID!): Order
    @aws_subscribe(mutations: ["createOrder"])
}
type Order {
  id: ID!
  userId: ID!
  amount: Float!
  status: String!
}

REST (API Gateway)REST (API Gateway)

over-fetching (الـ server يقرّر الحقول). نقطة نهاية لكل resource. تحديثات push تتطلّب WebSocket API منفصل.

Over-fetching (server decides fields). Endpoint per resource. Real-time push needs separate WebSocket API.

GraphQL (AppSync)GraphQL (AppSync)

العميل يختار الحقول. نقطة واحدة. Subscriptions مدمجة. استعلام واحد يجمع بيانات من مصادر متعدّدة.

Client picks fields. Single endpoint. Subscriptions built-in. One query fans to multiple sources.

نصيحة:Tip: AppSync مفيد جداً لـ mobile/SPA frontends: العميل يطلب بالضبط ما يحتاج (توفير bandwidth)، والـ subscriptions تعطي تجربة real-time بدون كتابة WebSocket code. AppSync shines for mobile/SPA frontends: clients fetch exactly what they need (saves bandwidth), and subscriptions deliver real-time UX without writing WebSocket code.

Standard (سنة، exactly-once) أو Express (٥ دقائق، عالي التردّد).

Standard (1 year, exactly-once) or Express (5 min, high-volume).

Retry same state, Catch to handle. Combine them.

AppSync للـ GraphQL AppSync for GraphQL

نقطة نهاية واحدة، حقول مرنة، subscriptions مدمجة.

Single endpoint, flexible fields, built-in subscriptions.

AppSync للـ mobile AppSync for mobile

توفير bandwidth، real-time UX، يدعم ٤ طرق authentication.

Saves bandwidth, real-time UX, 4 auth methods.

Standard = Slow + Serious (سنة، exactly-once، موافقات بشرية). Express = Everything fast (٥ دقائق، عالي التردّد، IoT). للـ GraphQL: AppSync، للـ workflows: Step Functions.

Standard = Slow + Serious (1 year, exactly-once, human approvals). Express = Everything fast (5 min, high-volume, IoT). For GraphQL → AppSync, for workflows → Step Functions.

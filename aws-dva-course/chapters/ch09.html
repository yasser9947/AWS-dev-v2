Buckets و Objects وقواعد التسمية Buckets, Objects, and Naming

S3 يُخزّن objects (ملفّات) داخل buckets (حاويات). الاسم العالميّ للـ bucket فريد عبر جميع حسابات AWS والمناطق. الـ bucket يُنشَأ في منطقة محدّدة، لكن الواجهة تُظهِر S3 كأنّه خدمة عالميّة.

S3 stores objects (files) inside buckets (containers). Bucket names are globally unique across all accounts and regions. A bucket is region-bound, though S3 feels global in the UI.

قواعد تسمية الـ bucketBucket naming rules

٣-٦٣ حرفاً، حروف صغيرة وأرقام فقط، لا يبدأ بـ xn-- ولا ينتهي بـ -s3alias، ليس عنوان IP.

3-63 chars, lowercase + digits only, not starting with xn-- or ending with -s3alias, not an IP.

مفتاح الـ objectObject key

المسار الكامل: s3://bucket/folder/file.txt. مكوّن من prefix + اسم الملف. لا توجد "مجلّدات" حقيقية — مجرّد / في المفاتيح.

Full path: s3://bucket/folder/file.txt. It's prefix + name. There are no real "folders" — just / in keys.

حدود حجم الـ objectObject size limits

الحد الأقصى ٥ تيرابايت لكل object. أي object أكبر من ٥ جيجابايت يجب رفعه عبر Multipart Upload.

Max 5 TB per object. Anything over 5 GB must use multipart upload.

Metadata و TagsMetadata & Tags

كل object يحمل metadata (system + user) و tags (حتى ١٠) و Version ID إن فعّلت versioning.

Each object has metadata (system+user), tags (up to 10), and a Version ID if versioning is on.

فخّ شائع:Common pitfall: لا يمكنك البحث داخل metadata أو tags من S3 مباشرة. إذا احتجت بحثاً سريعاً فخزّن الفهرس في DynamoDB مع الـ object key. هذا سؤال متكرّر في الامتحان. You cannot search metadata or tags directly in S3. If you need searchable lookups, index them in DynamoDB alongside the object key. Frequent exam question.

Bucket Policies و IAM و Block Public Access Bucket Policies, IAM, and Block Public Access

S3 يدعم سياستَي أمان: User-Based (IAM Policy مرتبطة بالمستخدم/الدور)، و Resource-Based (Bucket Policy مكتوبة بـ JSON على الـ bucket). القاعدة: يمكن للـ principal الوصول إذا سمحت IAM Policy أو Bucket Policy، وليس هناك DENY صريح.

S3 has two security layers: User-Based (IAM Policies attached to users/roles) and Resource-Based (JSON Bucket Policies on the bucket). Rule: access is granted if IAM OR Bucket Policy allows it, AND no explicit DENY.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnencryptedUploads",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::acme-prod/*",
      "Condition": {
        "StringNotEquals": { "s3:x-amz-server-side-encryption": "AES256" }
      }
    },
    {
      "Sid": "DenyInsecureTransport",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::acme-prod",
        "arn:aws:s3:::acme-prod/*"
      ],
      "Condition": { "Bool": { "aws:SecureTransport": "false" } }
    }
  ]
}
نصيحة للامتحان:Exam tip: Block Public Access هو مفتاح أمنيّ على مستوى الـ bucket (أو الحساب) يعطّل أيّ محاولة لجعل الـ bucket عامّاً عبر ACL أو Bucket Policy. AWS تفعّله افتراضياً لأيّ bucket جديد منذ ٢٠٢٣. أطفئه فقط إذا كنت متأكّداً (static website hosting). Block Public Access is a bucket- or account-level switch that overrides ACLs or policies that try to make the bucket public. AWS enables it by default on new buckets since 2023. Only disable for known public use (static website hosting). 
// Java SDK v2 — upload with server-side encryption (SSE-S3)
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.model.*;
import software.amazon.awssdk.core.sync.RequestBody;

S3Client s3 = S3Client.create();

s3.putObject(PutObjectRequest.builder()
    .bucket("acme-prod")
    .key("reports/q1.pdf")
    .serverSideEncryption(ServerSideEncryption.AES256)          // SSE-S3
    .contentType("application/pdf")
    .metadata(java.util.Map.of("author", "acme-reports-svc"))    // user metadata
    .build(),
    RequestBody.fromFile(java.nio.file.Path.of("/tmp/q1.pdf")));

Versioning و Replication Versioning & Replication

Versioning يحفظ نسخة تاريخيّة لكل تعديل على object ضمن نفس المفتاح. يُفعَّل على مستوى الـ bucket. مفيد للحماية من الحذف أو الكتابة الخاطئة. عند الحذف، S3 يضع Delete Marker بدلاً من الحذف الفعليّ. لاستعادة النسخة الأصلية، احذف الـ Delete Marker.

Versioning preserves a historical copy of every modification to an object under the same key. Enabled at bucket level. Protects against accidental deletes/overwrites. On delete, S3 places a Delete Marker instead of actually deleting. Remove the marker to restore the original.

Same-Region Replication (SRR)Same-Region Replication (SRR)

نسخ async داخل نفس المنطقة. حالات: تجميع logs من عدّة buckets، نسخ بين بيئة production و staging.

Async copy within the same region. Use cases: log aggregation across buckets, prod-to-staging replication.

Cross-Region Replication (CRR)Cross-Region Replication (CRR)

نسخ async عبر المناطق. حالات: الامتثال (Compliance)، تقليل الـ latency للمستخدمين في مناطق أخرى، نسخ احتياطيّ جغرافيّ.

Async copy across regions. Use cases: compliance, lower latency for users in other regions, geographic backup.

فخّ شائع:Common pitfall: ثلاث نقاط حرجة في الـ replication: (١) يجب تفعيل Versioning في المصدر والوجهة. (٢) يتم نسخ الـ objects الجديدة فقط — القديمة لا تُنسَخ إلّا عبر S3 Batch Replication. (٣) لا يوجد "chaining" — إذا كان bucket1→bucket2→bucket3 فالمحتوى من bucket1 لن يصل إلى bucket3. Three critical points: (1) Versioning must be on at source AND destination. (2) Only new objects are replicated; existing require S3 Batch Replication. (3) No chaining — bucket1→bucket2→bucket3 does NOT forward from bucket1 to bucket3.
مفهوم أساسي:Key concept: DELETE operations: يمكن اختيار نسخ الـ Delete Markers (optional). لكن الحذف بـ version ID محدّد لا يُنسَخ أبداً — لتجنّب انتشار الحذف الخبيث عبر المناطق. DELETE ops: replicating Delete Markers is optional. But deletes targeting a specific version ID are never replicated — to prevent malicious deletes from propagating.

Storage Classes و Lifecycle Rules Storage Classes & Lifecycle Rules

S3 يقدّم ٧ فئات تخزين تتراوح في التكلفة والـ availability ووقت الاسترجاع. اختيار الفئة المناسبة هو أحد أكبر روافع تحسين التكلفة في DVA-C02.

S3 offers 7 storage classes varying in cost, availability, and retrieval time. Picking the right class is one of the biggest cost-optimization levers on DVA-C02.

Standardبيانات ساخنة تُستخدَم باستمرارHot, frequently accessed99.99%ms
Intelligent-Tieringنمط وصول متقلّب — ينقل تلقائياً بين الطبقاتUnpredictable access — auto-tiers99.9%ms

Glacier Instantأرشيف يُقرَأ ربع سنويAccessed once per quarter99.9%ms

مفهوم أساسي:Key concept: Lifecycle Rules تنقل الـ objects تلقائياً بين الفئات. Transition Actions: "انقل إلى Glacier بعد ٩٠ يوماً". Expiration Actions: "احذف الـ logs بعد ٣٦٥ يوماً" أو "احذف النسخ القديمة". يمكن تطبيقها على prefix أو tag محدّد. Lifecycle Rules auto-transition objects between classes. Transition Actions: "Move to Glacier after 90 days". Expiration Actions: "Delete logs after 365 days" or "remove old versions". Can target a prefix or tag. 
{
  "Rules": [
    {
      "ID": "ArchiveOldReports",
      "Filter": { "Prefix": "reports/" },
      "Status": "Enabled",
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 180, "StorageClass": "GLACIER" }
      ],
      "Expiration": { "Days": 2555 }
    },
    {
      "ID": "CleanupIncompleteUploads",
      "Status": "Enabled",
      "Filter": {},
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
    }
  ]
}
نصيحة:Tip: استخدم S3 Analytics — Storage Class Analysis كتقرير أوّل قبل كتابة lifecycle rules. يعطيك توصيات Standard → Standard-IA بناءً على نمط الوصول الفعليّ. لا يعمل للـ One-Zone IA أو Glacier. Use S3 Analytics — Storage Class Analysis as a first report before writing lifecycle rules. Gives Standard → Standard-IA recommendations from real access patterns. Not for One-Zone IA or Glacier.

Performance: Multipart Upload و Transfer Acceleration و Byte-Range Performance: Multipart Upload, Transfer Acceleration, Byte-Range

S3 يتمدّد تلقائياً لطلبات عالية: 3500 PUT/COPY/POST/DELETE أو 5500 GET/HEAD لكلّ ثانية لكلّ prefix — ولا حدود على عدد الـ prefixes. توزيع المحتوى على عدّة prefixes يزيد الأداء.

S3 auto-scales to heavy workloads: 3500 PUT/COPY/POST/DELETE or 5500 GET/HEAD requests per second per prefix — unlimited prefixes. Distribute across prefixes to multiply throughput.

Multipart UploadMultipart Upload

موصى به للملفّات >100MB، إلزاميّ >5GB. الـ SDK يفعلها تلقائياً في Java v2. يتوازى الرفع ويعيد الأجزاء الفاشلة فقط.

Recommended for >100MB, mandatory for >5GB. Java SDK v2 handles automatically. Parallel uploads, retry only failed parts.

Transfer AccelerationTransfer Acceleration

يرسِل الملفّ إلى أقرب edge location ثم ينقله عبر شبكة AWS السريعة. مفيد للرفع من مواقع بعيدة جغرافياً. متوافق مع multipart.

Ships file to nearest edge, then over AWS's fast backbone. Useful for uploads across continents. Works with multipart.

Byte-Range FetchesByte-Range Fetches

طلب أجزاء من الـ object بالتوازي. يسرّع التنزيل ويدعم الاستمرار بعد الانقطاع. مفيد لقراءة header ملفّ كبير فقط.

Request specific byte ranges in parallel. Speeds downloads, supports resume after failure. Great for reading just the header of a big file.

S3 Select & Glacier SelectS3 Select & Glacier Select

استرجع صفوف/أعمدة محدّدة من CSV/JSON/Parquet داخل S3 مباشرة بـ SQL — بدلاً من تحميل الملف كاملاً.

Run SQL on CSV/JSON/Parquet inside S3 to fetch only needed rows/columns — instead of downloading the whole file.

// Java SDK v2 — multipart upload is handled by S3TransferManager (async, parallel)
import software.amazon.awssdk.services.s3.S3AsyncClient;
import software.amazon.awssdk.transfer.s3.S3TransferManager;
import software.amazon.awssdk.transfer.s3.model.*;
import java.nio.file.Path;

S3AsyncClient s3Async = S3AsyncClient.crtBuilder().build(); // CRT-based, native multipart
S3TransferManager tm = S3TransferManager.builder().s3Client(s3Async).build();

UploadFileRequest req = UploadFileRequest.builder()
    .putObjectRequest(p -> p.bucket("acme-prod").key("dumps/big-backup.tar"))
    .source(Path.of("/data/big-backup.tar"))                  // 20 GB file
    .addTransferListener(software.amazon.awssdk.transfer.s3.progress.LoggingTransferListener.create())
    .build();

FileUpload upload = tm.uploadFile(req);
upload.completionFuture().join();                              // wait
System.out.println("ETag: " + upload.completionFuture().get().response().eTag());

Event Notifications و Presigned URLs و S3 Object Lambda Event Notifications, Presigned URLs, and S3 Object Lambda

S3 يصدِر أحداثاً عند إنشاء/حذف/استعادة الـ objects. يمكن إرسالها إلى SNS أو SQS أو Lambda مباشرةً، أو إلى EventBridge للحصول على فلترة JSON متقدّمة وتوجيه لأكثر من ١٨ خدمة.

S3 emits events on object create/delete/restore. Can route directly to SNS, SQS, Lambda, or to EventBridge for advanced JSON filtering and fan-out to 18+ services.

نصيحة للامتحان:Exam tip: IAM Permissions للإشعارات: S3 يحتاج resource-policy على الهدف (SNS Topic، SQS Queue، Lambda) يسمح لـ s3.amazonaws.com بالنشر. هذا شرط حرج ومصدر شائع لأخطاء الامتحان. IAM for notifications: S3 needs a resource policy on the target (SNS Topic, SQS Queue, Lambda) allowing s3.amazonaws.com to publish. Critical and a common exam-error source.

Presigned URLs تعطي مستخدماً غير مُوثَّق صلاحيّة محدودة الزمن لرفع أو تنزيل object دون مشاركة مفاتيحك. الرابط يُوقَّع بـ SigV4 ويحمل X-Amz-Expires. الاستخدامات: صفحات الرفع من العميل، روابط تنزيل مؤقّتة.

Presigned URLs grant unauthenticated users time-limited upload/download rights without exposing your keys. Signed with SigV4 and carry X-Amz-Expires. Use cases: client-side uploads, temporary download links.

// Java SDK v2 — generate a presigned download URL valid for 15 minutes
import software.amazon.awssdk.services.s3.presigner.S3Presigner;
import software.amazon.awssdk.services.s3.presigner.model.*;
import software.amazon.awssdk.services.s3.model.GetObjectRequest;
import java.time.Duration;

try (S3Presigner presigner = S3Presigner.create()) {
    GetObjectRequest get = GetObjectRequest.builder()
        .bucket("acme-prod")
        .key("invoices/2025/inv-9821.pdf")
        .build();

    GetObjectPresignRequest pr = GetObjectPresignRequest.builder()
        .signatureDuration(Duration.ofMinutes(15))
        .getObjectRequest(get)
        .build();

    PresignedGetObjectRequest presigned = presigner.presignGetObject(pr);
    System.out.println("Download URL: " + presigned.url());  // shareable for 15 min
}
للمطوّر السينيور:For the senior dev: S3 Object Lambda يسمح بتعديل المحتوى أثناء استرجاعه: يمرّ الطلب عبر دالة Lambda تعدّل الـ response (إزالة PII، ضغط، ترجمة، إضافة watermark). يحلّ مشكلة الحاجة لنسخ متعدّدة من نفس الملف لاحتياجات مختلفة. S3 Object Lambda lets you transform objects on retrieval: requests pass through a Lambda that modifies the response (strip PII, compress, translate, watermark). Removes the need for multiple copies of the same file for different consumers.

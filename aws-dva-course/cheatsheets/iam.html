ملخّص سريع Cheatsheet

AWS IAM

إدارة الهويات والصلاحيات بدقّة عبر المستخدمين والأدوار والمجموعات والسياسات. Fine-grained identity and permission management via users, roles, groups, and policies.

المفاهيم الأساسية Key Concepts

المفهوم Concept الوصف Description
Users / Groups / Roles المستخدم هوية دائمة، المجموعة تجمع مستخدمين، والدور هوية مؤقتة يتحمّلها خدمة أو مستخدم. User = permanent identity; Group = collection of users; Role = temporary identity assumed by a service or user.
Identity vs Resource Policy Identity Policy تُلصق بالهوية، Resource Policy تُلصق بالمورد مثل S3 Bucket Policy أو Lambda. Identity policy attached to identity; resource policy attached to resource (S3 bucket, Lambda, etc.).
Managed vs Inline Policy Managed قابلة لإعادة الاستخدام (AWS أو العميل)، بينما Inline مرتبطة مباشرة بهوية واحدة. Managed policies are reusable (AWS or customer); inline is tied to a single identity.
Permission Boundary حدّ أعلى للصلاحيات الممكنة لمستخدم/دور حتى لو أُلصقت سياسات أكثر صلاحية. Maximum permission ceiling for a user/role even if broader policies are attached.
Policy Evaluation Logic Explicit Deny تغلب كل شيء، ثم Allow صريح، والافتراضي Deny ضمني. Explicit Deny > Explicit Allow > Implicit Deny (default).
IAM Conditions شروط دقيقة مثل aws:SourceIp، aws:MultiFactorAuthPresent، s3:prefix للتحكم حسب السياق. Fine-grained conditions like aws:SourceIp, aws:MultiFactorAuthPresent, s3:prefix.
IAM Access Analyzer يكشف عن الموارد المُشاركة خارج الحساب ويقدّم اقتراحات تضييق الصلاحيات. Detects resources shared outside the account; recommends narrowing permissions.
MFA & Hardware Keys يدعم MFA افتراضي (TOTP)، ومفاتيح U2F، وFIDO2 لحماية الحسابات الحسّاسة. Supports virtual MFA (TOTP), U2F, and FIDO2 hardware keys for sensitive accounts.

أوامر CLI الأساسية Essential CLI Commands

إنشاء دور يتحمّله EC2. Create a role assumed by EC2. 

aws iam create-role --role-name AcmeAppRole --assume-role-policy-document file://trust.json

إلصاق سياسة مُدارة بدور. Attach managed policy to a role. 

aws iam attach-role-policy --role-name AcmeAppRole --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess

محاكاة قرار السياسة لمستخدم. Simulate policy decision for a user. 

aws iam simulate-principal-policy --policy-source-arn arn:aws:iam::111:user/dev --action-names s3:PutObject

تدوير مفاتيح الوصول. Rotate access keys. 

aws iam create-access-key --user-name yasir && aws iam delete-access-key --access-key-id AKIA...

إنشاء Permission Boundary. Set a permission boundary. 

aws iam put-user-permissions-boundary --user-name dev --permissions-boundary arn:aws:iam::111:policy/DevBoundary

قراءة آخر استخدام للدور. Check last-used info for a role. 

aws iam get-role --role-name AcmeAppRole --query Role.RoleLastUsed

متى تستخدم AWS IAM؟ When to use AWS IAM

تطبيق EC2 يحتاج قراءة من S3. EC2 app needs to read S3.

IAM Role for EC2 (instance profile)

Lambda تحتاج الوصول لخدمات AWS. Lambda accessing AWS services.

Execution Role

منح حساب آخر وصولاً مؤقتًا. Grant temporary access to another account.

IAM Role + AssumeRole (STS)

منع تصعيد الصلاحيات لمطوّر. Prevent privilege escalation by a dev.

Permission Boundary

مستخدم تطبيق خارجي (B2B). External app user (B2B).

IAM User with access keys (or better: IAM Role Anywhere)

نصائح للامتحان Exam Tips

Explicit Deny دائمًا يتغلّب على Allow مهما كان مصدره. Explicit Deny always beats Allow, no matter the source.
لا تستخدم Access Keys على EC2 — استخدم IAM Role عبر Instance Profile. Never put Access Keys on EC2 — use IAM Role via Instance Profile.
Permission Boundary لا يمنح صلاحيات بل يُحدّد سقف الصلاحيات. Permission Boundary doesn't grant — it caps what can ever be granted.
Access Analyzer يكشف Public/Shared resources — حلّ سريع للأمان. Access Analyzer flags public/shared resources — quick security win.
Credentials Report + Access Advisor = تنظيف الصلاحيات الميّتة. Credentials Report + Access Advisor = clean up unused permissions.
